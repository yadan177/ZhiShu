# 美术资产入库清单生成

## 1. 开始前核对

1. 优先读取项目 `.agent-rules/overrides.md` 与 `.agent-rules/3d-art/其他规则/04-资产命名轴向导出与入库校验规范.md`（若已安装）。
2. 检查目标目录实际文件列表（模型 `.fbx`/`.glb`、贴图 `.png`/`.tga`、对应 `.meta` 及归档源文件位置），坚持**基于真实文件清单统计**，不捏造不存在的文件路径或面数。
3. 确认接收方岗位（TA / Unity 研发）需要的关键交接字段，以及是否需要同步记录至飞书多维表格（需先核对飞书 MCP 可用性并在写入前确认）。

## 2. 执行步骤

1. **梳理资产归属与映射关系**：将每个模型与它对应的 LOD 文件、贴图集合（Albedo / Normal / MaskMap 等）、预设材质名及源文件归档路径一一关联，避免“孤儿贴图”或“缺图模型”入库。
2. **补全核心入库台账字段**：
   - `资产 ID / 规范名`、`分类与级别`、`导出文件路径`、`源文件归档路径`、`LOD0/LOD1/LOD2 面数`、`材质槽数`、`贴图清单与分辨率`、`制作方式（手工 / 图生 3D 精修 / 商用采购）`、`版权与授权状态`、`自检结论`、`接收人/日期`。
3. **核查仓库版本控制卫生**：提醒检查大体积资产是否已由 Git LFS 跟踪、Unity 侧是否连带 `.meta` 同步提交、源文件是否按规范存放在独立归档仓而非塞进运行包目录。
4. **输出多格式交付件**：默认生成清晰的 Markdown 表格，并按需附可一键导入 Excel/飞书多维表格的 CSV 代码块。

## 3. 输出结构

- **一、本批次交接概览**（批次号 / 提交人 / 资产总数 / 所属模块与版本）
- **二、资产入库明细台账表**
- **三、异常与缺口提示**（缺失 LOD、缺图、命名不规范、待补充版权说明或待实测面数的条目）
- **四、下游接手提示**（给 TA / Unity 的特殊材质、碰撞体或动画挂点说明）

## 4. 交付自检与红线

- 任何未从文件直接读取出的数值（如面数、显存占用）必须标注 `待补录`，严禁编造近似数字充数。
- 凡涉及图生 3D、第三方素材库或外包资产，必须在台账中显式标注来源与商用授权状态。
