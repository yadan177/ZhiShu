# XR 模型与贴图规范体检

## 1. 开始前核对

1. 优先读取项目 `.agent-rules/overrides.md`、`.agent-rules/3d-art/其他规则/02-模型拓扑面数与LOD预算规范.md`、`03-UV展开与PBR贴图规范.md` 及 `.agent-rules/xr-common/其他规则/01-硬件档位与性能预算基准.md`（若已安装）。
2. 核对目标资产在场景中的级别（主角/近景核心道具 / 中景常驻资产 / 远景背景摆件）以及目标设备档位（移动 XR 一体机 / PCVR）。
3. 收集被检资产的实测数据（面数、LOD 级数、材质槽数、UV 通道、各贴图分辨率与位深、Alpha 透明面积）；缺失实测字段时标注“待在 DCC/Unity 实测补录”，禁止编造数据。

## 2. 六维体检项

1. **几何与面数预算**：LOD0 三角面数是否符合资产分级预算；是否存在无意义高密度细分、隐藏内面、微小孤立碎块或非流形几何。
2. **LOD 链完整性**：中/大型或重复出现资产是否配备递减合理的 LOD1/LOD2（避免相邻 LOD 减面率过小失去意义或跳变穿帮），且各 LOD 共享材质尽量一致。
3. **材质槽与透明控制**：单资产材质槽数量是否最小化（能合图不拆多材质）；是否误把全不透明模型挂了 Transparent 材质导致严重 Overdraw（移动 XR 头号杀手）。
4. **UV 与光照贴图（Lightmap UV）**：主 UV 是否无拉伸、无越界、具备足够 Padding；参与静态烘焙的模型 UV2 是否无重叠且留足光照烘焙间距。
5. **PBR 贴图尺寸与通道打包**：贴图是否为 2 的幂次（POT，如 512 / 1024 / 2048），尺寸是否与物体屏幕占比匹配（小螺丝严禁用 4K）；是否按目标管线正确合并通道（如 Metallic/AO/Smoothness），法线贴图绿色通道方向（OpenGL vs DirectX）是否正确。
6. **碰撞与骨骼开销**：物理碰撞是否使用简化基元或低面数凸包；带骨骼模型骨骼数与单顶点最大权重数（移动端常限制 ≤ 4）是否受控。

## 3. 输出结构

- **一、体检综合结论**（放行 / 整改后复检 / 阻断退回）
- **二、指标核对表**：`检查项 | 实测值 | 项目预算/规范基准 | 状态（✅/⚠️/❌） | 整改建议`
- **三、阻断级问题整改优先级**（按对真机帧率/内存影响从大到小排序）

## 4. 交付自检与红线

- 明确区分“已从文件/报告实测读出的指标”与“待上 DCC/Unity 核验的指标”，严禁虚报体检通过。
- 涉及 Unity 贴图压缩格式（如 Android/XR 优先 ASTC）时，以目标平台实测配置为准。
