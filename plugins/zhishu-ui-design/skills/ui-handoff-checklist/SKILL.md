# 设计稿走查与研发交付

## 1. 开始前核对

1. 优先读取项目 `.agent-rules/overrides.md`、`.agent-rules/ui-design/其他规则/05-验证交付与落地跟踪规则.md`、`06-设计工具与切图导出规则.md` 及 `.agent-rules/project-docs/ui-design/其他规则/04-UI设计文档任务入口.md`（若已安装）。
2. 明确研发端实现技术栈（Web CSS / React / Vue / Electron / Unity UGUI / Unity UI Toolkit），按目标渲染方式决定交付格式，不盲目导出冗余切图。
3. 确认项目既有的设计说明文档位置，确保“设计交付说明”与“研发技术文档”边界清晰、互不覆盖。

## 2. 执行步骤

1. **设计稿结构与画布自动化自查**：
   - 清理隐藏废图层、未命名临时画板、失效引用；同模块主页面与子状态/弹窗必须归入同一 `Section` 按阅读流排列，禁止按时间另起新行跨区堆放；
   - **执行零悬空按钮核查**：逐一盘点画板上所有按钮、Tab 与分段开关，确认每个交互入口都有对应落地画板或明确复用说明，且提交/安装/同步类动作均已补齐成功、失败与批量部分失败反馈态，无“预览并应用/预览安装”类拼接按钮文案；
   - 检查颜色、字号、圆角、间距是否已绑定设计系统令牌，主组件可变文案是否暴露为 `Text Property`，业务页是否复用组件实例而非裸 Frame 硬画；
   - **若设计稿位于 Figma，必须执行配套审计脚本 [figma-audit.js](./scripts/figma-audit.js)**（通过 Figma MCP `use_figma` 运行，确认 `pass === true`），并强制执行**双视角视觉复核**：同时截取并目视检查**整页俯瞰总览图**与**每张新增/大改画板的局部细节图**。
2. **按实现方式分类资产导出清单**：
   - **纯样式可实现元素**（纯色/渐变卡片、边框、阴影、圆角按钮）：直接交付 Token 与规格，**不导出位图切片**。
   - **图标与品牌标志**：优先交付清理过冗余路径与 `viewBox` 的矢量 `SVG`（或确认项目使用的图标库名称与图标 ID）；需位图时按平台倍率导出（如 `@2x`/`@3x` 或 Unity Sprite + 九宫格 `9-Slice` 边线值）。
   - **应用图标（App Icon）**：核对各平台专属规格（如 macOS HIG `1024×1024` 内含标准安全边距与圆角、Windows 多尺寸 `.ico`、Android/XR 自适应图标）。
3. **产出面向研发的交付说明**：列出画板索引、新增/变更 Token、动态交互说明（动效时长与缓动、滚动行为、键盘/射线焦点顺序）、资产命名与存放路径建议。

## 3. 输出结构

- **一、交付摘要与画板索引**（页面名称 / 画板位置 / 变更类型：新增/修改/不变）
- **二、设计令牌变更表**（新增 / 修改 / 废弃的 Token）
- **三、切图与图标资产清单**（文件名 / 格式 / 尺寸与倍率 / 9-Slice 或安全区说明 / 版权来源）
- **四、交互细节与边界规则交接表**（给研发的防踩坑提示）
- **五、待研发确认技术约束项**

## 4. 交付自检与红线

- 严禁交付带中文空格乱命名、未去背景杂边或超大未压缩的原图素材。
- 明确标注本次交付依赖的外部资源（字体、第三方图标/Logo）授权状态。
- 清晰区分“本次必须严格还原的硬规格”与“研发可按框架微调的弹性细节”。
