# XR 空间界面规范检查

## 1. 开始前核对

1. 优先读取项目 `.agent-rules/overrides.md`、`.agent-rules/ui-design/其他规则/07-XR空间界面规范.md`、`.agent-rules/ui-design/其他规则/08-XR空间布局与摆放架构规范.md` 及 `.agent-rules/xr-common/其他规则/02-空间舒适度与防眩晕红线.md`（若已安装）。
2. 明确目标头显型号/档位（Vision Pro / Meta Quest / PICO 等单眼分辨率与 PPD）、显示形态（VR 全沉浸 / MR 彩透 / 光学 AR）以及输入方式（6DoF 手柄射线 / 裸手近距直触 / 远距捏合 / 眼动）。
3. 区分被审材料属于“平面设计稿”“Unity 编辑器预览”还是“真机实拍/实测”，禁止把桌面高清屏观感等同于头显实际可读性。

## 2. 专项审查清单

1. **视距、中距歧义带与空间拓扑**：
   - 常规交互面板是否避开 **`0.50–0.80m` 中距交互歧义带**（近场手触 `< 0.46m`、远场射线/眼动 `1.0–2.0m`、空间锚点关联 UI 建议 `≤ 3.0m`），杜绝贴脸过近（`< 0.45m`）引发辐辏调节冲突；
   - 主信息是否控制在水平 `±30°`、垂直略偏下（约 `-5°` 至 `-15°`）的舒适视野内；超宽多栏界面是否已拆为主窗 + 内倾侧翼（`15°–25°`）或弧形排布；外部附属条（Ornament）宽度是否**不超过关联主窗宽度**。
2. **动态生成、面板锚定与防穿模**：
   - **严禁头部硬锁（Head-Locked HUD）**：核心界面必须采用世界锚定、惰性跟随（含死区与阻尼）或手部/控制器锚定；
   - **Yaw-Only 首次弹出与多窗调度**：核对弹窗是否忽略抬头低头（Pitch）与歪头（Roll）、是否限制同屏并发窗口数、是否提供视角重置（Recenter）与窗口召回，以及遇到 3D 主体或 MR 真实墙面/桌面时是否具备防穿模避让。
3. **Z 轴物理景深与文字/图标可读性**：
   - 核对主窗、悬浮附属条、下拉菜单与模态弹窗之间是否存在真实物理 Z 偏移（杜绝 Z-fighting），且弹窗打开时底层是否退让/降暗；
   - 核对换算后的物理高度/角字号是否满足目标头显清晰阅读底线（文字密集界面是否已评估硬件合成层 Composition Layers）；避免过细字重、低对比灰字与极细 1px 描边闪烁。
4. **跨设备输入热区与多模态反馈**：
   - 对照目标设备官方门槛核对：Vision Pro 是否满足常规按钮**中心距 `≥ 60pt` / 净间距 `≥ 16pt`** 与系统眼动 Hover；Meta Quest 是否满足**最小 `48dp` / 主控 `≥ 60dp` / 间距 `≥ 16dp`**、不可见热区扩展与按下防抖；PICO OS 6 是否兼容眼动+捏合多模态与手柄，且均避让系统保留手势/按键。
5. **MR 透视环境与移动一体机渲染预算**：
   - 透视模式下文字与控件是否带有足够不透明度隔离背板（经亮窗、暗场、杂乱桌面三类背景检验），且不遮挡现实脚下安全视线；
   - 移动一体机是否严控多层半透明叠层与全屏实时高斯模糊 Overdraw。

## 3. 输出结构

- **一、审查基线声明**（设备档位 / VR 或 MR 模式 / 输入方式 / 当前验证层级）
- **二、XR 空间问题清单**（`严重度（红线/高/中） | 维度 | 问题定位 | 空间风险说明 | 调整参数建议`）
- **三、真机必验项清单**（列出设计评审无法替代、必须戴目标头显复核的关键项）

## 4. 交付自检与红线

- 任何涉及角字号、距离、热区尺寸的建议，必须同步标明所基于的视距与设备前提，不把单一头显参数说成所有硬件的硬上限。
- 发现头部硬锁、过近弹窗或无反馈交互时，必须标为阻断级红线。
