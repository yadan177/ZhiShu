# 界面实现还原度验收

## 1. 开始前核对

1. 优先读取项目 `.agent-rules/overrides.md`、`.agent-rules/ui-design/其他规则/05-验证交付与落地跟踪规则.md` 与项目设计系统规范（若已安装）。
2. 同时取得**定稿设计稿依据**（Figma 画板、设计规格或文档）与**真实运行界面证据**（实机截图、当前渲染代码/样式或可运行构建），禁止凭猜测臆断界面效果。
3. 明确验收范围、当前运行分辨率/缩放比（如 macOS Retina 2x、Windows 125%/150% DPI、XR 真机）及验证层级。

## 2. 逐项走查维度

1. **布局与对齐**：主骨架尺寸、列宽比例、基线对齐、卡片/模块间距一致性，是否存在意外换行、重叠、裁切或多余滚动条。
2. **视觉与令牌一致性**：背景层次、文字主次对比度、字号/字重/行高、圆角、边框与阴影是否符合语义令牌，无错用颜色或缺失品牌图标容器（如白底容器、macOS 图标视觉尺寸偏大）。
3. **交互与动态状态**：Hover/Active/Focus 反馈、下拉框（是否误用系统原生控件）、抽屉与弹窗打开关闭动画/遮罩、加载态、空态、错误态与成功提示是否齐全。
4. **文案与极值容错**：核对标题、按钮、状态徽章文案是否与术语词典一致、无多余冗长解释段落；实测超长名称/路径截断与最小窗口尺寸表现。
5. **XR 专项复核（仅 XR 项目）**：在目标头显上核查锯齿闪烁、空间深度遮挡、射线悬停高亮与透视底色可读性。

## 3. 输出结构

- **一、验收结论与覆盖范围**（通过 / 需修改后复验；标注验收环境、分辨率与未覆盖项）
- **二、视觉与交互偏差清单表**：
  `编号 | 级别（P0 阻断 / P1 明显偏差 / P2 细节优化） | 页面/组件位置 | 设计预期 | 实际表现 | 精准修正建议（含建议 Token/像素/组件改动）`
- **三、已通过确认项摘要**（明确哪些关键改动已验证达标）

## 4. 交付自检与红线

- 每条问题必须精确指出组件位置与可量化偏差（如“图标占满画布导致 Dock 视觉偏大，需缩至 824×824 居中”），禁止只写“不好看”“感觉有点怪”。
- 严格区分**已实测/截图标注确认的缺陷**与**仅通过源码推测的疑似风险**。
- 区分设计还原阻断项（错位、遮挡、不可读、缺失关键状态）与细微优化项，避免拿 1px 细节卡死主干发布。
