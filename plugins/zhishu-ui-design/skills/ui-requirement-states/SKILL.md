# 界面需求与状态梳理

## 1. 开始前核对

1. 若项目已安装智枢规则，优先读取 `.agent-rules/overrides.md`、`.agent-rules/ui-design/15-AI通用入口规则.md` 与 `.agent-rules/ui-design/其他规则/01-需求分析规则.md`。
2. 核对目标端设备尺寸、平台交互范式（桌面端 / Web / 移动端 / XR 空间面板）及项目既有设计系统或组件库，禁止与既有信息架构割裂。
3. 核对页面内文案原则：如项目有极简去冗长要求，严禁在页面中强行堆砌段落式介绍、重复功能解释或教学废话。

## 2. 执行步骤

1. **提取页面目标与核心任务**：每页提炼 1 个首要任务（Primary Action）和不超过 2 个次要操作，避免多主按钮竞争注意力。
2. **信息优先级分层**：将页面展示字段分为 `L1 核心识别与主状态 / L2 关键参数与操作 / L3 展开或抽屉详情`，避免把低频元数据铺满主视图。
3. **补全六维页面与控件状态矩阵**：
   - **数据态**：正常态、首次空态、搜索/筛选无结果态、数据加载/骨架屏态、局部刷新态、请求失败/离线态。
   - **控件交互态**：默认、悬停（Hover）、按下（Active）、聚焦（Focus，含键盘 Tab/XR 射线悬停）、选中、禁用、加载中。
   - **极值态**：超长标题/路径截断（`ellipsis` + Tooltip）、0 项/1 项/100 项列表滚动、窄窗口/小屏自适应、高对比度或深浅背景切换。
4. **梳理高风险操作保护**：对删除、覆盖、不可逆发布、凭据修改等操作明确二次确认、差异预览或冲突阻断交互。

## 3. 输出结构

- **一、页面定位与信息层级表**（L1 / L2 / L3 信息分配与主次操作）
- **二、全场景页面状态矩阵**（状态 / 触发条件 / 展示内容 / 可执行动作）
- **三、控件状态与极值边界清单**（含截断、滚动、禁用原因与报错反馈）
- **四、前置待确认项**（影响界面架构的需求缺口）

## 4. 交付自检与红线

- 不得只设计“理想数据刚好 3 条”的静态态而忽略空态、报错态与长文案溢出。
- 控件选型遵循项目规范（如明确要求自定义下拉框时，不得退回系统原生下拉框）。
- 文案简洁准确，与项目术语词典保持一致。
