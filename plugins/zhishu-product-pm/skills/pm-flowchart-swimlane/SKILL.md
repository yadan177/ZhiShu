# 业务流程图与泳道图生成

## 1. 开始前核对

1. 优先读取项目 `.agent-rules/overrides.md`、`.agent-rules/product-pm/15-AI通用入口规则.md` 与 `.agent-rules/product-pm/其他规则/02-PRD编写与状态流程规则.md`（若已安装），遵循其中的流程图与泳道图制图规范。
2. 核对涉及的业务角色与端边界（例如：普通用户 / 管理员 / 客户端 / 服务端 / 第三方服务），沿用项目既有业务术语，不臆造未提及的审批节点或角色。
3. 先判定选图类型：
   - **单角色/单系统线性或分支流转** → 绘制**业务流程图**（`flowchart TD` 或 `flowchart LR`）；
   - **涉及 2 个及以上角色或双端协作**（如客户端 ↔ 服务端、用户 ↔ 审核员 ↔ 系统） → 必须绘制**跨职能泳道图**（使用带 `subgraph` 分区的 `flowchart` 清晰划分每一端/角色职责）。

## 2. 制图执行规范

1. **闭环与节点规范**：
   - 每张图必须有唯一的明确起点与全部合法终态（成功结束 / 取消中止 / 失败退出），严禁出现无出口的“断头节点”；
   - 节点标签使用简明动宾短语（如 `校验登录态`、`提交预览`），避免把整段长句子塞进方框；含括号或特殊符号的标签必须用双引号包裹（如 `A["校验权限 (RBAC)"]`）。
2. **判断分支与连线标签**：
   - 每个菱形判断节点的所有流出边必须标注清晰条件（如 `通过` / `拒绝`、`已安装` / `未安装`），禁止出现无条件标签的多分支箭头；
   - 跨泳道连线必须标明传递的数据、指令或触发事件（如 `提交配置参数`、`返回脱敏预览`）。
3. **强制补齐异常与回退路径**：
   - 对网络超时、校验失败、权限不足、并发冲突、用户中途取消等高频异常分支给出明确流向（提示重试、安全回退或终止），严禁只画理想主路径。
4. **控制单图信息密度**：单张主流程图/泳道图聚焦一个完整业务场景（建议 12–25 个节点以内）；超大流程拆分为“主流程总览图 + 子流程详图”，保持一屏可读。

## 3. 输出结构

- **一、场景与选图说明**（适用业务场景、选用流程图还是泳道图、参与角色/端定义）
- **二、可视化流程图 / 泳道图**（规范 Mermaid 代码块，可直接渲染或导入飞书/文档）
- **三、关键交接与异常分支表**（`节点/交接点 | 责任方 | 正常流向 | 异常/超时处理`）
- **四、流程断点与待确认项**（指出输入需求中缺失边界条件的分支）

## 4. 交付自检与红线

- 检查泳道划分是否严格按“谁执行放谁的泳道”，无把服务端校验错画在用户泳道。
- 检查 Mermaid 语法无裸特殊字符、无未闭合 `subgraph`、无无标签条件分支。
- 如用户配置了飞书 MCP / 画板工具并明确要求同步，可在确认图内容无误后再写入外部文档或画板。
