# 产品结构图生成

## 1. 开始前核对

1. 优先读取当前项目 `.agent-rules/overrides.md`、`.agent-rules/product-pm/15-AI通用入口规则.md` 及 `.agent-rules/product-pm/其他规则/01-需求范围与产品结构规则.md`（若已安装）。
2. 检查仓库现有产品文档、页面路由或既有 `.xmind` / 结构文档，沿用项目既有业务术语，禁止随意重命名既有模块。
3. 确认本次结构图的受众与粒度：全局产品规划、单版本需求范围，还是双端（如前端/客户端 + 管理后台）模块总览。

## 2. 执行步骤

1. **确立产品总根与端划分**：顶层为产品名称；如为多端产品（如 XR 客户端 + Web 管理后台 + 桌面工具），第一层先按“端/工作区”清晰分枝，避免把后台配置项混进前台用户页面。
2. **按“核心模块 → 页面/子功能 → 关键操作/信息元素”逐层展开**：
   - 遵循 MECE 原则（相互独立、完全穷尽），同级节点保持同一抽象层级，禁止将“按钮文案”与“一级模块”并列。
   - 纯中文节点命名尽量简短可读（建议 ≤ 7 字），不塞入整段解释文字，严禁使用“预览安装/预览更新/预览并应用”等拼接动词。
   - 明确标注范围与状态标签（如 `[本版 P0]`、`[已有]`、`[规划]`、`[仅管理员]`）。
3. **补充跨模块入口与复用组件**：对全局导航、登录鉴权、消息中心、设置/关于等横切能力单列清晰节点，避免在多个模块重复堆叠。
4. **选择合适交付载体并执行脚本校验**：
   - 默认提供**层级大纲（Markdown 列表）** + **Mermaid `flowchart LR` 可视化结构图**（遵守节点特殊字符双引号包裹原则）。
   - 若用户要求生成或更新 `.xmind` 产物，优先使用 XMind 原生概要（summary）表达收敛去向；**落盘后必须执行配套确定性校验脚本** [validate-xmind.mjs](./scripts/validate-xmind.mjs)：
     ```bash
     node <skill-dir>/scripts/validate-xmind.mjs <target.xmind> --max-depth 6 --max-zh-len 7
     ```
     脚本未返回退出码 `0` 前不得宣称结构图交付完成。

## 3. 输出结构

- **一、结构口径说明**（适用版本、端形态、标签图例）
- **二、产品结构图（Mermaid 可视化）**
- **三、完整层级清单表**（一级模块 / 二级页面 / 核心功能点 / 优先级 / 备注）
- **四、结构审视与缺口提示**（指出明显孤立页面、入口过深或权限边界不清之处）

## 4. 交付自检与红线

- 检查是否严格遵守产品结构层级（模块 → 页面 → 功能/元素），无把“接口实现”或“数据库表”写进产品结构图。
- 检查主链路入口深度（高频操作原则上不超过 3 级可达）与空态/异常/设置等辅助节点是否齐备。
- 不得把规划中未实现的能力标为“已上线现状”。
