# 版本验收清单生成

## 1. 开始前核对

1. 优先读取 `.agent-rules/overrides.md`、`.agent-rules/common/02-软件版本迭代与发布管理规范.md`、`.agent-rules/product-pm/其他规则/03-XR产品体验与验收准出规则.md` 及 `.agent-rules/xr-common/其他规则/03-真机验证与跨岗位协同基线.md`（若已安装）。
2. 读取本版本 PRD、功能清单、已知缺陷列表及目标发布版本号/构建号，以真实需求与代码事实为准。
3. 确认验收环境与目标设备清单（如 Web 浏览器矩阵、macOS/Windows 桌面端、具体 XR 头显型号与系统版本）。

## 2. 执行步骤

1. **划分验证层级与阻断门禁**：
   - **P0 阻断准出项（任一失败即一票否决发版）**：核心主链路跑通、数据不丢失/旧版平滑迁移、无崩溃/死锁、版本号与产物一致、XR 帧率达标与无眩晕红线违规。
   - **P1 核心体验项**：界面状态完整、错误提示清晰、多端/弱网恢复正常、性能与温控达标。
   - **P2 已知非阻断项**：记录可带病上线但须排入下版本的瑕疵，并明确风险说明。
2. **编写可执行验收条目**：每条包含 `编号 / 模块 / 前置条件 / 操作步骤 / 预期结果 / 验证层级（编辑器/模拟器/真机） / 结论（通过/不通过/待测）`。
3. **覆盖升级、回滚与发布资产核对**：补充从上一正式版本覆盖升级验证、配置文件兼容、Release Notes / CHANGELOG 准确度及异常回滚路径核对。

## 3. 输出结构

- **一、版本与测试环境信息表**（目标版本、构建号、Commit SHA、测试设备清单）
- **二、P0 阻断级冒烟与准出清单**
- **三、分模块功能与异常流验收表**
- **四、XR 真机专项验收项**（非 XR 项目自动省略本节，不硬套）
- **五、准出签字结论模板**（通过项 / 阻塞项 / 遗留风险与责任人）

## 4. 交付自检与红线

- 严禁将“编辑器预览通过”或“代码自检通过”写为“真机/用户端已验收”。
- 所有验收步骤必须具体可复现，避免“体验良好、无明显卡顿”等无法判定的描述。
- 如用户配置了飞书 MCP 且要求落表，可将验收条目导出为可导入多维表格的结构；否则直接输出 Markdown 清单。
