# 会议纪要转待办

## 1. 开始前核对

1. 若项目已安装 `.agent-rules/overrides.md` 或 `.agent-rules/product-pm/`，先核对项目模块名称、成员角色口径与既有任务模板。
2. 明确输入材料来源（会议逐字稿、飞书妙记/纪要、聊天记录或口述要点），检查是否包含日期、参会人、项目名称与版本上下文。
3. 若用户要求同步写入飞书任务、多维表格或群消息，先核对飞书 MCP 是否可用并在真正写入前向用户确认任务清单，严禁未经确认批量给他人派发任务。

## 2. 执行步骤

1. **提取四类关键信息**（严格忠实原文，不脑补结论）：
   - **已敲定决策（Decisions）**：明确达成一致的方案、范围增减、时间节点及决策依据。
   - **明确可执行待办（Action Items）**：拆解为单人负责的原子动作，提取 `任务描述 / 负责人 / 所属岗位 / 截止时间 / 依赖前置 / 验收交付物`。
   - **未决争议与阻塞项（Open Issues & Blockers）**：会上没定下来、需要会后进一步调研或由更高层拍板的问题。
   - **风险与变更影响（Risks & Scope Changes）**：对既有排期、跨岗位接口、预算或版本范围造成的连锁影响。
2. **去重与补齐缺口标注**：合并重复讨论点；对原文未指明负责人或截止日期的待办，显式标注 `待确认`，禁止自行编造人名或日期。
3. **按岗位分组呈现**：便于产品、UI、3D、TA、Unity、前后端各角色快速认领，并标注跨岗位交接先后顺序。

## 3. 输出结构

- **一、会议概览**（主题 / 时间 / 参会人 / 核心议题）
- **二、已达成决策清单**（编号 + 决策内容 + 影响范围）
- **三、分岗位待办任务表**（`ID | 岗位 | 任务项 | 负责人 | 截止日期 | 交付物 | 前置依赖`）
- **四、待决问题与风险追踪**（含建议跟进人）
- **五、可直接转发群聊的精简同步版**（3–6 行要点，方便一键同步团队）

## 4. 交付自检与红线

- 严禁把“某人会上随口提的设想”错写成“已确认决策”。
- 所有日期优先转为绝对日期（如 `2026-11-28`），避免只写“下周三”“明天”导致后续回看失真。
- 涉及飞书任务或群消息发送时，必须先呈现待写入清单并获用户确认后再执行外部写入。
