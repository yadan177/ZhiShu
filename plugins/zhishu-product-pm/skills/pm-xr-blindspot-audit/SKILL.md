# 需求自检与 XR 盲区排查

## 1. 开始前核对

1. 若项目已安装智枢规则，优先读取 `.agent-rules/overrides.md`、`.agent-rules/product-pm/其他规则/03-XR产品体验与验收准出规则.md` 与 `.agent-rules/xr-common/` 下的硬件预算、防眩晕红线及音频规范。
2. 明确被审需求的**目标硬件档位**（如移动 XR 一体机 vs PCVR 串流）、**显示模式**（VR 全沉浸 / MR 透视 / AR）及**输入方式**（6DoF 手柄 / 裸手追踪 / 眼动 / 混合）。
3. 若需求未说明目标设备或刷新率基线，将“缺少硬件与帧率假设”列为首条高危阻塞项。

## 2. 排查维度（逐项过筛）

1. **通用需求闭环检查**：
   - 是否存在“只有成功路径、没有失败/空态/中断恢复/无权限路径”的缺口；
   - 是否遗漏数据迁移、旧版本兼容、并发冲突、防重复提交或运维配置开关；
   - 是否存在范围蔓延、术语不统一或不可测试的主观描述。
2. **XR 空间舒适度与防眩晕红线**：
   - 是否包含强制接管头部视角、未经缓冲的镜头抖动/平滑加速旋转、贴脸过近（< 0.5m）弹窗或视差冲突；
   - 连续佩戴时长、坐姿/站姿切换、大空间行走安全边界（Guardian / 透视警示）是否明确。
3. **输入与追踪降级**：
   - 手柄电量耗尽/失踪、裸手出视野（FOV 外）丢失追踪、遮挡、摘戴头显休眠唤醒时，业务流程能否安全暂停与恢复。
4. **移动一体机性能与多模态风险**：
   - 需求是否隐含超预算效果（如海量同屏动态角色、全屏实时模糊、未限制粒子特效、长音频常驻或未限幅爆音）；
   - MR 透视场景下文字/UI 在高亮或杂乱现实背景中的可读性，以及空间音频是否遮蔽现实安全声。

## 3. 输出结构

- **审查结论摘要**：通过 / 有条件通过 / 建议打回重修，及高/中/低风险数量统计。
- **问题清单表**：`编号 | 风险等级（阻断/高/中/低） | 所属维度 | 对应需求位置 | 风险说明 | 可落地修改建议`。
- **需拉通的上下游岗位**：标明需要同步确认的岗位（UI / 3D / TA / Unity / 后端）。

## 4. 交付自检与红线

- 每条指出的问题必须附具体位置和可执行改法，禁止输出空泛套话。
- 区分“产品必改红线”与“体验优化建议”，不替业务方擅自删除核心价值功能，而是给出兼顾舒适度与性能的替代方案。
