# 需求调研与竞品分析

## 1. 开始前核对

1. 若当前工作区存在 `.agent-rules/overrides.md` 与 `.agent-rules/product-pm/15-AI通用入口规则.md`，先读取以确认项目本地边界；涉及 XR/MR/AR 时同步核对 `.agent-rules/xr-common/15-AI通用入口规则.md`。
2. 核对项目现有产品文档、用户反馈记录、历史版本说明或代码现状，区分**已验证事实**与**待确认假设**。
3. 明确本次调研的业务目标、目标用户角色、目标端形态（Web / 桌面 / 移动 / VR / MR）及时间窗口。

## 2. 执行步骤

1. **问题与用户分层**：用“目标角色 → 核心场景 → 触发条件 → 现有痛点 → 替代方案”结构梳理真实问题，避免从拍脑袋功能出发。
2. **竞品与标杆对照**：选取 2–4 个同场景标杆产品（若涉及外部实时信息且无联网能力，明确标注基于已有资料或请用户补充实测截图），从**核心路径、信息架构、交互亮点、明显短板、商业/技术约束**五个维度建立客观对比表，禁止空泛形容词。
3. **差异化机会与取舍**：提炼“必须对齐的行业基线”“本产品差异化突破口”与“刻意不做（Out of Scope）”三类结论。
4. **MVP 优先级排序**：使用 `P0（本版必做）/ P1（次优先）/ P2（后续演进）` 对需求池排序，并为每个 P0 标注可衡量的成功指标。

## 3. 输出结构

- **一、调研目标与已知事实边界**（列出依据来源与待补充信息）
- **二、目标用户与高频痛点矩阵**
- **三、竞品横向对比表**（维度化对比 + 关键借鉴与避坑结论）
- **四、需求池与 MVP 范围建议**（含 P0/P1/P2 分级与明确不做清单）
- **五、待决策问题清单**（需要业务方或技术负责人拍板的最多 5 个关键问题）

## 4. 交付自检与红线

- 不得捏造竞品未核实的具体参数、定价或版本号；不确定的信息显式标注“待实测核验”。
- 涉及 XR 产品时，必须核对目标头显档位、佩戴时长、交互方式（手柄 / 裸手 / 眼动）与场地约束。
- 若用户环境已配置飞书 MCP 且用户明确要求同步，可将结论写入指定飞书文档或汇总到多维表格；未配置时直接输出结构化 Markdown。
