# PRD 需求文档编写

## 1. 开始前核对

1. 若项目已安装智枢规则，优先读取 `.agent-rules/overrides.md`、`.agent-rules/product-pm/15-AI通用入口规则.md` 与 `.agent-rules/product-pm/其他规则/02-PRD编写与状态流程规则.md`；涉及 XR 体验时同步读取 `.agent-rules/xr-common/`。
2. 核对项目现有文档目录（如 `项目文档/产品文档/`）与既有 PRD 模板，沿用已有编号、术语与文件路径，不另造冲突目录。
3. 盘点已知输入（需求背景、产品结构图、调研结论或现有代码/设计稿），对关键缺失决策列为“待确认项”而非替业务方私下拍板。

## 2. 执行步骤

1. **锁定文档头与范围边界**：写明版本号、目标用户、核心业务目标、**本期做什么（In Scope）**与**明确不做什么（Out of Scope）**。
2. **绘制业务流程图与跨端泳道图**：
   - 单角色串行流程使用标准业务流程图（`flowchart TD/LR`），明确起点、分支判断条件与终态。
   - 涉及多角色或双端协作（如“用户 / 客户端 / 服务端 / 管理员”）时，使用**泳道图（带 `subgraph` 分区的 `flowchart`）**清晰界定每一端职责与交接点，并标注超时、拒绝、回退等异常分支。
3. **拆解模块与功能规格**：按模块逐项说明触发入口、前置条件、输入字段与校验规则、处理逻辑、状态流转（含空态/加载/成功/失败/无权限/离线降级）与输出反馈。
4. **明确非功能要求与数据埋点**：补充性能/帧率/并发预期、权限与安全边界、兼容性要求及关键核心指标。
5. **编写可测试的验收标准（AC）**：使用“给定（Given）—当（When）—则（Then）”或可勾选清单，确保测试同学无需二次追问即可直接转成测试用例。

## 3. 输出结构

1. **文档元信息与变更记录**
2. **背景、目标与范围边界（In / Out of Scope）**
3. **用户角色与权限矩阵**
4. **核心业务流程图与跨端泳道图**
5. **功能详细规格**（按模块编号，含字段约束、状态表与异常处理）
6. **非功能要求与兼容/迁移说明**
7. **验收标准清单与待确认问题（Open Questions）**

## 4. 交付自检与红线

- 每条功能规格必须具备明确边界条件（空值、超长、并发冲突、断网/超时、取消回退），禁止只写“正常流程”或含糊措辞如“界面友好、响应迅速”。
- 严禁在 PRD 中把具体代码实现细节（如数据库索引、内部类名）当作产品需求约束。
- 若用户要求写入项目文档目录，落盘前核对是否覆盖既有内容，并如实列出本次新建或修改的文件路径。
