# XR 真机性能排障

## 1. 开始前核对

1. 优先读取项目 `.agent-rules/overrides.md`、`.agent-rules/unity/其他规则/16-问题定位与根因确认规则.md`、`03-性能优化规则.md`、`07-日志调试规则.md` 及 `.agent-rules/xr-common/`（若已安装）。
2. 先收集可复现的故障事实：**设备型号、系统版本、构建版本/Commit、现象描述（持续低帧 vs 周期尖刺 vs 切场卡顿 vs 长时间升温掉帧 vs OOM 闪退）、复现路径及已有日志/Profiler 截图**；事实不足时先列出最小诊断采样步骤，绝不盲改代码碰运气。

## 2. 根因收敛排障流程

1. **现象归类与假设排序**：
   - **规律性尖刺卡顿**：优先排查托管堆 `GC.Collect` 峰值、对象频繁实例化/销毁、Shader 首次编译卡顿（PSO/Shader Warmup 缺失）或 UGUI Canvas 重建。
   - **持续帧率不达标**：核对 CPU Main/Render 与 GPU Frame Time 判定 CPU Bound 或 GPU Bound（DrawCall、粒子 Overdraw、分辨率缩放、阴影与动态光）。
   - **运行 10+ 分钟后掉帧**：优先排查内存持续上涨、资源未释放及散热降频（Thermal Throttling）。
   - **切场景/触发功能时冻结**：排查同步资源加载、大音频 `Decompress On Load`、同步 IO 或主线程大 JSON 反序列化。
   - **XR 特有抖动/重投影**：检查主线程阻塞、双目姿态预测时间差、固定物理步长 `FixedDeltaTime` 与头显刷新率不匹配。
2. **最小隔离实验**：设计单一变量开关验证（如临时隐藏特效层、关闭后处理、开启 Profiler Deep/Allocation 采样、查看 `adb logcat` 崩溃堆栈），用实测证据证实根因后再动业务代码。
3. **实施最小精准修复与防回归**：修复后在相同设备、相同场景重测对比修复前后数据，并评估是否补充自动化检查或监控告警。

## 3. 输出结构

- **一、故障现象与已知证据摘要**
- **二、候选根因假设表**（按概率与影响排序 + 对应证伪/证实采集指令）
- **三、定位结论与最小修复方案**（仅在证据充分时给出直接代码修改；证据不足时明确先采哪些指标）
- **四、真机复测验收标准**（修复前后对比维度与长测时长）

## 4. 交付自检与红线

- 严格遵守**先确认根因、再修改代码**原则，严禁同时乱改 5 处无关配置掩盖真实原因。
- 不得把 Unity Editor 下的帧率表现当作真机修复已验证的证据。
