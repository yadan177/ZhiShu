# 接口契约与前后端联调核对

## 1. 开始前核对

1. 优先读取目标项目 `.agent-rules/overrides.md`、`.agent-rules/common/03-跨端接口契约与联调规范.md` 及对应后端语言的 API 设计规则（`go/04`、`java/06`、`python/06` 等，若已安装）。
2. 同时定位**契约真源**（OpenAPI / `.proto` / Schema 文档）、**服务端路由与序列化模型**以及**前端/客户端请求层与类型定义**，坚持两端源码对照核验，不单凭一方猜测另一方。

## 2. 逐项核对维度

1. **路径、方法与鉴权一致**：HTTP 方法、URL 路径与版本前缀、Query/Path/Body 参数位置、必填性与鉴权 Header 双端严格匹配。
2. **字段命名与类型安全**：
   - 核查命名风格全链路统一（不混用 `camelCase` 与 `snake_case`）；
   - 核查超过 `2^53 - 1` 的 64 位 ID 是否字符串化、金额是否避开浮点传输；
   - 核查空列表 `[]` vs `null` vs 缺失字段处理一致，且消费端忽略未知新增字段。
3. **时间、时区与分页对齐**：时间格式自带时区（ISO-8601）或显式单位时间戳，分页请求与返回键名沿用项目统一模型。
4. **错误码、追踪与异常流**：HTTP 状态码、统一错误体结构、业务错误码、`X-Request-Id` / `requestId` 透传，确认不泄露内部堆栈或敏感信息。
5. **幂等、超时与兼容红线**：核心写操作幂等键、客户端超时取消与非 `4xx` 退避重试、WebSocket 心跳与断线补拉；确认接口修改未破坏仍在活跃的旧版客户端。

## 3. 输出结构

- **一、契约与实现一致性总览**（对齐 / 存在错位项 / 存在破坏性变更风险）
- **二、双端差异明细表**：`接口 | 字段或规则 | 契约定义 | 服务端实现 | 前端/客户端实现 | 风险级别 | 修复建议`
- **三、联调测试矩阵**（含成功主路径与鉴权失效、参数非法、空态、超时重试等异常流用例）

## 4. 交付自检与红线

- 发现双端字段不一致时，必须明确指出以哪一份契约真源为准并同步两端，防止各自私下改偏。
- 涉及破坏性接口变更时必须标红阻断并给出无破坏兼容方案（双写过渡或升版本前缀）。
