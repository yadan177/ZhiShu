# 自动化测试生成

## 1. 开始前核对

1. 优先读取项目 `.agent-rules/overrides.md` 与当前语言包测试规则（`javascript/08`、`go/11`、`java/08`、`python/08`，若已安装）。
2. **先探测仓库既有测试框架与写法**：检查 `package.json`、`go.mod`、`pom.xml`/`build.gradle`、`pyproject.toml` 与现有测试文件，**100% 沿用项目既有测试框架、断言库与目录结构，严禁私自引入 Jest / Vitest / Testify / pytest 插件等未授权依赖**。
3. 明确本次测试目标：被测模块的输入输出契约、核心分支、错误处理逻辑与易回归边界。

## 2. 高质量用例设计步骤

1. **优先测行为契约而非脆弱实现细节**：断言公开输入输出、状态变更、文件落盘与错误语义，避免过度 Mock 内部私有方法导致“重构就碎”。
2. **系统覆盖四类必测场景**：
   - **主路径（Happy Path）**：标准合法输入与端到端闭环。
   - **边界与极值**：空输入、0/1/超长值、特殊字符、跨平台路径（如 macOS `/tmp` 符号链接规范化）、并发/重入。
   - **异常与安全拒绝**：损坏文件、非法参数、路径逃逸/符号链接拦截、凭据脱敏、漂移冲突阻断与失败回滚。
   - **缺陷防回归**：若是修 Bug 任务，先写出在未修复前必挂、修复后必过的最小复现用例。
3. **测试隔离与零副作用**：使用独立临时目录（`mkdtemp`）并在 `finally` / cleanup 中彻底清理，不依赖外部不稳定网络或污染用户真实主目录；跨平台时间、随机数或外部 CLI 优先使用可控桩（Stub/Fake）。
4. **真实运行并核对结果**：写完后执行项目既定测试命令，确认全部新增与既有测试通过。

## 3. 输出结构

- **一、测试覆盖矩阵**（列出新增用例名与对应验证的场景/风险）
- **二、测试代码落盘路径与关键说明**
- **三、实际运行命令与精确结果**（通过/失败/跳过数；若环境受限无法执行某外部集成项，明确说明原因与跳过项）

## 4. 交付自检与红线

- 严禁通过删除断言、放宽错误匹配或伪造测试输出让用例“假通过”。
- 不得把需要外部真实密钥或线上服务的用例做成无门控默认必跑测试，应与离线单测清晰隔离。
