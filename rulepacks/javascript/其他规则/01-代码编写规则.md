# 01 - JavaScript 代码编写规则

> - 🟢 本文件适用于 JavaScript / Node.js 代码的基础语法与写法约束。
> - 🔴 不适用：项目级架构决策、第三方库深度用法、构建工具配置

---

## 1. 🔴 硬约束 · 这些绝对不要写

### 1.1 命名规范（变量 / 函数 / 类 / 常量 / 文件）

**变量 / 函数 / 方法**：`camelCase`

```js
// ✅
const userName = 'alice';
function getUserById(id) { /* ... */ }

// ❌
const user_name = 'alice';          // Python 风格
const UserName = 'alice';           // 误用 PascalCase
```

**类 / 构造函数**通常使用 `PascalCase`；框架组件命名按 React/Vue 专题和项目约定。

```js
// ✅
class UserService { /* ... */ }

// ❌
class userService { /* ... */ }
```

**模块级固定常量（编译期/配置期不变的真值）**：常见约定为 `UPPER_SNAKE_CASE`；局部或运行期计算的 `const` 绑定使用 `camelCase`，具体以项目既有风格为准。

```js
// ✅ 模块级固定常量使用 UPPER_SNAKE_CASE，运行期或局部 const 使用 camelCase
const MAX_RETRY_COUNT = 3;
const API_BASE_URL = 'https://api.example.com';
const currentUser = getCurrentUser();

// ❌ 对运行期可变对象或局部变量滥用全大写
const USER_PROFILE = fetchUserProfile(id);
```

**文件 / 目录**：沿用项目现有命名方式并在同一目录保持大小写一致；新项目未约定时，普通 JS 模块常用 `kebab-case`，React/Vue 等组件文件可按框架与项目约定使用 `PascalCase`（如 `UserCard.jsx` / `UserCard.vue`）。

```text
✅ 普通模块：user-service.js / date-utils.js
✅ 组件文件（按项目约定）：UserCard.jsx / UserCard.vue（或统一 kebab-case）
❌ 同目录混用风格：user-service.js 与 UserService.js 并存
```

**私有字段**：目标运行时和构建链支持时可使用 `#field`；`_field` 只是命名约定，不能提供运行时私有性。

```js
class Counter {
  #count = 0;                       // ✅ 真私有
  increment() { this.#count++; }
}

// ❌ _count 在外部仍可访问,只是"约定俗成"
class BadCounter {
  constructor() { this._count = 0; }
}
```

**命名"见名知意"**：禁止无意义缩写（`a / tmp / data1 / x`）

```js
// ❌
const d = getData();
const u = fetchUser();

// ✅
const userList = await fetchUser();
const userCount = users.length;
```

**禁用特性**：避免使用 `arguments`（改用 rest 参数 `...args`，避免类数组操作和箭头函数不可用问题）、`with`（严格模式/ESM 禁用且破坏静态作用域）以及 `eval` / `new Function`（存在代码注入风险并阻碍引擎优化；安全边界见 [11-安全规则](./11-安全规则.md)，其他常见反模式见 [12-JS常见反模式](./12-JS常见反模式.md)）。

### 1.2 引用与导入（import / export / 路径）

模块系统必须沿用项目的运行时、`package.json`、构建和发布约定；不得为了统一风格在 ESM 与 CommonJS 之间迁移。

```js
// ESM 项目
import { parseConfig } from './config.js';

// CommonJS 项目
const { parseConfig } = require('./config.cjs');
```

import 顺序和分组由项目 formatter/lint 配置决定；没有约定时可按运行时内置、外部依赖、项目内部的顺序保持稳定。

```js
// ✅
import fs from 'node:fs';           // 内置模块（Node 14.18+/16+ 起 ESM 与 CJS 均支持 node: 前缀）

import externalPackage from 'external-package'; // 项目已声明的外部依赖

import { getUser } from '@/api/user'; // 内部(@/ 仅在项目已配置别名时使用)
import { formatDate } from './util.js'; // 原生 Node ESM 需显式写扩展名，bundler 项目按项目解析约定
```

默认导出和具名导出沿用模块公共 API 与项目约定；公共库需要稳定重导出或静态分析时可优先评估具名导出。

```js
// 不推荐：把多个无关能力打包成一个默认对象
export default { getUser, createUser, deleteUser };

// ✅ 具名导出
export function getUser(id) { /* ... */ }
export function createUser(data) { /* ... */ }
```

路径别名只有在项目构建、类型检查、测试和运行时都已配置时才能使用；不得从示例引入 `@/`、`~/`。

循环依赖应通过调整职责或依赖方向消除；检测优先使用项目已有 lint、构建分析或测试，不为本节自动安装 `madge`。

### 1.3 类型与解构（const / let / 解构 / 展开）

**禁用 `var`**，只用 `const`（默认）/ `let`（需要重赋值）。

```js
// ✅
const PI = 3.14;
let count = 0;
count++;

// ❌
var PI = 3.14;                      // 变量提升 / 函数级作用域
```

**禁用 `==` / `!=`**，只用 `===` / `!==`。

```js
// ❌
if (count == '5') { /* 隐式转换 */ }

// ✅
if (count === 5) { /* 类型安全 */ }
```

**解构优于字段访问**（多层 / 多次访问时；嵌套对象可能为 `null` 或 `undefined` 时需配合可选链或默认值防崩溃）。

```js
// ✅ 字段确认非空时直接解构；嵌套对象可能缺省时先解构外层并配合可选链
const { name, age, address } = user;
const city = address?.city ?? '未知';

// ❌ 嵌套字段可能为 null/undefined 时直接深层解构会抛 TypeError
// const { address: { city } } = user;
```

**解构 + 默认值** 处理 `undefined`。

```js
const { page = 1, pageSize = 20 } = query;
```

**展开运算符**做浅拷贝（注意：只一层）；纯结构化数据的深拷贝在 Node 17+ 与现代浏览器中可优先评估标准 `structuredClone()`（不支持函数、Symbol 与 DOM 节点）。

```js
const newUser = { ...user, name: 'bob' };    // ✅ 一层浅拷贝
const updated = { ...user, address: { ...user.address, city: 'Shanghai' } };  // ✅ 仅克隆修改路径
const fullClone = structuredClone(user);     // ✅ 需要完整深拷贝纯数据时
```

### 1.4 字符串与模板（拼接 / 模板字符串 / 标签模板）

**优先模板字符串**，不要 `+` 拼接。

```js
// ✅
const greeting = `Hello, ${name}! You are ${age} years old.`;

// ❌
const greeting = 'Hello, ' + name + '! You are ' + age + ' years old.';
```

**多行字符串**用模板字符串，不要用 `\` 续行。

```js
// ✅
const sql = `
  SELECT *
  FROM users
  WHERE id = ?
`;

// ❌
const sql = 'SELECT *\n' +
             'FROM users\n' +
             'WHERE id = ?';
```

不要依赖 `+`、宽松相等或模板插值中的意外类型转换；需要转换时显式使用 `String(value)`、`Number(value)` 或 `Boolean(value)`，并处理转换失败或特殊值。

### 1.5 函数（声明 / 箭头 / 参数 / 返回值）

箭头函数适合词法 `this` 和短回调；需要动态 `this`、原型方法、提升或项目既有声明风格时使用普通函数。

```js
// ✅
const add = (a, b) => a + b;

// 类方法用普通方法(method)语法
class Counter {
  count = 0;
  increment() { this.count++; }
}
```

**单一职责**：一个函数只做一件事。

```js
// ❌ 一个函数干三件事
function processUser(user) {
  validate(user);
  save(user);
  sendEmail(user);
}

// ✅ 拆开并在 async 编排函数中显式组合
async function registerUser(user) {
  const validated = validateUser(user);
  await saveUser(validated);
  await sendWelcomeEmail(validated);
}
```

参数较多、多个参数含义相近或调用点容易传错时，优先评估对象参数。参数数量只是可读性信号，不设脱离项目语境的固定上限。

```js
// ❌ 5 个参数
createUser('alice', 25, 'female', 'alice@example.com', 'Beijing');

// ✅
createUser({ name: 'alice', age: 25, gender: 'female', email: 'alice@example.com', city: 'Beijing' });
```

**纯函数优先**：同样的输入 → 同样的输出，无副作用。

**rest 参数替代 `arguments`**：

```js
// ✅
function sum(...nums) { return nums.reduce((a, b) => a + b, 0); }

// ❌
function sum() { return Array.prototype.reduce.call(arguments, (a, b) => a + b, 0); }
```

### 1.6 类与面向对象（class / 继承 / 私有 / 静态）

**用 `class` 语法**，不用函数构造器。

```js
// ✅
class User {
  constructor(name) { this.name = name; }
  greet() { return `Hi, ${this.name}`; }
}

// ❌ 函数构造器(已过时)
function User(name) {
  this.name = name;
}
User.prototype.greet = function () { return 'Hi, ' + this.name; };
```

**继承 vs 组合**：优先组合（has-a），必须 is-a 才用继承。

```js
// ✅ 组合
class User {
  constructor(name, address) { this.name = name; this.address = address; }
}

// ❌ 过度继承
class BeijingUser extends User { /* 只为继承城市？ */ }
```

**静态方法**用于工具，不依赖实例。

```js
class User {
  static createGuest() { return new User('Guest'); }
}
const guest = User.createGuest();
```

**getter / setter**：仅在字段需要计算 / 校验时使用，简单字段直接公开。

### 1.7 模块化（export / import / 副作用 / 动态导入）

**具名导出为主**。

**内部目录 barrel files（`index.js`/`index.ts` 大量 `export *`）**：谨慎使用——可能拖慢 IDE 自动补全、影响 tree-shaking 并增加循环依赖风险。但 **monorepo 子包或发布库的单一公共入口**（如 `packages/<pkg>/src/index.ts`）通过显式重导出对外暴露稳定公共 API 属于合理用法（与 [02-模式设计规则 §1.2](./02-模式设计规则.md) 一致）。

```js
// ❌ 内部子目录把无关模块全量通配重导出
export * from './user.js';
export * from './order.js';
export * from './product.js';

// ✅ 模块内部直接从目标文件导入（原生 Node ESM 需显式写扩展名，bundler 按项目约定）
import { getUser } from './user/user.api.js';
```

**避免隐蔽的顶层副作用**：普通业务与库模块顶层不要修改全局变量（如 `window.x = ...`）或隐式触发网络/I/O 请求；若属于 CLI 入口、Electron preload（`contextBridge` 注册）或项目启动契约要求的显式初始化，应收敛在约定入口并明确执行时机、幂等性与清理方式（与 [02-模式设计规则 §1.2](./02-模式设计规则.md) 一致）。

**动态 `import()` 用于按需加载与代码分割**：

```js
// ✅ 按需加载功能模块（React/Vue 路由懒加载见对应框架专题）
async function openFeature() {
  const { initFeature } = await import('./feature.js');
  initFeature();
}

// ✅ 条件加载
if (isDev) {
  const { logger } = await import('./logger.js');
}
```

### 1.8 控制流（if / switch / for / 异常处理）

**早返回（guard clause）**，减少嵌套。

```js
// ✅ 早返回
function getDiscount(user) {
  if (!user) return 0;
  if (!user.isVip) return 0;
  return user.level === 'gold' ? 0.2 : 0.1;
}

// ❌ 嵌套地狱
function getDiscount(user) {
  if (user) {
    if (user.isVip) {
      if (user.level === 'gold') {
        return 0.2;
      } else {
        return 0.1;
      }
    } else {
      return 0;
    }
  } else {
    return 0;
  }
}
```

简单的“值到值”映射可用对象或 `Map` 表达；包含分支流程、类型收窄或 fallthrough 语义时保留 `switch`，不要为统一形式机械替换。

```js
// ✅ 使用 Map（或配合 Object.hasOwn 避免命中 Object.prototype 上的属性）
const STATUS_LABEL = new Map([
  ['pending', '待处理'],
  ['approved', '已通过'],
  ['rejected', '已拒绝'],
]);
const label = STATUS_LABEL.get(status) ?? '未知';

// 若沿用普通对象映射，外部 key 查表时应使用 Object.hasOwn
// const label = Object.hasOwn(STATUS_MAP, status) ? STATUS_MAP[status] : '未知';

// ❌ 简单值映射写成冗长 switch
let label;
switch (status) {
  case 'pending': label = '待处理'; break;
  case 'approved': label = '已通过'; break;
  case 'rejected': label = '已拒绝'; break;
}
```

**循环选型**：

| 场景 | 推荐 |
|------|------|
| 简单遍历 + 返回新数组 | `map` |
| 过滤 | `filter` |
| 累加 / 折叠 | `reduce`（复杂时拆 for） |
| 仅遍历副作用 | `forEach` |
| 需提前终止 | `for...of` 或 `.find` / `.some` / `.every` |
| 异步迭代 | `for await...of` |

**异常处理**：

- 用 `try/catch` 包可能抛错的代码
- **不要**空 catch / 吞错误

```js
// ❌ 空 catch（吞错误）
try { parseData(input); } catch (e) {}

// ✅ 在中间层补充上下文并携带 cause 重抛，由错误边界统一记录与处理（避免每层既记录又重抛导致重复日志）
try {
  return parseData(input);
} catch (e) {
  throw new Error('解析输入数据失败', { cause: e });
}
```

**自定义错误类**可用于携带稳定错误码与上游原因，并配合项目统一错误传播契约（见 [02-模式设计规则 §1.3](./02-模式设计规则.md) 与 [04-异步与事件循环 §1](./04-异步与事件循环.md)）：

```js
class BusinessError extends Error {
  constructor(message, { code, cause } = {}) {
    super(message, { cause });
    this.name = 'BusinessError';
    this.code = code;
  }
}
```

### 1.9 注释与文档（JSDoc / 行内 / TODO）

- 🔴 若目标项目已有明确英文注释约定（如开源英文仓库或 `.agent-rules/overrides.md` 指定），沿用项目既有语言约定；中文协作项目中，新增或修改的说明性注释、JSDoc 正文必须使用中文，JSDoc 标签、代码标识符与稳定事件键保持规范原样。
- 🟢 中文项目中可保留英文的情形包括：工具可识别标记或指令（如 `TODO`、`FIXME`、`@ts-expect-error`、`eslint-disable`）、协议/标准/第三方专有名词、已明确对外发布的英文 API 契约，以及外部依赖或自动生成代码；除标记和专有名词外，仍应以中文说明含义或原因。
- ❌ 中文协作项目中，不得仅因函数名、变量名或 API 为英文，就把说明性注释整体改写为英文。
- 🔴 方法内部和局部逻辑说明使用 `//`；对外公开或由项目约定要求文档化的 API 使用紧挨声明的 `/** ... */` JSDoc。
- ❌ **禁止**把普通 `/* ... */` 用作业务说明、算法说明或临时禁用代码；连续说明使用贴近代码的多行 `//` 说明注释。
- 🟢 文件级工具指令、不可改动的第三方/生成代码或授权声明需要 `/* ... */` 时，可保留其原有形式。

### 1.10 代码与注释并行维护

- 🔴 修改公共 API、认证与隐私边界、请求取消/重试、状态同步、组件生命周期、跨页面或跨端契约、兼容和降级逻辑时，必须在同一改动中新增或更新注释。
- 🔴 注释优先解释原因、约束、所有权、失败语义和非直观行为；不逐行复述代码，也不以注释行数或覆盖率为目标。
- 🔴 交付前同时检查错误注释、过时注释和应有但缺失的注释；不能只扫描英文注释。
- 🟢 第三方、自动生成和上游同步代码保持原文；标识符、API 字段、协议字段、SDK 名和工具指令保留英文，中文只解释用途、原因和边界。
- 🟡 承担独立业务职责、流程复杂或明显较长的自研文件应包含模块职责说明。具体行数阈值由目标项目规则决定；纯 DTO、声明文件、生成代码和简单组件可以例外。

**JSDoc** 描述公共 API。

```js
/**
 * 计算两个日期之间相差的天数
 * @param {Date} start - 起始日期
 * @param {Date} end - 结束日期
 * @returns {number} 经过的完整 24 小时数量(始终非负)
 * @throws {TypeError} 当参数不是有效 Date
 */
function daysBetween(start, end) {
  if (
    !(start instanceof Date) || Number.isNaN(start.getTime()) ||
    !(end instanceof Date) || Number.isNaN(end.getTime())
  ) {
    throw new TypeError('参数必须是有效 Date');
  }
  return Math.floor(Math.abs(end.getTime() - start.getTime()) / 86_400_000);
}
```

上例计算的是经过时长，不是本地日历日期差。涉及自然日、时区或夏令时时，必须沿用项目已采用的日期库或基于明确时区计算，不能直接用毫秒除法替代日历语义。

**行内注释解释"为什么"，不解释"是什么"**。

```js
// ❌ 解释是什么(废话)
// 把 count 加 1
count++;

// ✅ 解释为什么
// 用户点击后立即加 1,不等服务端响应(响应失败可回滚)
count++;
```

**TODO / FIXME / XXX 标签**：

```js
// TODO: 待实现 XX 功能
// FIXME: 此处有 bug,需要修复
// XXX: 临时方案,需要重构
```

**自动生成的代码不写注释**（生成器会写）。

## 2. 🟡 推荐 · 团队约定

### 2.1 项目级代码风格细节

详见 [10-代码风格规则](./10-代码风格规则.md)——沿用项目既有的代码风格与自动格式化工具，全项目保持统一，避免风格混用。

### 2.2 错误处理统一约定

- 自定义错误类 `BusinessError` / `ValidationError` / `NetworkError`（按项目已有错误模型命名并保留 `cause`）
- 进程或页面级 `unhandledrejection` / `unhandledRejection` 仅用于兜底观测与上报，不替代调用边界处理
- 见 [02-模式设计规则](./02-模式设计规则.md) 和 [04-异步与事件循环](./04-异步与事件循环.md)

### 2.3 命名补充（缩写词 / i18n 字符串）

**缩写词**在同一代码库内保持大小写风格一致（统一全大写或统一按普通词驼峰），不要混搭。

```js
// ✅ 一致（方案 A：统一全大写缩写）
function parseHTML(source) {}
function parseURL(input) {}

// ✅ 一致（方案 B：统一按普通词驼峰）
function parseHtml(source) {}
function parseUrl(input) {}

// ❌ 同一代码库内混搭缩写大小写
function parseHTML(source) {}
function parseUrl(input) {}
```

**i18n 字符串**：项目已经采用国际化体系时沿用其资源、键名和格式化方式，不从本节引入具体库。

```js
// ✅
const message = t('user.welcome', { name });

// ❌
const message = '欢迎,' + name;
```

## 3. 🟢 可选 · 视情况

### 3.1 monorepo / 多包项目结构

- 包划分：按业务域 / 按技术层
- 共享代码放在项目约定的公共包目录（如 `packages/core`、`packages/shared` 等，以仓库现有结构为准）
- workspace 和任务编排工具以仓库已有包管理器与配置为准；不得因采用 monorepo 自动引入 pnpm、Turborepo 或 Nx

### 3.2 国际化（i18n）字符串处理

- 字符串外置到 JSON / YAML
- 模板标签：`html` / `css` 等
- 复杂格式用 ICU MessageFormat
