# 10 - JavaScript 代码风格规则

> - 🟢 本文件适用于 JavaScript / Node.js 代码的外观风格（缩进/引号/分号/Prettier/ESLint）。
> - 🔴 不适用：业务逻辑实现、API 设计、数据库设计

---

## 1. 🔴 硬约束 · 这些绝对不要写

### 1.1 风格不统一（混用多种风格）

**选定一种，全项目统一**；优先沿用仓库已有约定。Airbnb、Standard、Google 或团队自定义规范均可，不应由规则库替代项目决策。

**不要**同事 A 用 Airbnb，同事 B 用 Standard，PR 里全是风格冲突。

### 1.2 缩进混乱（Tab 与空格混用）

**用 EditorConfig 锁定**：

```ini
# .editorconfig
root = true

[*]
indent_style = space              # 用空格不用 Tab
indent_size = 2                   # 2 空格缩进
end_of_line = lf
charset = utf-8
trim_trailing_whitespace = true
insert_final_newline = true       # 文件末尾留一个空行

[*.md]
trim_trailing_whitespace = false  # Markdown 保留行尾空格（用于换行）
```

**VS Code 等 IDE 自动读 `.editorconfig`**。

### 1.3 未遵循项目既有格式化约定或自动格式化工具

必须遵循项目已约定的代码格式规范、自动格式化工具（如 Prettier、Biome、dprint 或 ESLint 风格规则）或既有格式化脚本，避免在 PR 中手调大面积风格。若项目已采用 Prettier 或新项目明确选用它，可参考下例；不要为套用本节替换或强行引入 formatter。

```bash
# 仅在项目决定采用 Prettier 并获授权时安装
npm install -D prettier
```

```jsonc
// .prettierrc
{
  "semi": true,                    // 行尾分号
  "singleQuote": true,             // 单引号
  "trailingComma": "all",          // Prettier 3+ 默认值（数组 / 对象 / 函数参数均尾随逗号）
  "printWidth": 100,               // 行宽
  "tabWidth": 2,
  "useTabs": false,
  "arrowParens": "always",         // 箭头函数参数必加括号 (x) => x
  "endOfLine": "lf"
}
```

```gitignore
# .prettierignore
dist/
build/
node_modules/
coverage/
*.min.js
package-lock.json
```

**提交前自动格式化**：

```json
{
  "lint-staged": {
    "*.{js,jsx,ts,tsx,json,css,md}": ["prettier --write"]
  }
}
```

## 2. 🟡 推荐 · 团队约定

### 2.1 Airbnb 风格要点（推荐）

```js
// ✅ Airbnb 风格示例
const user = {
  firstName: 'Alice',
  lastName: 'Wonder',
  age: 25,
};

function getUser(id) {
  if (!id) {
    throw new Error('id is required');
  }
  return db.find(id);
}

const handleClick = (event) => {
  event.preventDefault();
  // 使用 event.target 执行既有的界面或业务处理。
};

// ✅ 模板字符串
const greeting = `Hello, ${user.firstName}!`;

// ✅ 解构 + 默认值
const { firstName, age = 18 } = user;

// ✅ 对象字面量简写
const newUser = { firstName, age, isActive: true };
```

**核心规则**：

| 类别 | 规则 |
|------|------|
| 缩进 | 2 空格 |
| 引号 | 单引号（字符串）/ 模板字符串（插值） |
| 分号 | 行尾必加 |
| 尾随逗号 | 按项目约定统一（Prettier 3+ 默认 `all`：数组 / 对象 / 函数参数；或 `es5`：数组 / 对象） |
| 行宽 | 100 字符 |
| 箭头函数参数 | 必加括号 `(x) => x` |
| 字符串拼接 | 必用模板字符串 |
| 比较 | 必用 `===` / `!==` |
| 变量声明 | 默认 `const`，重赋值才 `let`，禁用 `var` |

### 2.2 Standard 风格要点（备选）

```js
// ✅ Standard 风格：无分号
const user = { firstName: 'Alice' }
function getUser(id) {
  if (!id) throw new Error('id is required')
  return db.find(id)
}
```

**核心规则**：

| 类别 | 规则 |
|------|------|
| 缩进 | 2 空格 |
| 引号 | 单引号 |
| 分号 | **无** |
| 尾随逗号 | **无**（不允许） |
| 行宽 | 80 字符 |
| 空格 | 函数声明 `function name (x)` 参数前有空格 |

### 2.3 ESLint + Prettier 协作

**关键**：ESLint 管逻辑与代码质量，Prettier 管外观格式，避免规则冲突。ESLint 9+ 推荐使用 flat config（`eslint.config.js`）；已在稳定运行旧版 `.eslintrc.*` 的仓库保持现有格式，未经授权不得迁移。

```bash
# 仅在项目明确采用该组合并获授权时安装
npm install -D eslint @eslint/js prettier eslint-config-prettier
```

```js
// eslint.config.js（ESLint 9+ flat config 示例）
import js from '@eslint/js';
import prettierConfig from 'eslint-config-prettier';

export default [
  js.configs.recommended,
  {
    rules: {
      // 项目自定义规则（严重级别以仓库现有门禁为准）
      'no-console': 'warn',
      'no-debugger': 'error',
      'no-unused-vars': ['error', { argsIgnorePattern: '^_' }],
    },
  },
  prettierConfig, // 放在最后，关闭 ESLint 中与 Prettier 冲突的格式规则
];
```

### 2.5 注释风格（JSDoc）

```js
/**
 * 计算两个时间点之间经过的完整 24 小时数量
 *
 * @param {Date} start - 起始日期
 * @param {Date} end - 结束日期
 * @returns {number} 经过的完整 24 小时数量（始终非负）
 * @throws {TypeError} 当参数不是有效 Date
 *
 * @example
 * daysBetween(new Date('2024-01-01'), new Date('2024-01-10'));
 * // => 9
 */
function daysBetween(start, end) {
  if (
    !(start instanceof Date) || Number.isNaN(start.getTime()) ||
    !(end instanceof Date) || Number.isNaN(end.getTime())
  ) {
    throw new TypeError('参数必须是有效 Date');
  }
  return Math.floor(Math.abs(end.getTime() - start.getTime()) / 86_400_000);
}
```

自然日差受时区和夏令时影响，应使用项目已采用的日期能力按明确时区计算，不能套用本例。

**JSDoc 标签**：

- `@param` 参数
- `@returns` / `@return` 返回值
- `@throws` 抛错
- `@example` 示例
- `@deprecated` 废弃
- `@see` 参考

## 3. 🟢 可选 · 视情况

### 3.1 命名约定补充

**缩写词在同一代码库内保持大小写风格一致**（统一全大写或统一按普通词驼峰）：

```js
// ✅ 一致（方案 A：统一全大写缩写）
function parseHTML(source) {}
function parseURL(input) {}

// ✅ 一致（方案 B：统一按普通词驼峰）
function parseHtml(source) {}
function parseUrl(input) {}

// ❌ 同一代码库内混搭缩写大小写
function parseHTML(source) {}
function parseUrl(input) {}
```

**循环临时变量**：`i / j / k` 用于数字循环，`item / element` 用于对象 / 数组。

### 3.2 文件组织

- 每个文件围绕单一清晰的职责组织，不机械强求“一文件只能有一个类/函数”
- 文件命名沿用项目既有约定并保持同目录一致（如普通模块 `kebab-case`，React/Vue 组件文件按对应框架约定 `PascalCase` 或 `kebab-case`）
- 关联文件就近放（`user.api.js` / `user.store.js` / `user.schema.js`）
