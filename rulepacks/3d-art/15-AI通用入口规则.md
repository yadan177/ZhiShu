# 15 - 三维资产 AI 通用入口规则

> - 🟢 本文件适用于 AI 参与的三维资产规范体检、图生 3D 提示词与参考图准备、AI 模型修复方案、Blender 批处理脚本生成、FBX/glTF 导出校验与入库清单生成。
> - 🔴 不适用：未经确认直接批量覆写美术源工程文件（`.blend` / `.ma` / `.fbx`），或凭静态渲染图宣称模型拓扑与引擎性能合格。

---

## 1. 开始前核对

执行三维资产审查、脚本生成或流程辅助前，先读取[总览](./00-文档总览.md)与目标项目约定，核对以下事实：

1. **目标引擎与硬件档位**：目标引擎（如 Unity URP / HDRP / Unreal）、坐标系习惯及运行平台（移动 XR 一体机 / PCVR / 桌面 WebGL）。
2. **资产类型与重要级**：英雄主资产（近距高频观察）、常规场景道具、远景环境块，还是带骨骼蒙皮的动态角色。
3. **生产来源**：纯手工 DCC 建模，还是图生 3D 工具（Tripo / 混元 3D / Hyper3D 等）生成的 AI 粗模。
4. **项目已有规范**：已有命名规范、PBR 通道打包约定（如 Unity Metallic/Smoothness 或 ORM）、目录结构与材质模板。

- 🔴 找不到项目面数或贴图预算表时，先依据目标硬件档位给出分级建议并标明“待项目确认”，不得把单一数值冒充项目强制配额。
- 🔴 审查模型或贴图时必须基于可读取的真实几何/元数据（文件统计、导出日志、脚本扫描结果），不得仅看一张外观截图断言拓扑、UV 或法线正确。

## 3. DCC 批处理脚本安全底线

AI 生成 Blender（Python `bpy`）或其他 DCC 自动化质检/修复脚本时，必须遵守以下安全约束：

- 🔴 **先只读体检，再显式修改**：默认将“扫描报告”与“自动修复”分离；涉及减面（Decimate）、重拓扑、合并网格或覆写磁盘文件的脚本，必须先输出影响清单或另存为新版本文件，禁止无备份原地覆盖原始工程。
- 🔴 **注明目标 DCC 版本与 API 前提**：例如 Blender 3.x 与 4.x 在 `Principled BSDF` 接口、自定义法线或导出参数上存在差异，脚本顶部必须声明适用版本并在异常时给出清晰报错，而非静默跳过。
- 🔴 **严禁破坏绑定与关键元数据**：批量清理脚本必须避开骨骼权重、BlendShape / 形态键、动画关键帧与自定义挂点（Socket / Anchor）。

❌ 反例：生成一段 Blender 脚本直接对目录下全部 `.fbx` 执行无参数减面并覆盖原文件，导致角色蒙皮破裂、硬边法线全毁且无法回退。

✅ 正例：先输出只读体检脚本生成 CSV/Markdown 报告（列出超标面数、未冻结缩放、反法线与多余材质槽），再对经确认的静态道具输出带独立导出目录的可回滚批处理脚本。

## 4. 交付与报告

三维资产检查或交付报告应简要包含：

1. 资产基本信息（名称、类别、生产来源[手工/图生 3D]、目标平台档位）。
2. 量化体检指标（三角面数、LOD 档数、材质球数、贴图张数与尺寸、UV 套数、变换与轴向状态）。
3. 发现的阻断问题（🔴）与优化建议（🟡），标明具体对象/网格名。
4. 实际执行了哪些自动/人工验证，以及尚未在目标引擎与真机确认的缺口。
