# 02 - 模型拓扑面数与 LOD 预算规范

> - 🟢 本文件适用于实时 3D 与 XR 项目的网格拓扑质量、分级面数预算、LOD 制作、法线切线与碰撞体分离规范。
> - 🔴 不适用：将某一类资产的参考面数区间写死为所有项目或所有硬件档位的绝对上限。

---

## 1. 分级面数预算原则

实时 XR 渲染以**最终三角面数（Triangles）**和**实际渲染顶点数（Vertices，含 UV 接缝与硬边拆分后的真实顶点）**为准，而不是 DCC 软件里的四边面估算值：

- 🔴 **以项目硬件档位预算表为准**：移动 XR 一体机与 PCVR 预算差距显著，立项应先确定每档资产的参考上限并记录在项目预算表中。
- 🟡 **常见移动 XR 一体机分级估算参考（具体以项目预算与真机实测校准）**：

| 资产重要级 | 典型场景示例 | 预算控制策略 |
|---|---|---|
| **英雄主资产 / 可近距交互核心物** | 主角手持仪器、近距操作台、重点教学/展示主体 | 轮廓线保证平滑不露棱角，把面数集中在用户 0.5–1.5m 视野可见的结构特征上 |
| **常规中距道具** | 桌椅、常规器械、标准家具与环境装饰 | 优先用剪影体块 + 法线贴图表达细小凹凸，禁止为 2mm 倒角耗费上千三角面 |
| **背景与重复建筑模块** | 墙体、管线、外景远山、成排陈列架 | 严格控制单模块面数，优先支持静态合批或 GPU Instancing |
| **动态角色 / 手部模型** | 虚拟化身、手部追踪模型、NPC | 重点保证关节变形布线（三循环边），手部等贴近视野部位单独评估清晰度 |

- 🔴 严禁在看不见的底面、贴墙背面、封闭盒体内部保留无用封闭几何面；对封闭物体的隐藏面应删除或做遮挡剔除评估。

## 2. 干净拓扑与硬表面/变形布线红线

- 🔴 **禁止残留畸形几何**：导出前必须确保零非流形几何、零重合顶点（按合理阈值 Merge）、零重合面/共面闪烁面、零孤立点与游离边。
- 🔴 **多边面（N-gons > 4 边）处理**：静态硬表面平面在导出前须确认三角化结果无异常拉扯或阴影折痕；任何参与骨骼蒙皮、BlendShape 变形或曲面的区域严禁保留 N-gons，且优先以干净四边面环线组织。
- 🔴 **平滑组 / 锐边与法线贴图配合**：
  - 使用硬边（Hard Edge / Sharp Edge）的接缝处**必须同时断开 UV 岛**并留出足够 Padding，否则烘焙法线会出现明显黑边；
  - 法线烘烤与目标引擎的切线空间计算标准（如 MikkTSpace）保持一致，并明确法线贴图 Y 通道方向（OpenGL `Y+` vs DirectX `Y-`，Unity 默认使用 OpenGL `Y+`）。

## 3. LOD（多细节层次）规范

- 🔴 凡体量较大、会随用户距离变化、或同屏重复出现多次的资产，必须制作 **LOD 链**（常见 `LOD0 / LOD1 / LOD2`，必要时加 `LOD3` 或剔除距离）。
- 🔴 **逐级减面比例有意义**：每一级 LOD 相比上一级应有明确面数缩减（通常建议递减约 40%–55%），同时尽量维持外轮廓剪影稳定，防止切换瞬间产生明显视觉跳变（Popping）。
- 🔴 **低级 LOD 同步合并材质与简化透明**：`LOD1 / LOD2` 应优先合并多材质槽并取消远处不可见的细小镂空/装饰子件，真正降低远景 DrawCall 而非只减面数。
- 🟡 LOD 命名遵循目标引擎自动识别约定（如 Unity 标准 `_LOD0` / `_LOD1` / `_LOD2` 后缀），避免导入后逐个手工拖拽。

## 4. 渲染网格与碰撞体分离

- 🔴 **禁止直接拿高面数渲染网格作为实时 MeshCollider（尤其是动态物体与物理抓取物体）**，以免引发严重 CPU 物理开销和穿透卡顿。
- 🔴 物理交互优先使用引擎基础图元组合（Box / Sphere / Capsule）或极简凸包低模碰撞体（通常以独立前缀/后缀命名，如 `UCX_` / `_COL` 按项目约定），确保外观精度与物理性能解耦。
