# 10 - Go 代码风格规则

> - 🟢 本文件适用于 Go 代码的外观风格与团队约定（gofmt / goimports / golangci-lint / 命名约定 / EditorConfig / CI 集成）。
> - 🔴 不适用：业务逻辑实现、API 设计、数据库设计

---

## 1. 强制格式化：gofmt

🔴 **必加约束**：所有纳入改动的 Go 源码必须符合 `gofmt` 输出；优先使用仓库已有的格式化脚本或编辑器集成，不另起一套格式化约定。

### 1.1 基本用法

```bash
# 递归格式化当前模块（排除 vendor）
find . -path ./vendor -prune -o -name '*.go' -exec gofmt -w {} +

# 仅检查（CI 用）
find . -path ./vendor -prune -o -name '*.go' -exec gofmt -l {} +
```

### 1.2 关键规则（gofmt 自动处理）

| 规则 | 说明 |
|---|---|
| 缩进 | Tab（**不是空格**） |
| 行宽 | 无统一硬限制；以 `gofmt`、项目 lint 配置和可读性为准 |
| import 排序 | 按字母排序既有分组内的 import（不自动增删 import，也不区分第三方与本项目；分组与清理交由 `goimports` / `gci` 等工具） |
| 结构体字段对齐 | 自动对齐 |
| 函数签名 | 多参数自动对齐 |

**🔴 不要手动调整 gofmt 已经处理过的格式**——下一个人跑 `gofmt` 会改回去。

### 1.3 提交前必跑

```bash
# Git pre-commit hook（示例）
# .git/hooks/pre-commit
#!/bin/sh
unformatted=$(find . -path ./vendor -prune -o -name '*.go' -exec gofmt -l {} +)
[ -z "$unformatted" ] || { printf '%s\n' "$unformatted"; exit 1; }
```

## 2. 导入管理：goimports

🟡 **推荐**：在 `gofmt` 基础上使用 `goimports` 自动管理 import 顺序。

### 2.1 安装

```bash
go install golang.org/x/tools/cmd/goimports@<项目已验证版本>
```

### 2.2 用法

```bash
# 格式化（默认分为两组：标准库 / 非标准库）
find . -path ./vendor -prune -o -name '*.go' -exec goimports -w {} +

# 若仓库约定将本项目模块单独分成第三组，须显式传入 -local 参数
find . -path ./vendor -prune -o -name '*.go' -exec goimports -local <项目module路径> -w {} +

# 仅检查
find . -path ./vendor -prune -o -name '*.go' -exec goimports -l {} +
```

### 2.3 规则

- **默认两组**：**标准库**在前，其余外部与本项目 import 在后（与 `01-代码编写规则 § 1.4` 一致）
- **可选 `-local` 分组**：仓库配置了 `-local <module-prefix>`（或 `gci`）时，再将本项目包单独分组放在最后
- **分组之间用空行分隔**
- **未使用的 import 自动删除**

## 3. 静态检查：golangci-lint

🔴 **必加约束**：CI 必须执行与仓库相容的静态检查，并至少覆盖 `go vet` 与项目已有的错误/未使用代码检查。若项目已采用 [golangci-lint](https://golangci-lint.run/)，保持其版本与配置；新引入它需要先获授权。

### 3.1 安装

```bash
# 仅在项目决定采用 golangci-lint 时：固定工具版本，避免 CI 与本地漂移
go install github.com/golangci/golangci-lint/cmd/golangci-lint@<项目锁定版本>
```

### 3.2 最小配置文件

> 以下示例基于 `golangci-lint` v1 配置格式；使用 v2 时需显式声明 `version: "2"`，并将启用与配置项迁移至 `linters.default: none`、`linters.settings` 与 `formatters`。

```yaml
# .golangci.yml（golangci-lint v1 示例；v2 请按官方 v2 schema 迁移）
run:
  timeout: 5m
  go: '<项目支持的 Go 版本>'

linters:
  disable-all: true
  enable:
    - errcheck      # 未检查 error
    - govet         # 官方检查
    - ineffassign   # 无效赋值
    - staticcheck   # 静态分析
    - unused        # 未使用变量

linters-settings:
  govet:
    enable-all: true
```

### 3.3 推荐 Linters

| Linter | 用途 |
|---|---|
| `errcheck` | 检查 `error` 是否被忽略 |
| `govet` | Go 官方检查（默认包含 printf 等；`shadow` analyzer 不在 `go vet` 默认集合中） |
| `staticcheck` | 高级静态分析（在 `golangci-lint` v2 中已合并原 `gosimple` 规则集） |
| `gosimple` | 简化建议（`golangci-lint` v1 独立 linter；v2 起并入 `staticcheck`） |
| `unused` | 未使用的变量/函数/导入 |
| `gocritic` | 100+ 检查项（包括性能、风格） |
| `gocyclo` | 圈复杂度信号（阈值以项目配置为准） |
| `gofumpt` | 比 gofmt 更严格的格式化 |
| `nlreturn` | `return` 前必须有空行 |

## 4. 命名约定总览

🔴 **必加约束**：Go 命名遵循**简洁 + 一目了然**原则。以下规则与 01-代码编写规则 § 1 互补（01 讲硬约束，本章讲风格细节）。

### 4.1 包命名

- **全部小写**，不混用大写 / 下划线 / 中划线
- **简短精炼**——包名在每个调用点都完整写出
- 单数或复数由领域含义决定；`bytes`、`errors`、`strings` 等复数包名完全合理。
- 避免职责不清的泛义名；仓库已有且边界明确的 `common` / `util` 等包不因名称被机械重命名。

**正例**：`http`、`json`、`bytes`、`time`
**反例**：`url_utils`、`common`、`misc`

### 4.2 函数与变量命名

- **MixedCaps**：驼峰式（`camelCase` 或 `PascalCase`），**不用下划线**
- **导出用大写开头**：`GetUser`、`ParseConfig`
- **不导出用小写开头**：`getUser`、`parseConfig`
- **测试函数允许下划线分组**：`TestParse_EmptyInput`

**反例**：`get_user`、`parse_config`（Python 风格，不适用于 Go）

### 4.3 常量命名

| 类型 | 风格 | 示例 |
|---|---|---|
| 普通 const | MixedCaps | `const MaxRetryCount = 3` |
| 枚举 const | PascalCase + 类型前缀 | `const StatusOK Status = 1` |
| 包级错误变量 | `ErrXxx` | `var ErrNotFound = errors.New(...)` |
| 包级布尔 | `Is/Has/Can/Allow` 前缀 | `var IsEnabled = true` |

### 4.4 Receiver 命名

🟡 **推荐**：Method receiver 简短且能识别其类型，同一类型内所有方法保持一致，避免使用 `this` / `self` / `me`。

```go
// Good
type Client struct{ ... }
func (c *Client) Get() {}      // 常见简短命名
func (c *Client) Set() {}      // 同一类型保持一致

// Bad
func (this *Client) Get() {}   // 非 Go 惯用法
func (self *Client) Get() {}   // 非 Go 惯用法
```

保持简短、可读且同类型一致（不强制限定为单一首字母或固定 1-2 字符，避免同一类型混用 `c` 与 `cl`）。

### 4.5 接口命名

- **单方法接口**：用 `方法名 + er` 后缀
  ```go
  type Reader interface { Read(p []byte) (n int, err error) }
  type Writer interface { Write(p []byte) (n int, err error) }
  type Closer interface { Close() error }
  ```
- **多方法接口**：用描述行为的名称
  ```go
  type ReadWriter interface {
      Reader
      Writer
  }
  type FileSystem interface {
      ReadFile(path string) ([]byte, error)
      WriteFile(path string, data []byte) error
  }
  ```

## 5. 命名风格细节

### 5.1 缩写大写规则

🔴 **必加约束**：Go 常见缩写词（`URL`、`HTTP`、`ID`、`JSON` 等）保持统一大小写——导出或位于词中时**全大写**（如 `UserID`、`HTTPClient`），未导出且位于词首时**全小写**（如 `userID`、`httpClient`），不要写成混合大小写。

```go
// Good
type UserID int
func GetURL() string { ... }
type HTTPClient struct{ ... }
func ParseJSON() { ... }

// Bad
type UserId int       // 应该 UserID
func GetUrl() string  // 应该 GetURL
type HttpClient struct{}  // 应该 HTTPClient
func ParseJson() { ... }  // 应该 ParseJSON
```

### 5.2 避免 Stuttering

🔴 **必加约束**：包名**不重复**出现在类型名中。

```go
// Good
package http
type Client struct{}    // 用法：http.Client

// Bad
package http
type HTTPClient struct{}  // 用法：http.HTTPClient（重复）
```

### 5.3 接口使用方命名（非实现方）

🟡 **推荐**：接口名以**使用方**视角命名，而非实现方。

```go
// 包 "store"
package store

// 由调用方定义接口
type Reader interface { Read(...) }

// 实现方（别的包）
type FileStore struct{}
func (f *FileStore) Read(...) { ... }  // FileStore 隐式实现 store.Reader
```

## 6. 行宽与排版

Go 官方没有统一的 99 字符限制。长表达式应优先通过改善命名、拆分逻辑和减少嵌套提升可读性；不得为了固定行宽产生反常换行，也不得为执行本节擅自引入 `lll` 或 golangci-lint。

### 6.1 折行规则

```go
// Good：参数过多时按"主题"分组
func ProcessOrder(
    ctx context.Context,
    orderID string,
    user *User,
    options *Options,
) (*Result, error) {
    // ...
}

// Good：长字符串折行
log.Info("operation completed successfully",
    "user_id", userID,
    "duration_ms", elapsed.Milliseconds(),
)
```

### 6.2 函数调用风格

- **参数较少且保持可读**：可以放一行
  ```go
  result := Process(ctx, orderID, user, options)
  ```
- **参数较多、表达式复杂或项目 formatter 要求换行**：按语义分行
  ```go
  result := Process(
      ctx,
      orderID,
      user,
      options,
  )
  ```

## 7. 注释风格

> 注释语言与形式要求与 [01-代码编写规则 § 11](01-代码编写规则.md#11-注释与文档语言) 一致：说明正文统一使用中文，同时保留 `Package <包名>` 与符号名开头以满足 Go doc 约定。

### 7.1 包注释

🟡 **推荐**（与 [02-模式设计 § 8.9](02-模式设计.md#89-包级文档) 一致）：对外发布的包、需要生成文档的包以及承担重要边界的包应编写包注释；内部小包是否逐包补充由项目文档与 lint 门禁决定。

```go
// Package store 提供订单相关的持久化存储能力。
package store
```

### 7.2 导出符号注释

🟡 **推荐**（对外公开 API 或项目 lint 门禁要求时为 🔴 **必加**）：导出符号注释紧贴声明上方并以符号名开头，其后使用中文说明契约、错误语义和边界。

```go
// GetUser 根据给定 ID 查询用户；当用户不存在时返回 ErrNotFound。
func GetUser(id string) (*User, error) {
    // ...
}

// User 表示系统中的已注册用户。
type User struct {
    // Name 为用户的完整法定姓名。
    Name string
    // Age 为用户的年龄（单位：岁）。
    Age int
}
```

### 7.3 注释内容

- **说明 "why" 而非 "what"**（代码本身说明 what）
- **避免废话注释**（如 `// i 加 1`）
- **TODO/FIXME 注释**：说明具体欠债、触发条件或处理方向；Issue 编号、负责人和截止日期由项目流程决定，禁止没有上下文的 `TODO: later`，长期事项优先关联 Issue。

```go
// Good：说明 why
// 将超时设为 30s，因为上游服务在发布窗口期间偶发需要最多 25s 完成响应。
const requestTimeout = 30 * time.Second

// Bad：说明 what（代码已经说明了）
// 将 i 递增 1
i++
```

## 8. .editorconfig 团队配置

🟡 **推荐**：项目根目录加 `.editorconfig` 锁定基础编辑约定。

```ini
# .editorconfig
root = true

[*]
charset = utf-8
end_of_line = lf
indent_style = tab          # Go 用 Tab
indent_size = 4             # Go 默认 Tab = 4 空格宽
trim_trailing_whitespace = true
insert_final_newline = true

[*.{yml,yaml,json,toml}]
indent_style = space
indent_size = 2

[*.md]
trim_trailing_whitespace = false
```

**VS Code / GoLand 自动读取**——无需插件。

## 9. CI 中的风格检查集成

🔴 **必须**保留项目已经采用的格式化与静态检查。下例仅适用于使用 GitHub Actions 和 golangci-lint 的项目；所有 action、Go 和工具版本必须替换为项目已验证版本，不得覆盖现有工具链或版本锁定。

### 9.1 GitHub Actions 示例

```yaml
# .github/workflows/lint.yml
name: Lint
on: [push, pull_request]
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@<项目已验证版本>
      - uses: actions/setup-go@<项目已验证版本>
        with:
          go-version-file: go.mod
      - name: gofmt
        run: |
          unformatted=$(find . -path ./vendor -prune -o -name '*.go' -exec gofmt -l {} +)
          if [ -n "$unformatted" ]; then
            echo "gofmt failed:"
            printf '%s\n' "$unformatted"
            exit 1
          fi
      - name: go vet
        run: go vet ./...
      - name: golangci-lint
        uses: golangci/golangci-lint-action@<项目已验证版本>
        with:
          version: <项目锁定版本>
```

### 9.2 Makefile 集成

```makefile
# Makefile
.PHONY: lint
lint:
	@unformatted=$$(find . -path ./vendor -prune -o -name '*.go' -exec gofmt -l {} +); test -z "$$unformatted" || { printf '%s\n' "$$unformatted"; exit 1; }
	go vet ./...
	# 若本项目已采用 golangci-lint，再执行：golangci-lint run ./...

.PHONY: fix
fix:
	go fmt ./...
	# 若本项目已采用 goimports：find . -path ./vendor -prune -o -name '*.go' -exec goimports -w {} +
```

### 9.3 Pre-commit Hook

项目已采用 pre-commit 时，使用该工具官方支持的 hook 仓库或项目本地 hook。`golangci-lint-action` 是 GitHub Action，不能直接当作 pre-commit hook。新增钩子前确认工具版本和团队开发流程。

## 10. AI 写代码时的风格要点

AI 写完 Go 代码后，必须**主动验证**：

### 10.1 风格一致性

- [ ] **格式检查通过**——执行仓库已有格式命令；没有脚本时可用 `find . -name '*.go' -not -path './vendor/*' -exec gofmt -l {} +` 列出未格式化文件
- [ ] 项目已采用 goimports 时，按其配置整理 import
- [ ] 项目已采用 golangci-lint 时，运行仓库锁定版本和配置
- [ ] 编译/测试通过；未使用 import 或变量由编译器报告，`go vet` 负责其他静态检查

### 10.2 命名风格

- [ ] 包名小写、简短并表达职责；复数包名并非一律错误，标准库已有 `bytes`、`errors`、`strings` 等
- [ ] 函数 / 变量用 MixedCaps，**无下划线**（除测试函数）
- [ ] 缩写大写：`UserID`、`GetURL`、`HTTPClient`
- [ ] 常量用 `ErrXxx`（错误）/ `Is/Has/Can`（布尔）
- [ ] Receiver 简短且能识别其类型，同一类型内保持一致；不强制限定为首字母或固定长度

### 10.3 注释与文档

- [ ] 对外公开、需生成文档或受项目门禁约束的包具有中文包注释（`// Package xxx ...`）
- [ ] 对外公开或门禁要求的导出符号具有以符号名开头的中文注释（`// FuncName ...`）
- [ ] 注释以符号名开头且符合 `01 § 11` 的中文与并行维护要求
- [ ] 注释说明 "why" 而非 "what"

### 10.4 工具必跑命令

```bash
# 写完代码后按项目实际工具链运行
go fmt ./...            # 格式化
go vet ./...            # 静态检查
# 若仓库已有 goimports：find . -path ./vendor -prune -o -name '*.go' -exec goimports -w {} +
# 若仓库已有 golangci-lint：golangci-lint run ./...
```

## 11. 与 01-代码编写规则 的关系

| 章节 | 01（编码基础与硬约束） | 10（风格工具与排版细节） |
|---|---|---|
| 命名 | 包名小写/避免无职责泛词、MixedCaps、未导出顶层命名、避免内建名 | 缩写大小写 / Stuttering / Receiver / 接口命名细节 |
| 错误 | 错误类型 / `%w` vs `%v` / 命名 / 只处理一次 / 类型断言 | — |
| Goroutine | 禁止泄漏 / `init()` 不起 goroutine / 信道大小 | — |
| 零值 | `var mu sync.Mutex` / 字段名初始化 / `nil` 切片 | — |
| 控制流 | 减少嵌套 / 去除多余 `else` / 避免裸参数 / `Printf` 约束 | 折行与多参数调用排版 |
| 公共 API | 序列化字段标签 / 嵌入边界 / 切片与 map 边界拷贝 | — |
| 资源 | `defer` 清理 / 边界拷贝 | — |
| 入口退出 | `panic` / `os.Exit` / `init()` 约束 / `time` 处理 | — |
| **格式** | `import` 默认两组 | **`gofmt` / `goimports`（含 `-local`） / `golangci-lint` / `.editorconfig`** |
| **注释** | 中文注释 / `//` 形式 / 代码与注释并行维护（§ 11） | **包与导出符号 Go doc 风格 / why-not-what** |
| **CI** | — | **`gofmt` / `go vet` / lint 流水线集成** |

**一句话总结**：01 约束**正确性与工程编码基线**，10 约束**团队外观风格与自动化工具集成**。
