# 05 - TypeScript 声明文件

> - 🟢 本文件适用于 TypeScript 声明文件（.d.ts）的写法。
> - 🔴 不适用：业务逻辑实现、UI 样式设计

---

## 1. 🔴 硬约束 · 这些绝对不要写

### 1.1 .d.ts 里写运行时代码

```ts
// ❌ .d.ts 不应该有函数体
declare function greet(name: string): string {
  return `Hello, ${name}`;
}

// ✅ .d.ts 只放类型
declare function greet(name: string): string;
```

**类型声明错误立刻报错**（运行时错误才发现就晚了）。

### 1.2 全局类型污染

```ts
// ❌ 避免扩展内置原型（如 String.prototype）或在无 export 的脚本文件中隐式污染全局命名空间
interface String {
  padZero(): string;                                  // 污染全局内置类型，且与运行时原型修改耦合
}

// ✅ 仅为宿主环境实际注入的全局对象（如浏览器全局挂载或 Electron preload 桥接）补充类型
// src/types/preload.d.ts
declare global {
  interface Window {
    desktopBridge?: {
      getAppVersion(): Promise<string>;
    };
  }
}
export {};                                            // 标记为模块，防止顶层辅助类型泄漏到全局
```

### 1.3 没有类型的库直接 import

```ts
// ❌ 跳过类型检查
import { foo } from 'no-types-lib';

// 包确有匹配的官方/DefinitelyTyped 声明且项目授权新增时，
// 使用现有包管理器安装与库版本兼容的声明包。
import { foo } from 'no-types-lib';

// ✅ 库没类型时自己写最小 .d.ts
// src/types/no-types-lib.d.ts
declare module 'no-types-lib' {
  export function foo(x: string): number;
  export const bar: string;
}
```

**不要**用 `// @ts-ignore` 掩盖类型缺失——后面改代码会爆。

## 2. 🟡 推荐 · 团队约定

### 2.1 .d.ts 文件位置

| 类型 | 位置 |
|------|------|
| **TS 库产物**：编译输出目录 | 由 `tsc` / 构建器生成到 `dist/`（如 `dist/index.d.ts`），不要与 `src/*.ts` 同名并存 |
| **手写声明（应用或无类型 JS 依赖）**：统一放 `types/` | `src/types/global.d.ts` / `src/types/assets.d.ts` |

### 2.2 模块声明

```ts
declare module 'my-lib' {
  export interface User {
    id: number;
    name: string;
  }
  export function getUser(id: number): Promise<User>;
}
```

### 2.3 全局声明

```ts
// src/types/global.d.ts
export {};                                            // 标记为模块

declare global {
  interface Window {
    myApp?: { version: string };
    dataLayer?: unknown[];
  }

  namespace NodeJS {
    interface ProcessEnv {
      // 运行时环境变量可能未配置，声明为可选并在启动边界校验
      DATABASE_URL?: string;
      NODE_ENV?: 'development' | 'production' | 'test';
      PORT?: string;
    }
  }
}
```

### 2.4 ambient 模块（无 import 的全局模块）

```ts
// jQuery 老项目 / 第三方插件
declare const $: JQueryStatic;
declare const _: _.LoDashStatic;
```

**现代项目**不要用——用 `import` 引入模块。

### 2.5 第三方库类型来源

| 来源 | 优先级 |
|------|--------|
| **库自带类型**（d.ts 在 npm 包内） | ✅ 首选 |
| **`@types/xxx`**（DefinitelyTyped） | ✅ 次选 |
| **自己写 minimal .d.ts** | 🟡 兜底 |
| **无主体简写 `declare module 'xxx';`** | ❌ 禁止（所有导入退化为 `any`） |

### 2.6 CSS Modules / 图片 / JSON 模块声明

```ts
// src/types/assets.d.ts
declare module '*.module.css' {
  const classes: { readonly [key: string]: string };
  export default classes;
}

declare module '*.svg' {
  const src: string;
  export default src;
}

declare module '*.png' {
  const src: string;
  export default src;
}
```

### 2.7 模块扩展与声明合并

```ts
// ✅ 模块扩展（Module Augmentation）：为第三方框架的请求对象补充项目中间件注入的字段
// src/types/express.d.ts（仅在项目已使用 Express 时作为示例）
import 'express';

declare module 'express' {
  interface Request {
    requestId?: string;
  }
}
```

```ts
// ✅ 类与同名 namespace 合并（常见于声明外部库的嵌套类型）
declare class HttpClient {
  request(options: HttpClient.RequestOptions): Promise<Response>;
}
declare namespace HttpClient {
  interface RequestOptions {
    url: string;
    timeoutMs?: number;
  }
}
```

### 2.8 发布带类型的库

双格式（ESM + CJS）发布时，每个条件分支必须提供与模块格式匹配的独立 `.d.mts` / `.d.cts`（且 `"types"` 放在该分支最前），避免 `moduleResolution: "NodeNext"` 误判模块类型；若库仅发布纯 ESM（`"type": "module"`），只需保留单组 `"exports": { ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" } }`。

```jsonc
// package.json（双格式发布示例；实际 package.json 中不可保留注释）
{
  "main": "./dist/index.cjs",
  "types": "./dist/index.d.cts",                       // 兼容旧版解析器的回退入口
  "exports": {
    ".": {
      "import": {
        "types": "./dist/index.d.mts",
        "default": "./dist/index.mjs"
      },
      "require": {
        "types": "./dist/index.d.cts",
        "default": "./dist/index.cjs"
      }
    }
  },
  "files": ["dist"]
}
```

**自动生成 .d.ts**：

```jsonc
// package.json
{
  "scripts": {
    "build": "tsc -p tsconfig.build.json"
  }
}
```

```jsonc
// tsconfig.build.json
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "declaration": true,                               // 生成 .d.ts
    "declarationMap": true,                            // 生成 .d.ts.map 便于跳转源码
    "emitDeclarationOnly": false,
    "outDir": "dist"
  },
  "include": ["src"]
}
```

## 3. 🟢 可选 · 视情况

### 3.1 triple-slash directives

```ts
/// <reference path="../node_modules/@types/jest/index.d.ts" />
/// <reference types="node" />
```

**现代项目不用**——`tsconfig.json` 的 `types` 字段更干净。

### 3.2 类型补丁

项目已经采用 patch-package、包管理器 patch 能力或内部 fork 时，可以按既有流程临时修补上游类型；不得为本节自动安装 patch 工具。补丁必须锁定上游版本、说明原因和移除条件，并在升级依赖时重新验证。

### 3.3 .d.ts 文件导入类型

```ts
// types/foo.d.ts
export interface Foo { id: number }

// 在代码中
import type { Foo } from '@/types/foo';               // ✅ 用 import type
```
