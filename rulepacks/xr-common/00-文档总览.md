# 00 - XR 通用体验与硬件基准总览

> - 🟢 本规则库适用于 VR、透视 MR 与光学透视 AR 软件项目的跨岗位通用基准（产品、UI、三维美术、技术美术、引擎研发共享）。
> - 🔴 不适用：替代具体头显厂商 SDK 文档（如 PICO / OpenXR 专项规则）、引擎编码规则或目标项目的实测性能预算表。

---

## 1. 目标与边界

XR 项目同时受限于双目立体渲染、实时头部与手部追踪、人眼光学舒适度与移动设备功耗热节流。本规则包提供跨岗位共享的硬性底线与沟通口径，避免产品、UI、三维美术、TA 与研发各自按不同假设工作导致后期集中返工。

- 🔴 目标设备型号、系统版本、运行模式（一体机 / PCVR 串流 / MR 透视）和项目实测预算优先于通用参考范围。
- 🔴 任何跨岗位交付（需求、界面、模型、特效、代码）必须明确目标硬件档位，不得把桌面预览或高端 PCVR 效果直接等同于移动一体机可行方案。
- 🔴 帧率达标、空间舒适度和防眩晕红线具有一票否决权；画面复杂度必须服从实时稳定帧率。
- 🔴 设计稿、编辑器预览、模拟器与真机验证分别记录，未上目标真机验证的能力必须明确标记为待真机确认。
- 🟡 跨岗位预算变更时同步通知受影响的上下游岗位，避免单方超支挤占全局帧时或内存。

## 2. 跨岗位预算与责任分工

| 岗位 / 角色 | 在本基准下负责的核心底线 | 主要协作接口 |
|---|---|---|
| 产品经理 | 明确目标硬件档位、交互形态（VR/MR）、时长与眩晕风险场景、异常降级需求 | 输出设备目标与体验红线给 UI、三维、TA 与研发 |
| UI 设计师 | 保证空间视距、角字号、射线/手势热区、MR 透视可读性与防头部硬锁 | 输出空间尺寸单位、交互状态与降级态 |
| 三维设计师 | 控制单资产面数、LOD、UV 纹素密度、PBR 贴图体积与 AI 粗模精修质量 | 输出规范模型、LOD 链与资产入库指标 |
| 技术美术（TA） | 控制单通道立体渲染兼容性、粒子 Overdraw、DrawCall、Shader 变体与材质合批 | 输出渲染预算、导入校验与真机性能剖析 |
| Unity / XR 研发 | 保证目标刷新率帧时、零主线程卡顿、追踪丢失与热节流降级及真机打包验收 | 输出真机性能基线与问题定位证据 |

❌ 反例：产品按 PC 高清效果提需求、三维按高精度影视标准做模型、UI 在 2D 屏上定字号，直到发包前上移动一体机才发现帧率跌至 35fps 且眩晕严重。

✅ 正例：立项即锁定目标一体机档位与 72/90Hz 帧时预算，各岗位按拆分预算并行交付，在关键里程碑上真机联调核验。

## 4. 规则等级与维护

| 标识 | 含义 |
|---|---|
| 🔴 | 适用条件满足时必须执行 |
| 🟡 | 推荐，结合项目设备档位、目标与成本权衡 |
| 🟢 | 可选，仅在带来明确收益时采用 |

- 🔴 本包不写死特定品牌头显的绝对多边形数或贴图像素上限；具体数值以项目实测预算表和厂商当前官方文档为准。
- 🔴 通用规则不得绑定特定业务项目名称、私有 SDK 路径或未验证的第三方参数。
