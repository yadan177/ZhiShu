# 03 - 真机验证与跨岗位协同基线

> - 🟢 本文件适用于 XR 项目的分层验证口径、真机测试记录、跨岗位交接契约与发布前回归门禁。
> - 🔴 不适用：将静态检查、桌面渲染或模拟器运行结果冒充真机性能与舒适度验收结论。

---

## 1. 四级验证层级定义

所有跨岗位评审与交付报告必须明确标注当前所处的验证层级，严禁跨级宣称通过：

| 层级 | 名称 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| **L1** | 静态与资产检查 | 需求完整、设计尺度换算正确、模型面数/UV/命名/Shader 语法合规 | 运行帧率、双目深度效果、真实可读性 |
| **L2** | 桌面 / 编辑器预览 | 基础逻辑流程、动画状态、桌面画面布局与脚本无报错 | 移动一体机 GPU/带宽瓶颈、手势/手柄手感、立体眩晕风险 |
| **L3** | PC 串流 / 模拟器验证 | 基础交互流程、部分空间比例与键位映射 | 一体机独立算力、热降频稳态、原生 SDK 权限与离线包体加载 |
| **L4** | **目标真机实测** | 目标头显独立安装包的真实帧率、热稳态、可读性、舒适度、追踪与完整异常恢复 | 仅覆盖本次实测的机型、OS、SDK 与具体场景，不自动外推至未测机型 |

- 🔴 凡涉及**最终帧率达标、文字可读性、空间命中率、MR 透视融合度、防眩晕舒适度**的验收结论，必须具备 **L4 目标真机实测** 证据；仅做到 L1–L3 时必须明确标注“待真机验证”。

## 2. 真机测试记录必填字段

每次里程碑或发包前的真机性能与体验验证，至少记录以下事实字段，保证问题可复现、可对比：

- **硬件与系统**：设备型号、系统 OS 版本、电量与散热环境（是否连接充电或外接调试）。
- **构建与渲染**：引擎版本、XR SDK 路线与版本、渲染路径（Single-Pass Instanced / 管线设置）、构建配置（Release / Development，是否开启 Profiler）。
- **场景与时长**：测试场景名称、交互路径、连续运行时长（明确冷启动态 vs 热稳态）。
- **核心指标**：目标刷新率、平均帧率、P95/P99 帧时、掉帧尖峰次数、CPU/GPU 耗时、DrawCall/SetPass、三角面数、内存峰值。
- **体验结论**：可读性、命中精度、眩晕与疲劳反馈、追踪丢失/摘戴头显恢复结果，以及未覆盖范围。

## 3. 跨岗位交接与问题闭环契约

| 交接环节 | 上游交付物必须包含 | 下游验收核对重点 |
|---|---|---|
| **产品 → UI / 研发** | 目标设备档位、VR/MR 模式、交互方式、异常分支（追踪丢失/空间受限/断网）与可观测验收标准 | 核对是否有突破当前设备能力的隐含假设 |
| **UI → Unity / TA** | 空间视距、物理尺寸与角尺寸换算、组件状态矩阵、MR 明暗背景规范与资源实现方式 | 核对动静 Canvas 拆分、透明层开销与文字清晰度方案 |
| **三维 → TA / Unity** | 通过自检的模型/LOD/贴图/材质清单、AI 粗模修复记录、轴向与 1m 比例确认 | 核对导包配置、材质合批兼容性、Read/Write 开关与显存占用 |
| **TA → Unity** | Shader 立体渲染兼容证明、变体清单、特效 Overdraw 体检结果与导入校验脚本 | 核对打包变体裁剪、首帧卡顿预热与真机热稳态帧时 |

- 🔴 发现性能或舒适度超标时，必须先用真机性能剖析证据定位瓶颈归属（CPU 脚本 / 几何面数 / Overdraw / Shader 采样 / UI 重建 / 显存），禁止凭主观猜测要求某一岗位盲目降质。

## 4. 关键异常场景必测清单

发包前在目标真机上至少核验以下高频现实中断场景：

- [ ] **摘戴头显与休眠唤醒**：中途摘下头显静置再戴回，音频、追踪、网络会话与任务状态能正常暂停与恢复。
- [ ] **追踪丢失与安全边界触发**：遮挡摄像头或走近安全围栏时，画面安全暂停或给出清晰提示，不出现世界乱飞或死锁。
- [ ] **控制器切换 / 电量低 / 手势丢失**：手柄断开或裸手移出追踪视野时，操作安全中止且状态可恢复。
- [ ] **首次冷启动与重场景加载**：无长时间冻结画面、无 Shader 编译剧烈掉帧、无内存峰值闪退。
- [ ] **长时热稳态运行**：连续运行项目约定典型时长后，帧率、温度与交互响应仍保持在可接受阈值内。
