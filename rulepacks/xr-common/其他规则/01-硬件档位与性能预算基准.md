# 01 - 硬件档位与性能预算基准

> - 🟢 本文件适用于 XR 项目的目标硬件分级、刷新率帧时拆解、全局预算分配及功耗热节流风险评估。
> - 🔴 不适用：将某一型号头显的参考上限硬套为所有项目或未来设备的固定指标。

---

## 1. 目标硬件档位分级

不同 XR 设备的算力、内存带宽与散热边界差异巨大，立项与评估前必须先归类目标档位，以项目实际支持的最低档位作为性能兜底基线：

| 档位 | 典型设备特征 | 核心瓶颈 | 预算策略 |
|---|---|---|---|
| **Tier 1 · 移动 XR 一体机** | 移动 SoC、瓦片式渲染（TBDR）、电池供电与被动/紧凑散热 | 显存带宽、半透明 Overdraw、DrawCall、内存上限与热降频 | **最严格基线**：优先烘焙光照、单通道立体渲染、紧密裁切特效与严格 LOD |
| **Tier 2 · 桌面级 PCVR / 有线串流** | 独立桌面 GPU、较高显存带宽、额外编码/传输延迟 | 端到端串流延迟、高分辨率像素填充、CPU 物理与脚本峰值 | 允许更丰富的实时光照与高模档位，仍须严控帧时抖动与 GC 卡顿 |
| **Tier 3 · 高算力空间计算设备** | 高像素密度 Micro-OLED、多传感器融合、系统级窗口合成 | 光学清晰度门槛更高、系统多应用共享资源与内存配额 | 遵循平台系统合成规范，高精细资产仍须做分层加载与显存监控 |

- 🔴 跨档位发布项目必须以**最低目标档位**作为默认设计约束，高档位通过清晰的质量分级（Quality Tier / LOD / Shader LOD）增量增强，而不是先按高端做完再临时删减。
- 🔴 涉及厂商硬件具体规格（分辨率、刷新率档位、可用内存、注视点渲染能力）时，必须以项目实测或厂商最新官方文档为准，并注明核验来源。

## 2. 刷新率与帧时预算分解

稳定帧率是 XR 不眩晕的第一前提。任何单帧超过目标刷新率帧时都会触发异步时间扭曲/空间重投影（ATW / ASW），导致拖影、撕裂感与晕动症：

| 目标刷新率 | 单帧总时间上限 | 安全工作预算（留 15%–20% 余量防热降频与峰值） | 适用口径 |
|---|---|---|---|
| **72Hz** | `13.89 ms` | 约 `11.0 – 11.8 ms` | 移动一体机基础档位常见底线 |
| **90Hz** | `11.11 ms` | 约 `8.8 – 9.5 ms` | 主流 XR 体验推荐档位 |
| **120Hz** | `8.33 ms` | 约 `6.6 – 7.0 ms` | 高速交互或竞技类场景 |

- 🔴 性能评估不能只看“平均 FPS”，必须同时看 **P95 / P99 帧时** 与 **单帧尖峰（Spike）**；偶发 GC、Shader 首帧编译、大贴图同步解码导致的 30ms 卡顿会直接破坏沉浸感。
- 🔴 移动一体机必须以**连续运行 15–30 分钟后的热稳态（Thermal Steady State）**为准，冷启动前 2 分钟的满频帧率不能当作发布达标依据。
- 🟡 建议在项目预算表中将单帧预算拆分为 CPU（主线程逻辑/物理/动画/渲染提交）与 GPU（不透明几何/透明与特效/UI/后处理与合成）两条并行线，分别设预警线与红线。

## 3. 跨岗位全局预算拆解口径

项目应在立项或里程碑前建立《项目性能预算表》，将总预算拆分到各产线，避免“谁先塞满谁占便宜”：

| 预算维度 | 主要责任岗位 | 必须明确的项目约定项 |
|---|---|---|
| 同屏可见面数 / 顶点数与 LOD | 三维设计师 + TA | 视锥内有效三角面预算、单角色/单英雄道具/场景块面数分级 |
| 贴图显存与包体体积 | 三维设计师 + Unity | 贴图分辨率分级、压缩格式（如 ASTC/BC）、Mipmap 与流式加载策略 |
| DrawCall / SetPass 与批处理 | TA + Unity | 单通道立体渲染、SRP Batcher 兼容率、静态/GPU Instancing 策略 |
| 半透明 Overdraw 与特效 | TA | 最大同屏粒子发射数、单特效屏幕面积占比、禁止无裁切全屏叠层 |
| 空间 UI 渲染与更新开销 | UI 设计师 + Unity | Canvas 动静拆分、透明/模糊层数上限、高频刷新控件隔离 |
| CPU 脚本、物理与 GC | Unity 研发 | 每帧 0 字节热路径托管堆分配目标、固定物理步长、异步加载与对象池 |

❌ 反例：未做跨岗位预算拆分，三维团队把 80% 显存用完后，UI 和特效加载直接触发一体机 OOM 闪退。

✅ 正例：立项在项目预算表中为场景、角色、特效、UI、音频与系统保留明确的内存与帧时配额，超配额资产在入库或合入前拦截并协商调整。

## 4. 功耗、散热与内存安全

- 🔴 严禁在热路径（每帧 `Update`、粒子回调、射线检测循环）产生持续托管内存分配导致周期性 GC 掉帧。
- 🔴 场景切换、大模型加载与音视频解码必须采用异步加载与分帧实例化，并提供明确过渡态，防止头显画面长时间卡死触发系统黑屏或追踪警告。
- 🟡 针对移动一体机长时运行场景，规划可观测的动态降级手段（如动态分辨率缩放、注视点渲染等级、次要特效密度下调），并验证降级后文字清晰度不跌破可读底线。
