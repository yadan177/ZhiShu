# 04 - 音频与 XR 空间音效规范

> - 🟢 本文件适用于 VR、MR、AR 及 Unity 3D 项目的音频资产制作、响度基准、导入压缩配置、3D 空间音效（Spatial Audio）、配音字幕与真机听感验收。
> - 🔴 不适用：替代特定空间音频中间件或厂商 SDK（如 Wwise / FMOD / Meta XR Audio / Steam Audio / Resonance Audio）的底层 API 文档，或强行限定具体音效美学风格。

---

## 1. 音频资产规格与响度安全红线

### 1.1 响度统一与防“炸耳”保护

XR 头显的近耳开放式扬声器与贴耳耳机距离人耳极近，突发爆音或音量剧烈跳变会直接引发听觉惊吓与佩戴不适：

- 🔴 **峰值限幅与防削波红线**：所有入库音频必须经过响度规范化与真峰值限幅处理（参考上限 `True Peak ≤ -1.0 dBTP`），**严禁将存在 `0 dBFS` 削波失真（Clipping）或未统一响度的原始录音/下载素材直接导入工程**。
- 🟡 **分级响度参考口径**（若项目已由音频团队设定独立混音台标准，以项目实测标准为准）：
  - 整体混合输出综合响度参考 `-16 LUFS` 至 `-14 LUFS`（消费级移动 XR 头显常见舒适区间）。
  - 旁白与角色语音（VO）保持清晰居前；当语音触发时，背景音乐（BGM）与环境底噪应通过混音总线自动压低（Ducking，参考 `-6 dB` 至 `-12 dB`），避免人声被背景声掩盖。
  - 频繁触发的 UI 悬停/点击音效保持轻盈短促，克制 `2–5 kHz` 人耳敏感频段的尖锐能量。

### 1.2 源文件格式、采样率与声道规范

| 资产类别 | 工程入库源格式 | 声道要求 | 采样率与剪辑要求 |
|---|---|---|---|
| **3D 空间点声源（SFX / 角色语音）** | 无损 PCM `.wav`（16-bit / 24-bit） | 🔴 **必须单声道（Mono）** | 全项目统一采样率（推荐 `48 kHz` 或 `44.1 kHz`）；开头无冗余静音避免触发延迟 |
| **2D UI 交互反馈音** | 无损 PCM `.wav` | Mono 或 Stereo（单音优先 Mono 省内存） | 首尾紧贴波形，时长精简（常 `< 0.5s`） |
| **全局 BGM / 环境氛围音（Ambience）** | 无损 PCM `.wav`（多声道/Ambisonics 按管线配置） | Stereo（或四阶/一阶 Ambisonics 空间声场） | 🔴 循环素材必须做**无缝过零点（Zero-Crossing）**处理，禁止循环接缝出现“咔哒”爆音 |
| **全局旁白 / 对话（VO）** | 无损 PCM `.wav` | Mono | 去底噪、齿音控制，按语种/句子分文件便于本地化与字幕同步 |

- 🔴 **3D 空间声源严禁使用立体声（Stereo）直接空间化**：HRTF / 3D 空间化算法基于单声道点声源计算双耳时间差与电平差；立体声素材直接做 3D 定位会导致声像塌陷、方位模糊，同时白白翻倍内存与包体开销（需在制作阶段输出 Mono，或在引擎导入设置勾选 `Force To Mono`）。
- 🔴 **源工程统一用无损母带入库、压缩交由引擎/中间件**：禁止将已有损压缩的 `.mp3` 反复编辑再导出二次压缩，避免音质劣化与 MP3 编码帧头部静音破坏无缝循环。

## 2. 引擎导入设置与内存性能预算

### 2.1 按音频时长分类配置加载模式与压缩格式

以下以 Unity 原生 `AudioClip` 导入器为基准（若项目采用 Wwise / FMOD 等专业中间件，按其等价的 Memory / Stream 与平台压缩策略执行）：

| 音频类型 | 典型时长 | 推荐 `Load Type` | 推荐 `Compression Format` | 工程依据 |
|---|---|---|---|---|
| 短促高频 SFX / UI 音 | `< 1–2 秒` | `Decompress On Load` | `ADPCM` 或 `PCM` | 避免播放瞬间实时解码造成音频/主线程毛刺；`ADPCM` 体积约为 `PCM` 的 1/3 且解压极快 |
| 中等 SFX / 短语音 | `2–10 秒` | `Compressed In Memory` | `Vorbis`（质量按真机听感标定，如 `50%–70%`） | 在内存占用与实时 CPU 解码间取得平衡 |
| 长 BGM / 长旁白 / 环境声 | `> 10 秒` | `Streaming` | `Vorbis` | 从存储流式边读边播，避免数十 MB 解压常驻内存撑爆移动一体机 |

- 🔴 **严禁对长音乐或长语音使用 `Decompress On Load + PCM`**：一段 3 分钟的立体声未压缩音频常驻内存可达 30 MB 以上，会严重侵占移动 XR 一体机内存预算并拉长场景加载停顿。
- 🟡 **按需配置 `Preload Audio Data` 与 `Load In Background`**：非首屏/当前场景立刻使用的音频避免勾选启动预加载；XR 切场景或动态加载大音频时优先异步加载，禁止阻塞主渲染线程导致画面掉帧。

### 2.2 并发声道（Voices）与 `AudioSource` 治理

- 🔴 **限制并发发声上限与同音冷却**：移动 XR 一体机 CPU 预算紧张，必须在项目音频设置与业务逻辑中控制最大并发发声数（Real / Virtual Voices），并对碰撞、粒子或高频交互音效加入**最小触发间隔（Cooldown）与同类别并发上限**，防止同一帧叠加触发几十个相同音效导致削波破音与帧时飙升。
- 🔴 **复用对象池与清晰优先级**：动态 3D 音效必须通过对象池复用 `AudioSource`（避免频繁 `Instantiate` / `Destroy` 引发 GC 卡顿），并按业务重要性配置 `Priority`（系统警示与语音 VO > 核心交互 SFX > 远景环境声），防止核心旁白被远景杂音抢占静音。

## 3. XR 空间音效（Spatial Audio）与听觉舒适度设计

### 3.1 2D 音频与 3D 空间音频边界

| 音频模式 | 适用场景 | 核心约束 |
|---|---|---|
| **3D 空间音频**（`Spatial Blend = 1.0` + 空间化启用） | 场景内物体动作、NPC/角色说话、空间机械运转、近场交互控件反馈、视野外事件引导 | 声源坐标必须与真实发声物体或控件对齐，随头部 6DoF 转动与位移实时更新方位与距离 |
| **2D 非空间音频**（`Spatial Blend = 0.0`） | 全局背景音乐（BGM）、非空间绑定的系统级提示、画外音旁白 | 不参与头部空间旋转；音量克制，不与 3D 空间线索争夺注意力 |

- 🔴 **严禁声画空间错位**：视觉发声体在用户右侧而声音从正中 2D 播放，或 3D 场景音效错误挂载在头部/主摄像机上随头僵硬跟随，都会破坏空间定位感并诱发认知违和。
- 🟡 **用空间音效辅助视野外引导**：在 XR 中遇到需要引导用户转身查看的场景，优先采用“空间方位提示音 + 边缘视觉指引”，避免强行接管头部旋转（与 [02 - 空间舒适度与防眩晕红线](./02-空间舒适度与防眩晕红线.md) 协同）。

### 3.2 距离衰减、遮挡与 MR 透视兼容

- 🟡 **按真实米制尺度标定衰减曲线**：使用对数衰减（Logarithmic Rolloff）或自定义平滑曲线，`Min Distance` 与 `Max Distance` 必须匹配真实空间尺寸（例如桌面级近场交互约 `0.3–3 m`，展厅级导览约 `1–12 m`），避免在空间另一端仍听起来贴在耳边，也避免刚跨出一步就突兀静音。
- 🔴 **移动 XR 慎用重度实时声学反射**：实时射线声学追踪/复杂全场景卷积混响 CPU 开销极高；移动一体机优先采用分区 Reverb Zone 或轻量早期反射，开启高级空间声学特性前必须完成真机 CPU 剖析（见 [01 - 硬件档位与性能预算基准](./01-硬件档位与性能预算基准.md)）。
- 🔴 **MR 透视模式保持环境声觉安全**：透视混合现实中用户处于真实物理空间，虚拟背景音与环境声必须克制留白，严禁持续高密度轰鸣完全遮蔽现实世界的呼唤或安全警示声。

## 4. 混音总线、对数音量与头显生命周期响应

- 🟡 **统一混音总线分组**：无论使用引擎 `AudioMixer` 还是音频中间件，至少划分 `Master`、`VO`（语音）、`SFX`（音效）、`UI`（界面）、`BGM`（音乐）、`Ambience`（环境）总线，所有 `AudioSource` 禁止绕过总线直出，确保全局音量滑块、语音 Ducking 与静音策略统一生效。
- 🔴 **音量滑块必须采用对数分贝（dB）映射**：线性滑块值 `v ∈ [0, 1]` 映射至混音器分贝值时，必须使用对数换算（如 `v <= 0.0001 ? -80 : 20 * log10(v)`）；严禁将 `0..1` 线性映射到 `-80..0 dB` 导致滑块拉到一半就几乎听不见。
- 🔴 **头显摘戴与失焦静音底线**：当用户摘下头显（佩戴传感器触发休眠）、切出系统菜单、锁屏或应用退入后台时，必须立即暂停或静音应用音频，重新戴上/恢复焦点时采用短淡入（如 `100–300 ms`）恢复播放，严禁摘下头显后声音持续外放或恢复瞬间产生爆音。

## 5. 配音（VO）、字幕与多语言协同

- 🔴 **关键语音信息必须配备字幕或视觉替代**：涉及核心操作教学、剧情关键节点、任务指令与安全警示的语音，必须提供可开关的空间字幕或明确视觉提示，保障嘈杂展厅现场、静音使用及听障用户的完整体验。
- 🟡 **语音资产与脚本解耦**：代码通过稳定逻辑键/本地化表引用音频资源，禁止在业务脚本里硬编码具体语种路径或中文文件名；多语言切换时由音频/本地化管理层统一映射对应语种语音包。

## 6. 资产命名与真机听感验收

### 6.1 推荐命名约定

项目无既有音频命名约定时，采用全小写 ASCII + 下划线格式：

```text
<类别前缀>_<模块或对象>_<动作或状态>_<变体编号或语种>.wav
```

| ❌ 反例 | 问题说明 | ✅ 正例 |
|---|---|---|
| `按钮音效最终版2.mp3` | 含中文、版本号乱拼且采用有损 MP3 入库 | `ui_btn_click_01.wav` |
| `explosion_stereo_3d.wav`（未转 Mono） | 3D 点声源使用立体声且未做响度限幅 | `sfx_barrel_explode_01.wav`（Mono） |
| `BGM_Lobby.wav`（`Decompress On Load` + `PCM`） | 长背景音乐解压常驻内存，挤爆一体机 RAM | `bgm_lobby_loop.wav`（`Streaming` + `Vorbis`） |
| 仅在 PC 桌面音箱试听后宣布音频验收通过 | 桌面音箱与头显近耳扬声器频响和空间感差异巨大 | 在目标 XR 头显真机上戴机走位转头实测通过 |

### 6.2 真机听感验收要求

- 🔴 **必须上目标头显真机试听验收**：PC 监听耳机、外放音箱与 XR 头显开放式近耳扬声器的低频响应、左右分离度、空间衰减和漏音表现差异显著；未经目标真机佩戴试听（含 360° 转头定位、走动衰减、多音叠加压力与摘戴暂停恢复）的音频，不得宣称体验达标（验证层级记录见 [03 - 真机验证与跨岗位协同基线](./03-真机验证与跨岗位协同基线.md)）。

## 7. 音频交付与验收自检清单

音频资产入库或版本提测前逐项核对：

- [ ] 所有入库源音频是否为统一采样率的无损 `.wav`，且通过响度规范化与防削波限幅（无爆音、无循环接缝咔哒声）
- [ ] 所有 3D 空间点声源是否已确保为单声道（Mono / `Force To Mono`），声源坐标与发声体一致
- [ ] 导入设置是否按时长分类（短音 `Decompress On Load`，长 BGM/长语音 `Streaming` + `Vorbis`），无长音频 `PCM` 常驻内存
- [ ] 是否已配置全局并发发声上限、高频触发冷却、`AudioSource` 对象池及优先级
- [ ] 所有 `AudioSource` 是否已接入统一混音总线，音量调节使用对数 dB 映射，且语音播放时正确压低 BGM
- [ ] 关键语音是否有可开关字幕/视觉替代，且头显摘下/退后台时自动静音并平滑恢复
- [ ] 是否已完成目标 XR 头显真机佩戴听感验收（含转头定位、距离衰减与高频叠加无破音）
