# 15 - XR 通用基准 AI 通用入口规则

> - 🟢 本文件适用于 AI 参与的各类 XR 项目跨岗位分析、设计、资产审查、性能优化与验收协作。
> - 🔴 不适用：替代具体 SDK 文档、猜测未验证的设备硬件参数，或绕过真机验证宣称体验达标。

---

## 1. 开始前核对

开始任何涉及 XR 的需求、设计、美术、TA 或研发任务前，先读取[总览](./00-文档总览.md)与项目本地覆盖规则，确认以下项目事实：

1. **目标设备与运行形态**：独立一体机（如移动芯片 XR 设备）、PCVR 串流，还是混合跨端；VR 全沉浸还是 MR 透视。
2. **目标刷新率与帧时口径**：项目锁定的刷新率（如 72Hz / 90Hz / 120Hz）与对应单帧时间上限。
3. **输入与姿态假设**：手柄 6DoF 射线、裸手追踪（近距直触 / 远距捏合）、眼动还是多模切换；坐姿、站姿还是大空间行走。
4. **已有预算与真机基线**：项目已确认的渲染管线、性能预算表及最近一次真机测试记录。

- 🔴 找不到目标设备或刷新率事实时，先查项目配置与文档；仍缺失时明确标注假设条件并提示确认，不得默认按高端 PC 规格设计。
- 🔴 区分行业通用经验、厂商官方规范与本项目实测数据，不得把经验参考值写成所有设备的硬性上限。
- 🟡 仅涉及纯 2D 后台管理页或离线工具脚本的任务，无需强制套用 XR 空间体验红线。

## 3. 跨岗位硬约束

- 🔴 不得在设计或研发方案中默认使用强制接管用户头部视角、未经缓冲的镜头抖动或持续低帧率重投影。
- 🔴 面向移动 XR 一体机的方案必须评估双目渲染、带宽、发热降频与半透明填充率成本，不能只看单帧静态截图。
- 🔴 任何声称“满足 XR 性能/清晰度/舒适度要求”的结论，必须指明验证层级（理论估算 / 编辑器预览 / 真机实测）。
- 🔴 当上游需求或视觉效果突破当前设备预算时，主动提出降级替代方案与取舍依据，而非静默放宽帧率底线。

❌ 反例：在需求评审时承诺“所有 MR 场景叠加实时景深模糊与动态多点阴影”，未标明移动一体机 GPU 成本与降级方案。

✅ 正例：说明实时多点阴影与全屏模糊在移动一体机上的渲染开销风险，给出烘焙光照 + 轻量聚焦提示的替代方案，并约定真机实测门禁。

## 4. 交付与报告

涉及 XR 跨岗位产物的输出或审查报告应简要写明：

1. 本次所依据的目标硬件档位、显示模式与输入方式（标明来源或假设）。
2. 是否触及帧率、内存、热节流或防眩晕红线及具体规避措施。
3. 受影响的上下游岗位（产品 / UI / 三维 / TA / Unity）及需同步项。
4. 已完成的验证层级与仍需真机实测确认的缺口清单。
