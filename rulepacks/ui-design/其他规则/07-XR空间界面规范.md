# 07 - XR 空间界面专项规范

> - 🟢 本文件适用于 VR 全沉浸、MR 彩色透视与光学透视 AR 的空间界面光学显示、尺度换算、基础锚定、空间输入交互、透视可读性与渲染交付。
> - 🔴 不适用：纯平面 Web / 桌面 / 移动界面（常规 2D 任务见 [02-交互设计规则](./02-交互设计规则.md) 与 [03-视觉设计规则](./03-视觉设计规则.md)）；多窗口空间布局拓扑、动态生成生命周期、UI 与 3D/MR 共存防穿模、Z 轴景深层级及跨设备（Vision Pro / Meta / PICO）差异适配见 [08-XR空间布局与摆放架构规范](./08-XR空间布局与摆放架构规范.md)。

## 1. 显示模式与光学环境区分

空间界面设计前必须先确认目标项目的显示模式，不同光学环境对底板、不透明度、文字与留白的要求完全不同：

| 显示模式 | 背景特性 | 核心视觉约束 |
|---|---|---|
| **VR 全沉浸** | 背景完全由虚拟场景控制，明暗可预期 | 兼顾与 3D 场景的层次分离，避免纯白强光大面积刺眼导致视觉疲劳 |
| **MR 彩色透视（Passthrough）** | 现实房间明暗、杂物与反光不可控，且透视画质通常低于原生渲染 | **底板必须自带足够不透明度与边界对比**，禁止在复杂现实背景上直接裸放细浅色文字 |
| **光学透视 AR** | 叠加发光原理，纯黑呈现透明，高亮环境易发白 | 避免依赖纯黑遮挡背景，核心信息优先高对比高亮图形并核对强光环境可读性 |

- 🔴 同一份空间 UI 需同时兼容 VR 与 MR 时，必须分别在暗场、亮窗与杂乱桌面三类真实背景下验证对比度与边界清晰度，不得只看深色渲染预览图。
- 🔴 若项目同时安装 `xr-common` 规则包，空间帧率、防眩晕和真机验证底线必须与 `xr-common` 保持一致。

## 2. 空间尺度、视距与角尺寸换算

空间界面中，人眼感知大小取决于**物理尺寸 ÷ 观看距离（角尺寸 / 视角）**，而非平面画布上的固定像素值：

- 🔴 **四类参数分别记录，严禁直接互换**：设计稿像素（px）、引擎面板物理尺寸（米 / 毫米）、默认观看距离（米）、实际角尺寸（视角角度或 dmm，即每米距离上的毫米数）。
- 🔴 **清晰换算比例**：在交付说明中写明本项目采用的 Canvas 映射比例（例如 `Canvas Scale / 像素每米 PPU` 或物理面板宽×高），保证同一设计稿在不同视距下不会意外过大或模糊。

| 典型视距层级 | 常见放置距离 | 适用界面类型 | 尺度与排版要点 |
|---|---|---|---|
| **近距直触层** | 约 `0.25 – 0.46m`（舒适屈臂内；手部交互按目标设备校准，**避开 `0.50 – 0.80m` 交互歧义带**） | 手腕菜单、桌面工具条、可伸手直接按压的开关 | 按钮实体感与按压深度反馈明确，面板不宜过宽以防频繁大幅转头 |
| **中距主操作层** | 约 `1.0 – 2.0m`（大看板可至 `2.5m`） | 主业务面板、弹窗、列表、设置页与核心交互区 | **最常用舒适视距**；主阅读区尽量避免长段密集小字，增加行距与卡片间距 |
| **远距环境层** | 锚点建议 `≤ 3.0m`；环境导视 `> 3.0m` | 空间导视牌、场景标题、状态大屏、多人协作共享看板 | 仅展示低信息密度摘要与强视觉状态，不放细碎表单或密集小按钮 |

- 🔴 禁止将移动端或桌面端 12px/14px 的 2D 字号无换算直接照搬到头显空间面板；具体最小可读角字号必须结合目标头显 PPD（每度像素数）并在目标真机实测确认。
- 🟡 当面板支持用户拖拽拉近或推远时，明确是否采用“随距离等角缩放”还是“保持真实物理大小”，避免拖近糊脸或推远看不清。

## 3. 视野分布、锚定策略与人体工学

- 🔴 **核心内容位于自然舒适视野**：主界面默认出现在用户自然平视及微俯视方向（水平约 ±30° 内），避免强迫用户仰头、低头或大幅扭转颈部阅读。
- 🔴 **严禁默认使用“头锁（Head-Locked）”面板**：将面板刚性绑定在头部中心随每帧抖动极易引发眩晕与眼疲劳；仅在极少数系统级安全警示或用户显式开启的特殊辅助模式下谨慎评估。
- 🔴 **明确面板锚定模式**：

| 锚定方式 | 行为特征 | 适用场景 | 避坑红线 |
|---|---|---|---|
| **世界锚定（World-Locked）** | 固定在真实或虚拟空间某一点（如墙面/桌面） | 固定工作台、长期参考看板、空间标牌 | 用户移动较远后需提供一键召回或重置位置 |
| **惰性跟随（Body / Lazy Follow）** | 当用户转头或位移超过阈值角度/距离后，平滑缓动回到舒适区 | 主菜单、通用对话框、跟随式助手面板 | 必须设死区阈值与柔和阻尼，避免高频微抖与挡路 |
| **手部 / 控制器跟随** | 绑定在非惯用手掌或手柄侧边，抬手出现、放下隐藏 | 快捷工具盘、属性切换、状态微标 | 只放 3–6 个高频短操作，严禁塞入长滚动列表 |

- 🟡 面板默认居中面向用户（Billboard 仅绕 Y 轴朝向或轻度倾角），避免完全固定角度导致侧看透视畸变难以辨认。

## 4. 空间输入、命中热区与防误触

XR 空间中存在射线抖动、手部追踪精度波动与深度判断误差，交互容错必须高于鼠标点击：

- 🔴 **可见尺寸与实际命中区（Collider / Hit Target）分别定义**：视觉保持精致克制的同时，按钮、关闭图标、下拉项与滑块必须提供足够宽裕的命中热区与安全间距，防止射线微抖造成误点相邻项。
- 🔴 **区分近距直触与远距射线交互模型**：
  - **远距射线（手柄 / 远距捏合）**：必须具备清晰的悬停预高亮（Hover）、射线落点光标、捏合/扣动确认态与防抖阈值（按下瞬间微小手抖不得取消点击或误触发拖拽）；
  - **近距直触（手部戳点）**：必须提供明确的深度接近反馈（靠近渐变/光圈缩放）、触碰压缩行程与弹回防连击冷却，避免无物理阻力导致反复穿透误触。
- 🔴 **检查与系统保留手势/按键的冲突**：不得将头显系统的主菜单手势、掌心捏合系统唤起或退出键占作业务高频交互，并按目标平台规范核对。
- 🔴 **避免长时抬臂（Gorilla Arm）与复杂空间文字输入**：
  - 长列表滚动、批量选择优先支持摇杆/滚轮/轻拂惯性，减少持续举手拖拽；
  - 尽量减少头显内大段文本输入，优先使用快捷选项、自定义下拉、语音或跨端同步配置；确需输入时明确调用系统虚拟键盘及其弹出遮挡位置。

❌ 反例：把桌面端紧凑的 16×16 关闭图标和 4px 间距工具栏原样放进 2 米外空间面板，用户用射线瞄准时频繁误关弹窗。

✅ 正例：保持视觉简洁的同时加大热区与安全间距，提供明显悬停光晕与落点反馈，关键破坏性操作保留明确二次确认。

## 5. 空间材质、层级与渲染性能协同

空间 UI 同时影响视觉清晰度与移动一体机 GPU 帧时，设计阶段必须与 TA / Unity 研发对齐以下边界：

- 🔴 **严控多层半透明叠加与全屏实时模糊**：在移动 XR 一体机上，多层半透明叠底、实时背景高斯模糊（Glassmorphism Blur）会急剧抬高 Overdraw 与带宽消耗；设计采用半透明毛玻璃感时，必须同时给出可落地的低开销方案（如高不透明度纯色/微渐变底板 + 1px 精致高光描边）并经真机验证。
- 🔴 **规避双目深度冲突与 Z-Fighting**：重叠面板、弹窗、下拉菜单与卡片阴影之间必须定义清晰的物理前后深度偏移（Z Offset），严禁将多层 UI 贴在完全同一 Z 平面上造成双目闪烁。
- 🔴 **文字与细线清晰度保护**：
  - 避免 1px 以下过细斜线或高频细网格在头显透镜下产生严重闪烁摩尔纹（Aliasing / Shimmering）；
  - 优先采用适合空间缩放的文字渲染方案（如 SDF 字体或平台原生清晰文字层），禁止用低分辨率整张切图承载动态文本。
- 🟡 弹窗或抽屉打开时，通过轻度后退/降亮背景面板建立空间景深层次，替代覆盖整个视场的厚重全黑遮罩。

## 6. XR 空间界面完成检查

- [ ] 已明确 VR / MR / AR 显示模式，MR 场景已核对亮暗与杂乱背景下的可读性。
- [ ] 已分别记录设计像素、物理尺寸、默认视距与角尺寸换算依据，未直接照搬 2D 像素。
- [ ] 主信息区位于舒适视野内，锚定策略明确，无强制头锁与高频微抖。
- [ ] 远距射线与近距直触的悬停、深度反馈、命中热区与防抖策略已定义，无系统手势冲突。
- [ ] 半透明层数、物理 Z 偏移与文字清晰度已与 TA / 研发对齐，并区分预览与真机验证状态。
