# 08 - XR 空间布局与摆放架构规范

> - 🟢 本文件适用于 VR 全沉浸、MR 彩色透视与光学透视 AR 产品的空间界面布局规划、多窗口摆放拓扑、动态弹出与跟随生命周期、UI 与 3D/现实空间共存规则，以及跨头显设备（Vision Pro / Meta Quest / PICO）的适配决策。
> - 🔴 不适用：纯 2D 桌面/Web/移动端平面布局（见 [02-交互设计规则](./02-交互设计规则.md) 与 [03-视觉设计规则](./03-视觉设计规则.md)）；单块面板的光学显示模式、基础角字号与渲染材质细节见 [07-XR空间界面规范](./07-XR空间界面规范.md)。

## 1. 分层治理原则：通用空间底座与设备差异分离

空间 UI 摆放规律中，约 **80% 由人体颈部活动范围、双目视觉生理与三维空间几何决定**，在所有 XR 设备上成立；约 **20% 因目标头显的输入范式、光学清晰度（PPD）、原生窗口系统与算力预算而异**。

- 🔴 **核心规范跨设备统一，禁止按品牌复制整套重复规则**：布局拓扑、视距分层、Yaw-only 初始生成、防穿模与景深层级作为通用底线维护，不拆分为 Vision Pro / Meta / PICO 三份割裂规范。
- 🔴 **设备差异通过对照矩阵 + 项目声明落地**：具体业务项目必须在 `.agent-rules/overrides.md` 中声明目标设备型号、显示模式（VR/MR/AR）、主辅输入方式与最低算力档位，AI 与跨岗位成员按“通用规则 + 对应设备差异列”组合执行。
- 🟡 当单一项目同时面向多款头显（如同时发 PICO 4 Ultra 与 Meta Quest 3，或兼顾 visionOS）时，以**输入容错要求最高、光学 PPD 与算力预算最低的目标设备**作为默认布局基线，再为高档位设备做增量体验增强。

## 2. 空间布局拓扑与多窗口架构

在三维空间中，超过人眼自然平视范围的整块大平面会造成边缘距离拉远、文字透视畸变和频繁大幅转头。

### 2.1 单面板边界与弧形 / 折角多窗拆分

| 布局形态 | 适用信息体量与水平视角 | 空间几何与摆放要求 | 避坑红线 |
|---|---|---|---|
| **单主平面窗口** | 水平视角 `≤ 35°–40°`（约中距 `1.5–2.0m` 下宽 `0.9–1.3m`） | 居中放置于用户自然平视偏下（俯角约 `5°–15°`），面向用户 | 禁止将所有二级导航、工具栏和长属性面板硬塞进一块超宽平面板 |
| **主窗 + 折角侧翼（Winged）** | 水平视角 `40°–60°`，含主画布 + 导航/目录/属性等辅助区 | 主窗口居中，左右副面板向用户内倾约 `15°–25°` 形成微环绕，保持各面板中心到眼睛距离相近 | 副面板与主窗之间留明确物理缝隙（约 `2–6cm`）与视觉层级区分，禁止紧贴错位导致双目边缘闪烁 |
| **柱面弧形画布（Curved）** | 沉浸式多栏工作台、影院/数据大屏或全景观测界面 | 面板沿以用户为圆心、与视距接近的圆柱弧面排布，使左右边缘法线指向用户 | 曲率不可过陡导致边缘文字拉伸变形；总水平跨度严禁常态超过 `±60°` 强迫大幅扭颈 |
| **独立伴随小窗 / 工具板** | 高频短操作、实时状态、快捷切换 | 放置在主窗外沿、近距手腕/控制器侧或桌面舒适区 | 只放 3–6 个高频项，严禁塞入长滚动列表或复杂表单 |

- 🔴 **核心高频操作必须留在主舒适区（水平 `±30°` 内）**：侧翼面板仅承载辅助导航、大纲、属性检查或次要参考信息，不得把高频确认/主提交按钮长期丢在 `±45°` 以外的边缘。
- 🔴 **严禁环形 360° 包围式日常 UI**：除极少数全景态势展示外，不得在用户背后或头顶上方摆放需主动查找的常规交互面板。

### 2.2 附属悬浮条（Ornaments / Floating Chrome）分离范式

参考成熟空间系统将导航与控制条剥离主内容容器的做法，避免主内容画布被多层顶栏/底栏挤压：

- 🟡 **导航条、工具栏、媒体控制与窗口抓手条优先作为外部附属条（Ornament）**：贴合主窗口底部、左侧或顶部外沿排布，并在 Z 轴相对主窗口向用户方向**微前移约 `2–4cm`**，不随主内容区滚动，形成自然层次感。
- 🔴 **附属条宽度与生命周期红线**：附属条的宽度**不得超过其关联主窗口的宽度**（参照 Apple visionOS HIG Ornaments 规范），且必须与主窗口共享同一生命周期与拖拽坐标系——移动、缩放、隐藏或关闭主窗口时同步联动，沉浸浏览全屏照片/视频时可按需淡出隐藏，严禁留下失联的孤立漂浮工具栏。
- 🟡 底部窗口控制条（移动抓手 + 关闭按钮）应与主内容区保持清晰物理间距，防止用户想拖动窗口时误点页面底部操作按钮。

### 2.3 视距分区与「中距交互歧义带（`0.5m – 0.8m`）」避坑红线

不同视距决定了用户的本能交互意图（伸手直接碰 vs 用射线/眼动间接操作），切忌把主面板落在交互意图模糊的过渡带：

| 视距分区 | 参考距离 | 适用界面与交互方式 | 关键约束 |
|---|---|---|---|
| **近距直触区** | 约 `0.25 – 0.46m`（舒适屈臂范围内；特定手部操作场景需按目标设备校准，如 PICO Spatial SDK 近距交互可达 `0.45 – 0.70m`） | 手腕快捷盘、桌面物理感开关、近距直触工具条 | 仅用于明确可伸手直接触碰的控件，提供接近渐变与按压深度反馈，避免长时悬空举臂 |
| **中距交互歧义带（高风险）** | 约 `0.50 – 0.80m`（Meta Horizon OS 明确警示的 Middle Distance Danger Zone） | **尽量避免放置主交互面板** | 用户容易犹豫该伸手触碰还是发射射线，体验割裂；若业务确需在此区间放置面板，必须通过强烈视觉提示锁死单一交互态 |
| **中距主操作区（推荐）** | 约 `1.0 – 2.0m`（大屏看板可延至 `2.5m`） | 主业务窗口、多窗工作台、弹窗与核心阅读界面 | **默认最舒适区间**，适配眼动+捏合与手柄/手势射线；遵循约 `15°` 轻度俯视与动态角缩放 |
| **空间锚点与远距环境层** | 锚点建议 `≤ 3.0m`；环境导视 `> 3.0m` | 墙面/桌面锚定看板、空间导视牌、多人共享状态大屏 | PICO 官方建议世界空间锚点及关联 UI 尽量保持在距头显 `3m` 内以保障追踪与感知稳定；超过 `3m` 仅展示低密度摘要 |

❌ 反例：把 PC 端 1920×1080 后台的左侧导航、顶部多级工具栏、中间表格和右侧抽屉原样拼成一块 2.6 米宽的纯平大板挂在眼前 1.5 米处，用户看左右两侧时文字斜视角严重且脖子酸痛。

✅ 正例：保持主工作区落在约 35° 水平视野内，导航以左侧轻量悬浮条或内倾 18° 侧翼独立承载，窗口底部提供独立抓手条，各区边缘清晰且无需大幅转头。

## 3. 动态生成位置与多窗口生命周期

空间界面不是静态贴在屏幕四个角上的，必须完整定义**首次弹出（Spawn）→ 跟随/驻留（Follow/Pin）→ 拖拽缩放（Manipulate）→ 重置/关闭（Recenter/Dismiss）**全生命周期。

### 3.1 首次弹出锚点红线（Yaw-Only 生成）

- 🔴 **初始位置必须基于当前用户头部位置 + 仅水平朝向（Yaw-Only）计算**：将头部前向向量投影到水平面后，按默认视距与微俯角（眼高略低约 `5°–15°`）生成；**严禁叠加抬头/低头（Pitch）与歪头（Roll）角度**，避免用户低头看手或仰头看天花板时弹出斜拍地板或贴在头顶的畸形窗口。
- 🔴 **禁止写死绝对世界坐标原点 `(0, 0, 0)` 或固定绝对高度**：不同用户身高、坐姿/站姿与出生点朝向各不相同，所有首次弹出的交互窗口必须相对当前用户实时头部基准计算。
- 🔴 **弹窗不得侵入最小舒适安全距**：任何弹出面板中心与最近边缘都必须距双眼 `≥ 0.45m`（中距主面板默认 `1.2–2.0m`），严禁贴脸弹出引发双目聚焦疼痛。

### 3.2 多窗口并发调度与防重叠规则

- 🔴 **明确二级内容承载策略，严禁无序原地堆叠**：打开详情页、二级设置或临时工具时，必须在产品与设计阶段明确采用以下三种策略之一：
  1. **主窗内路由 / 模态浮层**：强相关单线程任务（如确认弹窗、筛选器），在主窗正前方 `+5–10cm` 弹出并弱化主窗；
  2. **侧翼展开**：需对照主画布操作的检查器/素材库，在主窗右侧或左侧按折角槽位展开；
  3. **多窗槽位排布**：支持自由多任务的工作台，设定同屏活动窗口数量上限（常规建议 `≤ 3` 块主窗）并按预设水平槽位错开生成，避免与已有窗口重叠造成 Z-fighting 或遮挡。
- 🟡 关闭侧翼或临时弹窗后，主窗口保持原位稳定，不无故大幅跳动重排造成视线丢失。

### 3.3 拖拽、推远拉近与视角重置（Recenter）

- 🔴 **用户拖拽移动窗口时，默认保持仅绕 Y 轴朝向用户（Y-Axis Billboard）且沿舒适球面/柱面自然滑动**，防止拖到侧面后面板背对用户或发生歪斜翻滚。
- 🔴 **明确距离变化时的缩放模式**：
  - **动态等角缩放（Dynamic Scaling）**：拉近缩小、推远放大，使角尺寸近似恒定，适合需要自由摆在房间的通用内容窗口与阅读面板；
  - **真实物理尺寸（Fixed Physical Size）**：保持真实米制尺寸不变，适合与真实设备/3D 等比模型对齐的工业标注、尺规与沉浸式道具界面。
- 🔴 **必须提供视角重置与窗口召回能力**：当用户走动离开世界锚定面板较远、切换坐/站姿或系统 Recenter 后，必须提供明确的一键召回或回正入口，防止面板遗失在房间角落。

❌ 反例：用户低头拿手柄时触发系统弹窗，代码直接沿 `Camera.forward` 与 `Camera.rotation` 生成面板，结果窗口 45° 斜插在地面上且被主菜单遮住一半。

✅ 正例：弹窗仅取头部水平前向（Yaw），在眼前 `1.5m`、眼高略偏下 `10°` 且避开已有主窗/墙体的安全槽位水平正向展开，用户走动后可一键召回至当前正前方。

## 4. UI 与 3D 主体及现实环境（MR）的共存与防穿模

成熟 XR 应用的核心特征是**空间 UI 与 3D 场景/真实世界和谐共存**，而不是把 3D 画面当背景墙、在正中间糊一块遮挡视线的巨型平板。

### 4.1 附属 3D 物体的局部 UI vs 独立空间窗口

| UI 归属类型 | 典型场景 | 空间摆放规则 | 禁止事项 |
|---|---|---|---|
| **3D 物体附属 UI（Diegetic / World-Attached）** | 3D 模型热点标注（Callout）、物体底座操作环、部件局部属性卡片、工具把手状态指示 | 紧邻目标 3D 物体外轮廓的侧上方或底座安全区，通过轻量引导线或锚点与目标建立视觉连接，随目标物体相对移动 | **严禁直接糊在 3D 主体正中遮挡核心观察面**；严禁把全局设置或长列表挂在移动中的 3D 物体上 |
| **独立空间窗口（Spatial Window）** | 主菜单、资产库、全局设置、协作聊天、文档/报表看板 | 独立置于用户前方主舒适区或侧翼，与 3D 主体左右错开或上下分层，不抢占 3D 主操作焦点的中心视线 | 严禁在用户正操作 3D 模型时自动弹出不透明全遮挡大板打断空间操作 |

### 4.2 碰撞避让、MR 平面吸附与安全视线

- 🔴 **生成与拖拽必须处理防穿模（Anti-Clipping）**：当面板默认生成位置或拖拽落点与 3D 大型模型、真实墙面或桌面（MR 场景网格 / 深度缓冲）相交时，必须按以下优先级处理：
  1. **自动前推避让**：沿用户视线方向前移至障碍物前方安全偏移处（同时不得突破最小离眼距 `0.45m`）；
  2. **平面吸附对齐（MR 贴墙/贴桌）**：当用户主动将面板推近墙面或桌面时，允许自动吸附并保留 `1–3cm` 防 Z-fighting 离墙间距；
  3. **显式避让回退**：若真实空间过于狭小无法无穿模展开，缩小至紧凑布局或提示用户调整朝向，**严禁任由面板一半插进墙体或模型内部导致按钮无法点击**。
- 🔴 **MR 模式保留现实物理安全视线**：严禁用大面积不透明 UI 面板遮挡用户脚下地面、走廊通道或现实操作台危险区域；涉及移动任务时及时收起或半透明退让非必要大窗。

## 5. 空间景深层级规范（Z-Layering 与背景退让）

二维界面靠 `z-index` 与投影表达层级，三维双目视觉下必须使用**真实的物理 Z 轴深度偏移**，否则左右眼视差一致会导致严重的双目层级错乱与 Z-fighting 闪烁。

| 景深层级 | 相对主窗口 Z 偏移参考（正值指向用户） | 典型元素 | 视觉与交互协同要求 |
|---|---|---|---|
| **L0 · 场景与环境层** | 远于主窗（背景空间） | 3D 场景、共享 3D 模型、MR 真实环境 | 保持稳定物理深度，不与 UI 抢同一平面 |
| **L1 · 主内容窗口层** | `0 cm`（基准面） | 主业务窗口、侧翼副面板 | 弹窗打开时可整体轻度后退（如 `-4 至 -8cm`）并降低亮度/对比度 `20%–35%` |
| **L2 · 悬浮控件与附属条层** | `+2 至 +4 cm` | Ornaments 外部工具/导航条、悬停浮起卡片、窗口抓手条 | Hover 时轻度向前浮起（如 `+1 至 +2cm`）强化深度可达感 |
| **L3 · 瞬态浮层与下拉层** | `+4 至 +6 cm` | 自定义下拉菜单、Tooltip、气泡确认、上下文菜单 | 严禁与父面板贴在同一 Z=0 平面，确保在双目视角下清晰浮于父面之上 |
| **L4 · 模态弹窗与系统确认层** | `+6 至 +10 cm` | 破坏性操作二次确认、关键异常拦截、虚拟键盘 | 同步锁定底层窗口交互并退暗底层，替代铺满全视野的纯黑半透遮罩 |

- 🔴 **物理深度层级必须跨岗位对齐**：UI 设计稿交付说明中须明确组件所属层级（L1–L4），研发侧在 Unity / WebXR / 原生空间引擎中落实真实物理 Z 偏移，不得仅靠调整 Canvas 排序（Sort Order）关闭深度测试来糊弄双目遮挡关系（特殊防穿模覆盖层须经过真机双目舒适度验证）。

## 6. 主流设备与平台差异适配矩阵

通用空间摆放规则落地到具体头显时，按目标设备查阅下表调整输入交互、材质预算与系统窗口范式（下列平台特征核验日期：`2026-11-25`）：

| 适配维度 | Apple visionOS（Vision Pro 等） | Meta Horizon OS（Quest 3 / 3S 等） | PICO OS 6 / PICO XR（PICO 4 Ultra 等） |
|---|---|---|---|
| **主输入范式** | **眼动注视 + 双指轻捏（Look & Pinch）**为主，近距裸手直触为辅（HIG 明确优先间接手势防举臂疲劳） | **6DoF 手柄射线 + 裸手直触/远距捏合**双模并行 | **多模态原生支持**：PICO OS 6 已将**眼动注视 + 手势捏合**纳入系统默认交互，同时支持 6DoF 手柄与外接键鼠；旧版 OS / 工业项目常以手柄为主 |
| **热区、间距与核心视野** | 常规按钮**中心距 `≥ 60pt`**、边界净间距 **`≥ 16pt`**；依赖系统眼动 Hover 反馈，不强求手举射线悬停；渐进/全沉浸边界约 `1.5m` | 最小命中热区 **`48dp × 48dp`**、主控件推荐 **`≥ 60dp × 60dp`**、相邻间距 **`≥ 16dp`**；眼动目标 **`≥ 3°` 视角**；推荐核心设计安全区 **`58° H × 54° V`**；善用不可见热区扩展（Hit Slop） | 水平优先排布与圆角控件，支持 Hover / Tap / LongPress / Drag / Scale / Rotate 空间事件；空间锚点与关联 UI 官方建议在 **`≤ 3.0m`** 范围保证稳定追踪 |
| **光学清晰度与渲染策略** | 高 PPD Micro-OLED，支持精致排版与系统原生 Glass 材质（自动响应环境光）与 Dynamic Scaling | 移动一体机严格受限，严控多层半透明与实时全屏模糊；高文本清晰度优先采用 **Compositor Layers（`OVROverlay` / `OVROverlayCanvas`）** 与密度缩放（`DpDisplayOptions` 288 DPI / `DpPerMeterDisplayOptions` ~500 dp/m） | 移动一体机同样严控实时模糊 Overdraw；支持曲面大面板保边缘清晰，Unity 工程文本密集面板优先评估 OpenXR Composition Layers / `PXR_Overlay` |
| **原生窗口与挂件范式** | Shared/Full Space；`WindowGroup` + **`Ornament`（宽度不超主窗）** + `Volume` + 底部系统 Window Bar | 2D / 曲面多窗 Dock + 底部系统控制栏；引擎内常基于 Meta XR Interaction SDK / `OVRCanvasMeshRenderer` 构建 | PICO OS 6 统一空间引擎支持 Shared/Full Space 多任务：**Planar Windows**（平面/曲面动态缩放）+ **Volumetric Windows**（3D 体积窗） |
| **系统保留手势/按键红线** | 顶部控制点、Digital Crown 旋钮（沉浸度/视角重置）、双指捏合系统菜单 | 右手掌心捏合呼出菜单、手柄 Meta 键 | 手柄 PICO 键、系统手势唤起主菜单 |
| **常见实现技术栈** | SwiftUI + RealityKit / Unity PolySpatial | Unity（OpenXR / Meta XR SDK）/ Meta Spatial SDK / Unreal / WebXR | PICO Spatial SDK（Kotlin 声明式空间 UI）/ Unity（OpenXR / PICO XR SDK）/ Unreal / WebXR |

- 🔴 **项目本地覆盖绑定模板**：具体 XR 项目应在 `.agent-rules/overrides.md` 中显式声明目标设备、OS 版本与运行基线（例如：`目标设备：PICO 4 Ultra（PICO OS 6 / MR 彩透）；主输入：眼动捏合 + 6DoF 手柄射线；主窗默认视距：1.5m；缩放策略：动态等角缩放`），避免 AI 在不同平台范式间混用。
- 🔴 **官方参考依据与时效声明**：上表参数依据 Apple Developer HIG（visionOS Spatial Layout / Windows / Ornaments）、Meta Horizon OS Developer Documentation（Spatial UI Design Guidelines / Target Sizing / Distance Zones / OVROverlay）及 PICO Developer Documentation（PICO OS 6 / PICO Spatial SDK Design Guidelines）核验（核验日期 `2026-11-25`）；具体项目仍须以所装目标 SDK 版本与真机实测结果为准。

## 7. 跨岗位交接契约与完成检查

涉及空间 UI 规划、设计与开发协作时，各岗位通过以下统一规格表对齐（可写在 PRD、UI 交付说明或技术设计文档中）：

| 交接字段 | 产品经理定义 | UI 设计师补全 | 引擎/前端研发落地 |
|---|---|---|---|
| 窗口/面板标识与归属 | 业务职责、独立窗口 vs 3D 附属 UI | 拓扑形态（单窗/折角侧翼/弧排/附属条） | Prefab / 组件容器与 Window Manager 注册 |
| 视距、尺寸与缩放 | 坐/站姿与预期观看距离层级 | 物理宽高（m）、设计稿 px 与 PPU 换算、等角/物理缩放 | Canvas Scale / 空间尺寸与缩放曲线 |
| 生成、跟随与多窗 | 触发时机、并发上限与关闭策略 | 初始位置、折角角度、锚定模式与 Recenter 行为 | Yaw-only Spawn、Lazy Follow 阻尼与槽位调度 |
| 景深与防穿模 | 与 3D 主体/现实空间的遮挡预期 | L1–L4 景深层级与背景退让视觉 | 真实物理 Z 偏移、碰撞前推/MR 贴墙避让 |
| 设备与输入适配 | 目标设备列表与最低档位 | 各设备热区、MR 底板对比度与降级态 | OpenXR/SDK 输入映射、防抖与真机验证 |

### 完成检查清单

- [ ] 已明确目标设备（Vision Pro / Meta Quest / PICO 等）与显示模式（VR / MR / AR），未将单一平台交互范式误用到不兼容设备。
- [ ] 单窗超宽内容已拆分为主窗 + 折角侧翼 / 弧形布局或剥离外部附属条，核心高频操作落在水平 `±30°` 主舒适区。
- [ ] 首次弹出采用 Yaw-only 水平基准，已定义多窗并发上限、推远拉近缩放模式及视角重置/窗口召回路径。
- [ ] 已明确独立空间窗口与 3D 物体附属 UI 的归属，并设计了遇到 3D 模型或 MR 真实墙面/桌面时的防穿模避让策略。
- [ ] 已定义 L1–L4 物理 Z 轴景深层级与跨岗位交接规格表，且标注了待真机实测复核项。
