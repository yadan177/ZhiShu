# 04 - 资产导入自动化校验与真机剖析规范

> - 🟢 本文件适用于 Unity 编辑器资产导入校验脚本编写、资产合入前自动质检以及 XR 真机性能剖析与优化报告输出。
> - 🔴 不适用：未经审核在导入钩子中静默大面积覆写项目历史资产 `.meta` 文件或修改外部第三方插件包内容。

---

## 1. 资产导入校验脚本（AssetPostprocessor / Validator）编写规范

通过自动化脚本把三维资产和特效规范落到日常导入流程中，但脚本本身必须遵守工程安全底线：

- 🔴 **清晰界定作用目录（白名单范围）**：导入脚本必须通过明确路径白名单只作用于项目自研美术资产目录（如 `Assets/Art/...`），**严禁无过滤拦截 `Packages/`、第三方 SDK 插件目录与编辑器图标资源**。
- 🔴 **审计与改写分离**：
  - 优先提供独立的“一键规范体检窗口 / CI 检查命令”，以可点击定位对象的方式输出违规清单（🔴 阻断 / 🟡 警告）；
  - 若使用 `AssetPostprocessor` 自动施加项目默认导入预设，必须只对**首次新导入资产**或显式符合约定命名规则的资产生效，避免每次 Reimport 无声覆盖美术已特批微调的参数（应提供明确豁免标记机制）。
- 🔴 **高价值必查规则清单**：
  - **模型导入**：检查静态非脚本读取网格是否误开 `Read/Write Enabled`（开启会导致 CPU+GPU 双份内存占用）、是否误导入无用相机与灯光、无动画模型是否关闭 Rig、是否缺失预期 LOD 或超过档位面数预警线；
  - **贴图导入**：检查数据图（Normal / ORM / Mask）是否误勾 sRGB、是否误开 `Read/Write Enabled`、3D 贴图是否误关 Mipmap、非透明图是否残留 Alpha 通道、目标平台压缩格式是否符合项目档位约定；
  - **材质与特效**：检查是否残留默认 `Standard` / 报错粉红 Shader、单 Prefab 粒子数上限是否超标、是否误开 Particle Lights 或高开销碰撞模块，以及特效目录/命名、`_Common/` 单向依赖（禁引用 `_Sandbox/` 或业务脚本）、根 Transform `(1,1,1)` 与 `Scaling Mode` 是否符合 [02-VFX 特效与 Overdraw 预算规范](./02-VFX特效与Overdraw预算规范.md#4-特效目录树命名与跨项目资产复用规范)。

## 2. 真机性能剖析流程（先测再改，杜绝盲目优化）

任何性能优化必须先在**目标最低档位真机、Release/非重调试干扰口径、热稳态运行**下获取量化证据，禁止在桌面 Editor 凭感觉“猜瓶颈”：

1. **先分清 CPU 瓶颈还是 GPU 瓶颈**：
   - 使用 Unity Profiler、目标厂商性能工具（如 PICO 性能监控 / OVR Metrics / Snapdragon Profiler / RenderDoc）记录帧时分布；
   - CPU Bound（主线程或渲染线程耗时接近/超过帧时上限）：优先查脚本 `Update` 逻辑、GC 分配尖峰、物理模拟步数、UI Canvas 频繁 Rebuild、未合批 DrawCall 提交与动画更新；
   - GPU Bound（GPU 帧时超标）：优先查半透明特效 Overdraw、全屏后处理与深度/不透明图拷贝、片元 Shader 复杂度与采样数、阴影 Pass 与过高分辨率/面数。
2. **用 RenderDoc / Frame Debugger 逐 Pass 拆解**：
   - 核对单帧总 Pass 数，检查是否存在意料之外的额外全屏拷贝、多余阴影投射或重复渲染；
   - 核查 SRP Batcher 合批打断原因（Unity Frame Debugger 会直接标出破批原因），逐项消除高频破批。
3. **验证单变量收益与副作用**：
   - 每轮优化尽量控制改动范围，记录优化前后的同场景同视角热稳态指标，并复核画面质量与双目舒适度未发生不可接受退化。

## 3. 真机性能剖析报告标准结构

向项目负责人、三维美术或研发同步真机剖析结果时，报告应包含以下精简结构：

| 章节 | 必填内容 |
|---|---|
| **1. 测试环境与基线** | 设备型号、OS、引擎与 SDK 版本、场景名、刷新率目标、测试时长（冷态/热稳态） |
| **2. 核心指标总览** | 平均 FPS、P95/P99 帧时、CPU/GPU 耗时、DrawCall/SetPass、面数、显存与总内存峰值 |
| **3. Top 瓶颈归因（按影响排序）** | 精确到具体场景对象/特效/Shader/脚本，附 Profiler 或 Frame Debugger 证据，明确责任岗位 |
| **4. 落地优化方案与预期收益** | 区分“立即可做低风险项”与“需美术/产品确认视觉取舍项” |
| **5. 回归对比与剩余风险** | 优化前后实测对比数据，以及尚未覆盖的设备或复杂交互场景 |
