# 15 - 技术美术（TA）AI 通用入口规则

> - 🟢 本文件适用于 AI 参与的特效性能体检、Shader 编写与审查、渲染管线与材质合批检查、Unity 资产导入校验脚本生成及真机性能剖析报告输出。
> - 🔴 不适用：未读取项目实际引擎/管线版本即套用过时 Shader 宏，或仅凭桌面编辑器视图宣称移动 XR 性能与双目显示合格。

---

## 1. 开始前核对

开始任何 TA 审查、Shader 开发、特效优化或校验脚本任务前，先读取[总览](./00-文档总览.md)并核对项目真实渲染环境：

1. **引擎与渲染管线版本**：确认 Unity 版本、URP / HDRP / Built-in 管线版本及 Graphics API（Vulkan / OpenGL ES / Metal / Direct3D）。
2. **立体渲染模式**：确认 XR 项目采用 `Single-Pass Instanced` 还是 `Multi-Pass`（移动 XR 优先检查 Single-Pass Instanced）。
3. **目标硬件档位**：明确最低目标设备（移动一体机 vs PCVR）与是否安装 `xr-common` 预算基线。
4. **现有资产管线约定**：检查项目中已有的自定义 Shader 库、材质模板、AssetPostprocessor 脚本与变体收集文件（`.shadervariants`）。

- 🔴 不得脱离项目实际 URP 版本盲写内部未公开函数或废弃 API；涉及 RenderGraph（URP 17+）或旧版 `ScriptableRenderPass` 时先核对工程实际包版本。
- 🔴 审查特效或材质性能问题时，必须区分“静态配置静态风险（L1）”与“真机实测瓶颈证据（L4）”，不可把理论猜测写成实测结论。

## 3. 脚本与修改安全约束

- 🔴 **资产导入脚本默认先做只读体检报告**：生成 `AssetPostprocessor` 或编辑器批处理工具时，优先提供可预览差异的审计窗口或日志报告，严禁在未经团队确认的情况下静默批量改写全工程 `.meta` 与贴图/模型导入参数。
- 🔴 **修改公共 Shader 前盘点全部引用材质**：改变属性名、CBUFFER 布局或关键字语义前，必须核查受影响的材质实例与运行时 `Material.Set*` / `EnableKeyword` 代码。
- 🔴 **不以关闭关键质量特性掩盖根因**：禁止在未说明视觉副作用的情况下擅自关闭 MSAA、全局降分辨率或粗暴删光全部阴影来“凑帧率”。

❌ 反例：发现项目帧率偏低，直接写脚本把所有贴图强制改成低分辨率且关闭全场景 Mipmap，导致头显内画面严重闪烁噪点且无法追溯哪些资产受影响。

✅ 正例：先通过真机 Profiler / Frame Debugger 定位主瓶颈（例如半透明特效 Overdraw 占去 GPU 45% 耗时），给出针对性 Tight Mesh 与层数裁剪方案并保留真机前后对比数据。

## 4. 交付与报告

TA 审查、优化或脚本交付输出应简要包含：

1. 本次核对的引擎/管线版本、立体渲染模式与目标硬件档位。
2. 定位出的核心问题清单（按阻断 🔴 / 推荐 🟡 排序，精确到 Shader/材质/特效/场景路径）。
3. 具体修改方案、对视觉与合批/变体/帧时的影响及回滚方式。
4. 已完成的验证层级（静态检查 / 编辑器编译 / 真机热稳态剖析）与待真机确认项。
