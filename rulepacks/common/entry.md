# 00 - 智枢通用入口规则

> - 🟢 本文件适用于所有接入智枢项目规则的业务工程与协作仓库。
> - 🔴 不适用：替代目标项目的真实代码事实、本地覆盖规则或安全边界。

---

## 1. 优先级

执行任务时按以下顺序处理约束：

1. 用户当前任务与安全限制。
2. 目标工程代码、依赖、配置、测试和已有项目约定。
3. `.agent-rules/overrides.md` 中的项目覆盖规则。
4. 当前任务相关的已安装智枢规则包。

共享规则不得替代项目事实，也不得要求与当前任务无关的重构、升级或迁移。

## 2. 规则选择与作用域隔离

先按任务读取已安装的相应入口：开发与排障选择当前技术栈（如 `unity`、`pico`、`typescript`、`javascript`、`go`、`java`、`python`），XR 跨岗位基准选择 `xr-common`，产品规划选择 `product-pm`，界面设计选择 `ui-design`，三维美术选择 `3d-art`，技术美术选择 `ta-vfx-shader`，文档任务选择对应的 `project-docs/*`。再按入口读取必要专题，不要把整个规则库当作每次改动都必须执行的清单。

- 若仓库同时安装 `rule-authoring`（规则编写格式规范），其作用域**严格限定为规则库正文（如 `rulepacks/`）的编写与维护**，不得与业务代码规范或普通项目文档规范混用。
- 规则包 manifest 未标记为 `ready`、入口不存在或链接损坏时，必须报告缺失，不得声称已经执行该规则包。

## 3. 通用工程治理专题

跨语言、跨岗位共享的协作与发版基线（各技术栈特有细节如 `.gitignore`、Unity `.meta`/LFS、依赖锁文件等仍以对应语言包的版本控制规则为准）：

- 分支时机、分支命名、Commit 提交与推送合并（单人/多人通用）：[01 - Git 版本控制规范](./01-Git版本控制规范.md)
- 软件版本号、迭代封板、Tag / CHANGELOG、Hotfix 与多端版本协同：[02 - 软件版本迭代与发布管理规范](./02-软件版本迭代与发布管理规范.md)
- 跨端接口契约、字段/错误码对齐、并行联调与向下兼容：[03 - 跨端接口契约与联调规范](./03-跨端接口契约与联调规范.md)

## 4. 交付

完成任务时说明实际使用的规则、执行的验证、文档影响和未验证范围。不得伪造命令、测试结果、接口或项目事实。

## 5. 规则更新

更新已安装的智枢规则时，先检查新版本并审查差异；只有在用户明确同意后，才应用更新。不得静默覆盖项目本地规则或未知文件。
