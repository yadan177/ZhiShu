# 智枢 — 安装与更新指南

本文说明**当前已实现的智枢 `2.0.0` 桌面版与 CLI** 如何安装与更新。旧的规则管理 Codex 插件包已从仓库退役；6 大官方岗位插件（42 个 Skills）已在 `plugins/` 落地并接入桌面端官方预设随 `desktop-v2.0.0` 分发，详情见 [智枢产品需求文档](../产品文档/智枢-产品需求文档.md) 与 [用户环境资产安装机制](用户环境资产安装机制.md)。

## 当前安装位置与形态

- **智枢桌面版（`desktop-v2.0.0`）**：安装在个人电脑，采用左侧 4 模块架构（「我的项目 / 项目规则」「插件与技能」「AI 工具」「来源管理」），支持多岗位 20 规则包组合、本地/私有 Git/官方三级来源与企业必选锁定、中断事务可视化恢复、跨工具插件/技能同步及 MCP 脱敏配置。
- **`zhishu` CLI（`v2.0.0`）**：安装在个人电脑，按指定项目路径检测、下载、校验、恢复、卸载和更新规则，支持 `init --rulepacks` 与 6 平台 `--targets`（`codex,antigravity,trae,qoder,cursor,workbuddy`）。
- **项目级落盘位置**：选定的规则包复制进业务项目的 `.agent-rules/`，与 `agent-rules.yaml`、`.agent-rules.lock.json` 和 `AGENTS.md` 一同提交 Git；项目本地规则写在 `.agent-rules/overrides.md`。
- **软件用户级落盘位置**：插件、独立技能与 MCP 安装在所选 AI 工具的本机用户环境（跨项目复用，不绑定具体项目），详情见 [用户环境资产安装机制](用户环境资产安装机制.md)。

从 `v0.1.2` 起，如果规则源包含根目录的普通文本 `LICENSE`，安装器还会把它复制为业务项目中的 `.agent-rules/LICENSE`，记录在锁文件并纳入后续差异预览和完整性校验。已有同名未知文件时会停止，不会覆盖。

## 从 npm 首次安装

需要 Node.js 22+、npm 和可访问 GitHub 的网络。

```bash
npm install -g zhishu
zhishu detect /absolute/path/to/project
zhishu init /absolute/path/to/project
zhishu validate /absolute/path/to/project
```

默认来源是 `yadan177/ZhiShu` 的最新正式 GitHub Release。CLI 验证 Release 资产的 SHA-256 后才解包；下载、校验或规则清单有问题时不会安装。初始化会保留已有 `AGENTS.md` 的非受管内容，若目标位置已有未知文件则停止并报告冲突。

当前源码构建后的 CLI 支持显式指定多平台与多岗位规则包组合：

```bash
node packages/cli/dist/index.js init /absolute/path/to/project \
  --source-workspace /absolute/path/to/ZhiShu \
  --targets codex,antigravity,trae,qoder,cursor,workbuddy \
  --rulepacks common,unity,xr-common,product-pm,ui-design
```

规则正文在 `.agent-rules/` 只安装一份，`AGENTS.md` 只有一个受控入口；传递依赖（如 `project-docs/ui-design`、`javascript`）自动解析写入锁文件。其他平台现有的原生规则文件不会被修改。

`init` 会先打印检测到的技术栈依据和建议规则包，然后尝试安装；若希望先判断技术栈而不写入项目，只运行 `detect`。规则更新始终先用 `diff` 审查，再显式执行 `update --apply`。

TypeScript 工程即使没有 `package.json`，只要项目根目录有 `tsconfig.json`，也会识别为 TypeScript 并安装其 JavaScript 基线依赖；技术栈检测仍以目标工程的实际文件为准。

锁文件固定 Release 版本、资产摘要与 Git 来源提交。首版只接受正式 stable 版本；若最新 Release 低于项目锁定版本或同版本资产摘要发生变化，`check`、`diff`、`update` 均拒绝继续，不会自动降级。

## 更新与中断恢复

```bash
zhishu validate /absolute/path/to/project
zhishu check /absolute/path/to/project
zhishu diff /absolute/path/to/project
zhishu update /absolute/path/to/project --apply
zhishu validate /absolute/path/to/project
```

- `validate` 校验本地配置、锁文件、受管文件哈希与传递依赖闭包。
- `check` 对比规则源版本，发现可用更新时退出码为 `3`。
- `diff` 与不带 `--apply` 的 `update` 仅预览不写入；`update --apply` 应用前二次重验差异与配置，失败自动回滚。
- 遇到异常中断残留 `.agent-rules.transaction-*` 事务目录时：
  - **CLI**：先运行 `zhishu recover <project-root>` 审查，再运行 `zhishu recover <project-root> --apply` 恢复。
  - **桌面端**：在「我的项目」状态栏或「项目规则」顶部中断警告条直接点击「恢复中断事务」。
- 写入期间生成的 `.agent-rules.operation.lock` 用于防并发修改，不应提交到业务项目 Git。

## 卸载业务项目中的规则

```bash
zhishu uninstall /absolute/path/to/project
zhishu uninstall /absolute/path/to/project --details
zhishu uninstall /absolute/path/to/project --apply
```

卸载无需联网，只删除锁文件登记且未漂移的受管规则文件、配置与锁文件；`AGENTS.md` 仅移除智枢受控区块，`.agent-rules/overrides.md` 及其他非受管文件原地保留。

## 本地开发、三级来源与离线试用

当前源码中的 `ui-design`、`project-docs/ui-design`、`xr-common`、`product-pm`、`3d-art` 与 `ta-vfx-shader` 为新增可选规则包，尚未进入 `v0.1.5` 正式 GitHub Release：

- **桌面端试用**：运行 `ZHISHU_DEV_PROFILE=/tmp/zhishu-dev npm run dev --workspace zhishu-desktop`，在「来源管理」中添加企业/个人本地目录源或私有 Git 源（HTTPS 令牌仅存本机 `0o600` 凭据文件），或直接在「项目规则」切换「本地目录源」即可选装全部 20 个规则包；企业源声明的必选规则包会在项目规则页自动锁定。
- **CLI 离线试用**：在仓库根目录执行 `npm ci && npm run build`，使用 `--source-workspace /absolute/path/to/ZhiShu`（可配合 `--rulepacks`）对独立临时工程执行初始化、更新与校验。

本地目录源配置会记录 `workspace` 路径，请勿把指向个人绝对路径的测试配置提交到团队共享业务仓库。
