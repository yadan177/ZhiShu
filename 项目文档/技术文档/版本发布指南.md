# 版本发布指南

本文说明 **智枢（ZhiShu）** 的双轨发布机制、门禁检查与验证流程。历史版本变更记录见 [CHANGELOG.md](../../CHANGELOG.md) 与 GitHub Releases；历史过程验收记录已清理，需回溯时通过 Git 历史查阅。

---

## 1. 双轨发布策略

仓库将 **核心规则包 + npm CLI** 与 **桌面应用** 拆分为两条独立发布轨道：

| 轨道 | Git 标签规则 | 触发工作流 | 发布产物 | 说明 |
|---|---|---|---|---|
| **规则包（GitHub Release）** | `vX.Y.Z` | `.github/workflows/ci.yml` | `zhishu-rulepacks.tar.gz`（含 `zhishu-release.json`、`LICENSE`、`rulepacks/`） | 作为 GitHub `latest` Release，供 CLI 与桌面端在线拉取并做 SHA-256 校验 |
| **CLI（npm）** | `vX.Y.Z`（手动触发） | `.github/workflows/publish-npm.yml` | `zhishu@X.Y.Z`（OIDC Trusted Publisher） | 发布前强校验同版本 GitHub Release 已存在且 `sourceCommit` 与 `LICENSE` 一致 |
| **桌面应用（GitHub Release）** | `desktop-vX.Y.Z` | `.github/workflows/desktop-release.yml` | `ZhiShu-Desktop-X.Y.Z-macOS-arm64.dmg`、`ZhiShu-Desktop-X.Y.Z-Windows-x64.exe` | 发布时标记 `--latest=false`，避免覆盖规则包的 `latest` Release |

> 安全保护：Release 与 npm 发布工作流均要求仓库处于 Public 状态，且桌面标签必须源自 `main` 分支并与 `packages/desktop-app/package.json` 版本一致。

---

## 2. 规则包与 CLI 发布步骤

1. **统一版本号**：确保以下位置的 `version` 与目标标签 `vX.Y.Z` 一致，运行 `npm run manifests` 刷新全部规则包清单：
   - `package.json`、`packages/core/package.json`、`adapters/codex/package.json`、`packages/cli/package.json`
   - `adapters/{codex,qoder,cursor,workbuddy}/adapter.json`
   - `packages/cli/src/index.ts`（`VERSION`）与 `packages/core/src/project.ts`（`TOOLKIT_VERSION`）
   - 运行 `node scripts/verify-release-version.mjs vX.Y.Z` 校验一致性。
2. **同步内容来源清单与全量校验**：
   ```bash
   node scripts/generate-provenance-inventory.mjs --write
   npm run check
   bash scripts/check-rule-docs.sh
   ```
3. **推送标签发布规则包 Release**：推送 `vX.Y.Z` 后，CI 在 Linux / macOS / Windows（Node 22/24）全部通过后自动打包并创建 GitHub Release。
4. **本地与远端烟测**：
   ```bash
   npm run smoke:public -- X.Y.Z
   ```
5. **发布 npm CLI**：在 GitHub Actions 手动对 `vX.Y.Z` 触发 `发布 npm CLI` 工作流（通过 OIDC 发布）。发布后执行：
   ```bash
   npm run smoke:npm -- X.Y.Z
   ```
   跨版本更新验证需先以旧版初始化隔离测试工程，再依次执行 `check`、`diff`、`update --apply` 和 `validate`。

---

## 3. 桌面应用发布步骤

1. 更新 `packages/desktop-app/package.json` 的 `version` 与 `build.buildVersion`，并编写 `packages/desktop-app/RELEASE-X.Y.Z.md`。
2. 执行本机检查：
   ```bash
   npm run check
   npm run typecheck --workspace zhishu-desktop
   npm test --workspace zhishu-desktop
   ```
3. 推送源自 `main` 的 `desktop-vX.Y.Z` 标签，自动在 macOS / Windows 运行器构建 DMG 与 EXE 并创建独立的桌面 Release。
4. 签名状态说明：未配置代码签名与公证前，仅输出手动安装包（不含 `latest.yml`），桌面端自动更新策略引导用户手动下载安装。

---

## 4. 许可文件与权利复核策略

- 从 `v0.1.2` 起，GitHub 规则包归档根目录强制携带仓库 `LICENSE`，安装器将其作为 `.agent-rules/LICENSE` 纳入业务项目的受管文件与差异审查。
- `verify-published-release.mjs` 在 npm 发布前会下载真实 Release 归档，逐字节核对 `LICENSE` 与仓库一致。
- 附带仓库许可文本不替代各规则文件第三方材料的人工核对，逐项复核记录维护于 [内容权利复核表](内容权利复核表.md) 与 [规则包内容来源清单](规则包内容来源清单.md)。
