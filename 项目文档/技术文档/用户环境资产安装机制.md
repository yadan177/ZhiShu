# 用户环境资产安装机制（插件、技能与 MCP）

本页描述智枢桌面端用户环境安装器的当前源码实现（含已发布 `1.2.2` 的 Codex / TraeWork 能力，以及 2.0 阶段新增的 Antigravity、通用标准目录、MCP 脱敏配置引擎与本机工具探测器）。Codex 文件/插件流程已验证；Antigravity 与 MCP 配置的隔离目录文件事务已通过自动化单元测试，真实 Antigravity / 新版 TRAE 客户端的实机加载与任务调用仍待人工验收。

## 使用流程

1. **插件与技能**：进入左侧「插件与技能」→ 在「插件 / 技能 / MCP」三类标签下浏览内置官方 6 大岗位插件（`plugins/`，共 38 个 Skills）、导入本地插件包/独立 `SKILL.md`，或选择预设 `飞书 MCP` / 添加自定义 MCP → 点击卡片滑出右侧安装抽屉（展示中文技能清单与关联底层规则，点击任意技能可原地查看正文）→ 多选目标 AI 工具（不兼容工具自动禁用并说明原因）→ 预览逐文件或脱敏 Diff → 确认写入。
2. **AI 工具盘点**：进入左侧「AI 工具」→ 查看 4 类工具实时探测状态与计数 → 点击工具卡片筛选已安装清单 → 支持同源版本切换更新、MCP 环境变量快捷修改与安全卸载。

插件源支持根级 `plugin.json` 或兼容的 `.codex-plugin/plugin.json`。独立 Skill 使用根级 `SKILL.md`，必须有有效的 `name` 与 `description`；可通过 `metadata.version` 声明版本，没有版本时按内容摘要生成独立版本。每次导入保留完整文件快照、许可、来源和摘要；源脚本在导入时不执行。

## 目标 AI 工具交付矩阵

| 内容与目标 | 当前实现 | 检查与验收状态 |
| --- | --- | --- |
| 独立 Skill → OpenAI Codex | 安装到 `~/.agents/skills/<name>/`；旧 `~/.codex/skills/` 的同名内容会阻止重复安装。 | 校验文件摘要及权限；有可用 CLI 时通过只读 `skills/list` 核对用户级识别。 |
| 原生插件 → OpenAI Codex | 在智枢用户数据建立独立个人市场，经官方 `codex plugin marketplace add` / `plugin add` / `plugin remove` 管理。 | 核对宿主安装身份、来源、版本、启用状态及缓存文件。 |
| MCP → OpenAI Codex | 在 `~/.codex/config.toml` 中维护 `# zhishu:mcp:<id>:start/end` 受控 TOML 区块，保留用户其余配置。 | 校验区块摘要与漂移，预览强制脱敏（`••••<后4位>`）；隔离单测已通过，实机运行待验收。 |
| 独立 Skill / 插件 → Antigravity | 分别安装到 `~/.gemini/config/skills/<name>/` 与 `~/.gemini/config/plugins/<name>/`。 | 校验文件摘要与权限；隔离单测已通过，实机加载待验收。 |
| MCP → Antigravity | 合并写入 `~/.gemini/config/mcp_config.json` 的 `mcpServers.<id>`，保留用户其他服务与字段。 | 校验 JSON 项摘要与漂移，预览强制脱敏；隔离单测已通过，实机运行待验收。 |
| 独立 Skill → 通用标准目录 | 安装到 `~/.agents/skills/<name>/`；拒绝非 Skill 插件并提示改选 Codex 或 Antigravity。 | 校验本地文件摘要；与 Codex 共享目录时拒绝覆盖未知同名目录。 |
| 独立 Skill / Product Design → TraeWork | 安装到 `~/.trae-cn/skills/<name>/`（实验支持），保留 `toolbox-product-design` 适配与 ZIP 导出；其他插件明确标为不支持。 | 校验本地文件；新 TRAE 客户端路径与真实任务仍待实机验收。 |

Codex CLI 优先发现桌面应用附带的可执行文件，再检查 PATH 和 npm 原生二进制。找不到支持插件命令的版本时给出错误，不自动安装或修复用户的 Codex。

官方依据：[Codex 本地 Skills](https://learn.chatgpt.com/docs/build-skills)、[Codex 插件与个人市场](https://developers.openai.com/plugins/build/plugins)、[TraeWork Skills](https://docs.trae.cn/work_skills)、[TRAE 官方迁移说明](https://docs.trae.cn/work_traework-to-traecode-data-migration?lang=zh)。

## 写入、脱敏与安全护栏

- **资产安装回执**：保存在 `userData/ide-assets/receipts/`，分别记录软件、来源版本、目标目录、受管文件摘要和 Codex 宿主缓存。
- **MCP 密钥隔离与脱敏**：
  - MCP 定义目录保存于 `userData/mcp-assets/catalog.json`，安装回执保存于 `userData/mcp-assets/receipts/`，**两者均严禁保存明文密钥**（回执仅记录受管配置项摘要与键名列表）。
  - 敏感参数仅在确认写入时以 `0o600` 权限原子写入目标工具配置文件，预览弹窗全程按 `••••<后4位>` 脱敏展示。
  - 遇到未知同名 MCP 配置、符号链接路径、预览后文件变化或受管配置漂移时拒绝写入并回滚。
- **文件事务安全**：所有资产与 MCP 操作均采用暂存/临时文件、备份与互斥操作锁；异常自动回滚，绝不跟随符号链接或静默覆盖未知文件。

## 开发验证

```bash
npm run check
npm run typecheck --workspace zhishu-desktop
```

本机有可用 Codex CLI 时，设置 `ZHISHU_CODEX_CLI` 为其绝对路径再运行检查，可运行真实 CLI 的隔离安装、更新、缓存漂移拒绝和卸载测试；未设置时该项显式跳过。

开发版可设置 `ZHISHU_DEV_PROFILE` 为临时绝对目录，启动独立验证窗口；规则状态、导入库、来源注册表、MCP 配置以及各 AI 工具的目标用户环境均隔离在该目录中。
