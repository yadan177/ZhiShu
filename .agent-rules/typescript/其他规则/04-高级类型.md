# 04 - TypeScript 高级类型

> - 🟢 本文件适用于 TypeScript 高级类型的使用边界（条件类型/infer/映射类型/模板字面量）。
> - 🔴 不适用：业务逻辑实现（仅库 / 抽象层使用）

---

## 1. 🔴 硬约束 · 这些绝对不要写

### 1.1 业务代码过度使用高级类型

```ts
// ❌ 业务代码用条件类型 + infer + 映射类型
type GetFieldType<T, K extends keyof T> = T[K] extends infer R ? R : never;
function processEntity<T, K extends keyof T>(entity: T, field: K): GetFieldType<T, K> {
  return entity[field];
}

// ✅ 业务代码用简单泛型
function processEntity<T, K extends keyof T>(entity: T, field: K): T[K] {
  return entity[field];
}
```

**判断标准**：业务代码读不懂 = 维护灾难。同事需要先学一遍 TS 类型体操才能 review。

### 1.2 自己造轮子（重复实现内置工具类型）

```ts
// ❌
type MyPartial<T> = { [K in keyof T]?: T[K] };          // 与 Partial 重复
type MyPick<T, K extends keyof T> = { [P in K]: T[P] }; // 与 Pick 重复
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : any;  // 与 ReturnType 重复

// ✅ 直接使用内置工具类型
type UserOptional = Partial<User>;
type UserNameOnly = Pick<User, 'name'>;
type FnReturn = ReturnType<typeof myFn>;
```

常用内置工具类型速查见 [01-类型系统](./01-类型系统.md) §1.6。

### 1.3 条件类型把不支持的输入静默变成 `unknown`

```ts
// ❌ false 分支过宽，调用方很难发现传入了不支持的类型
type Wrap<T> = T extends string ? { value: T } : unknown;     // 非 string 全部变 unknown

// ✅ false 分支也要写
type Wrap<T> = T extends string ? { value: T } : T extends number ? { value: T } : never;

// ✅ 用 never 兜底
type Wrap<T> = T extends string | number ? { value: T } : never;
```

### 1.4 递归类型没有区分特殊对象

```ts
// ❌ 会递归处理函数、Date、RegExp、Map/Set 等特殊对象，破坏其方法或结构
type DeepReadonly<T> = {
  [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K];
};

// ✅ 明确终止条件：基本类型、函数与常见内置对象原样返回，集合分别处理，仅递归普通对象与数组/元组
type Primitive = string | number | boolean | bigint | symbol | null | undefined;
type Builtin = Primitive | ((...args: never[]) => unknown) | Date | RegExp;

type DeepReadonly<T> = T extends Builtin
  ? T
  : T extends ReadonlyMap<infer K, infer V>
    ? ReadonlyMap<DeepReadonly<K>, DeepReadonly<V>>
    : T extends ReadonlySet<infer V>
      ? ReadonlySet<DeepReadonly<V>>
      : { readonly [K in keyof T]: DeepReadonly<T[K]> };
```

**库代码也要谨慎**——深递归类型容易拖慢编译或触发实例化深度上限，仅在确有需要时使用。

## 2. 🟡 推荐 · 团队约定

### 2.1 条件类型（Conditional Types）

**语法**：`T extends U ? X : Y`

```ts
type IsString<T> = T extends string ? true : false;
type A = IsString<string>;                              // true
type B = IsString<number>;                              // false

// 提取 Promise 的内层类型（教学示例，实际直接用内置 Awaited<T>）
type UnwrapPromise<T> = T extends Promise<infer U> ? U : T;
type Unwrapped = UnwrapPromise<Promise<string>>;        // string
```

### 2.2 infer 关键字

```ts
// 函数返回类型
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
type Fn = () => number;
type R = MyReturnType<Fn>;                              // number

// 数组元素类型
type ElementOf<T> = T extends (infer U)[] ? U : never;
type E = ElementOf<string[]>;                           // string

// Promise 内层
type PromiseInner<T> = T extends Promise<infer U> ? U : T;
type I = PromiseInner<Promise<number>>;                 // number
```

**infer 位置**：`infer` 类型变量声明在条件类型的 `extends` 子句中，并在条件成立的分支中使用。

### 2.3 映射类型（Mapped Types）

**基本语法**：`{ [K in keyof T]: ... }`

```ts
// 全字段可选
type MyPartial<T> = { [K in keyof T]?: T[K] };

// 重命名 + 过滤
type Stringify<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

interface User { id: number; name: string; }
type UserGetters = Stringify<User>;
// { getId: () => number; getName: () => string }
```

**修饰符**：`readonly` / `?` / `-readonly` / `-?`

```ts
type ReadonlyUser = { readonly [K in keyof User]: User[K] };
type Mutable<T> = { -readonly [K in keyof T]: T[K] };
type MyRequired<T> = { [K in keyof T]-?: T[K] };        // 教学示例，实际直接用内置 Required<T>
```

### 2.4 模板字面量类型

```ts
type EventName = `on${Capitalize<string>}`;             // 'onClick' | 'onHover' | ...
type ApiPath = `/api/${string}`;                        // 路径约束
type CssUnit = `${number}${'px' | 'rem' | '%'}`;        // '12px' | '12rem' | '12%'
```

### 2.5 内置工具类型原理（理解而非重新实现）

下表为简化原理示意（标准库 `lib.es5.d.ts` 中还带有泛型约束，且 `Awaited<T>` 会递归处理任意 thenable 对象；其中 `ReturnType<T>` 与 `InstanceType<T>` 的 false 分支在标准库中为 `any`）：

| 类型 | 简化原理示意 |
|------|------|
| `Partial<T>` | `{ [K in keyof T]?: T[K] }` |
| `Required<T>` | `{ [K in keyof T]-?: T[K] }` |
| `Readonly<T>` | `{ readonly [K in keyof T]: T[K] }` |
| `Pick<T, K>` | `{ [P in K]: T[P] }` |
| `Omit<T, K>` | `Pick<T, Exclude<keyof T, K>>` |
| `Record<K, V>` | `{ [P in K]: V }` |
| `Exclude<T, U>` | `T extends U ? never : T`（分布式） |
| `Extract<T, U>` | `T extends U ? T : never`（分布式） |
| `ReturnType<T>` | `T extends (...args: any) => infer R ? R : any` |
| `Parameters<T>` | `T extends (...args: infer P) => any ? P : never` |
| `InstanceType<T>` | `T extends abstract new (...args: any) => infer R ? R : any` |
| `Awaited<T>` | `T extends Promise<infer U> ? Awaited<U> : T`（简化示意） |

### 2.6 分布式条件类型

```ts
// 联合类型进入条件类型会自动 distributive
type ToArray<T> = T extends any ? T[] : never;
type A = ToArray<string | number>;                      // string[] | number[]

// ❌ 想保留 union 时别 distributive
type WithoutDistribute<T> = [T] extends [any] ? T[] : never;
type B = WithoutDistribute<string | number>;            // (string | number)[]
```

## 3. 🟢 可选 · 视情况（库 / 抽象层用）

### 3.1 类型层级（Type Hierarchy）

以下为开启 `strictNullChecks` 时的安全子类型层级示意：

```text
unknown                                        ← 顶层类型（任意类型都可赋给 unknown）
├── {}                                         ← 非 null / undefined 的值（包含基本类型与对象）
│   ├── object                                 ← 非基本类型（对象、数组、函数等）
│   └── string / number / boolean / bigint / symbol
│       └── 字面量类型（'a' / 42 / true 等）
├── null
└── void                                       ← 常用于函数返回类型（忽略返回值）；作为值类型仅接受 undefined
    └── undefined
never                                          ← 底层类型（可赋给任意类型，表示不可能存在的值）

* any 为类型检查旁路（双向可赋值），不属于安全子类型层级。
```

**赋值规则**：下层可赋给上层，反之不可（除 `any` 与函数返回 `void` 的特殊宽容规则）。

### 3.2 同态（Homomorphic）映射类型

当映射类型直接写作 `{ [K in keyof T]: ... }`（键直接来自 `keyof T`）时，TypeScript 会自动保留原属性上的 `readonly` 与可选 `?` 修饰符：

```ts
interface User {
  readonly id: number;
  name: string;
  email?: string;
}

// ✅ 同态映射：自动保留 id 的 readonly 与 email 的可选 ?
type NullableFields<T> = { [K in keyof T]: T[K] | null };
type NullableUser = NullableFields<User>;
// { readonly id: number | null; name: string | null; email?: string | null }

// 对比：非同态映射（通过独立键联合遍历）不会自动保留修饰符
type NonHomomorphic<T, K extends keyof T> = { [P in K]: T[P] | null };
```

### 3.3 索引访问类型

```ts
type User = { profile: { name: string; age: number } };
type Name = User['profile']['name'];                    // string
type Profile = User['profile'];                         // { name: string; age: number }
```

### 3.4 const 断言 + 模板字面量组合

```ts
const routes = {
  home: '/',
  users: '/users',
  userDetail: '/users/:id',
} as const;
type Route = (typeof routes)[keyof typeof routes];      // '/' | '/users' | '/users/:id'

function navigate(route: Route) { /* ... */ }
navigate('/users');                                     // ✅
navigate('/unknown');                                   // ❌
```
