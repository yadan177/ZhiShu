# 00 - 产品设计规范总览

> - 🟢 本规则库适用于软件、平台与 XR 产品的需求调研、产品结构梳理、PRD 编写、变更评估与版本验收。
> - 🔴 不适用：替代商业决策、未经验证编造用户调研结论，或直接替 UI 与研发决定具体视觉样式和代码实现方案。

---

## 1. 目标与边界

产品设计的职责是用无歧义的边界、清晰的结构、完备的状态与异常分支、以及可观测的验收条件，对齐业务目标、设计与工程实现。文档不是为了显得“长而全”，而是为了减少跨岗位理解偏差与后期返工。

- 🔴 严格区分 **现状事实**（代码/线上已存在）、**本期目标**（本次要交付）与 **远期规划 / 待定假设**，严禁把未实现能力写成现状。
- 🔴 先明确用户角色、真实使用场景、核心任务与“明确不做（Non-Goals）”，再展开页面和功能点，防止需求无序膨胀。
- 🔴 任何核心流程必须同步定义异常态、空态、权限边界与数据口径，不能只写理想“主干正常流程”。
- 🔴 验收标准必须可测试、可观测、无二义性，禁止使用“体验流畅”“界面美观”“尽量快”等不可验证措辞。
- 🟡 文档详略与任务规模匹配：小需求写清差异、影响与验收即可，大版本按完整结构分层展开。

## 2. 工作路径

| 任务类型 | 建议路径 | 核心交付物 |
|---|---|---|
| 新产品 / 大版本规划 | 业务目标与调研 → 定位与边界 → 产品结构图 → 核心 PRD → 跨岗位评审 | 调研结论、产品结构图、PRD、验收清单 |
| 存量功能迭代 | 核对现状事实 → 界定变更范围与影响面 → 更新差异与状态 → 验收标准 | 增量 PRD、受影响模块清单、回归点 |
| 需求自检与评审 | 核对角色/场景/边界 → 排查状态与异常盲区（含 XR 专项）→ 校验验收可测性 | 缺陷与盲区清单、待决策问题表 |
| 会后推进与验收 | 纪要提取决策与未决项 → 拆解负责人与截止点 → 生成版本验收准出清单 | 决策记录、待办清单、验收准出表 |

❌ 反例：把“支持 XR 协同”写成一句话需求，不说明目标设备、人数上限、断网行为和验收标准，导致设计与研发各自脑补。

✅ 正例：明确本期支持的设备档位、核心任务闭环、明确不做的范围、关键异常分支和逐条可验证的准出条件。

## 4. 规则等级与项目差异

| 标识 | 含义 |
|---|---|
| 🔴 | 适用条件满足时必须执行 |
| 🟡 | 推荐，结合团队规模、项目周期与风险等级选择 |
| 🟢 | 可选，仅在带来实际沟通收益时采用 |

- 🔴 项目已有的文档模板、编号体系、审批流和协作工具（如飞书文档 / 多维表格）优先沿用，不强行推翻重写。
- 🔴 通用产品规则不得绑定某家企业的私有业务术语、客户名称或固定内部工具账号。

## 5. 完成检查

- [ ] 现状事实、本期范围、明确不做与后续规划界限清晰。
- [ ] 核心流程包含完整的主链路、空态、异常态与权限约束。
- [ ] 每项核心需求均有可观测、可执行的验收条件。
- [ ] 涉及 XR 场景时已完成硬件档位、交互方式与防眩晕盲区自检。
- [ ] 未决业务问题已集中列出选项与影响，未替负责人擅自拍板。
