# 03 - XR 产品体验与验收准出规则

> - 🟢 本文件适用于 XR（VR / MR / AR）产品的需求盲区自检、跨岗位评审与版本验收准出清单编写。
> - 🔴 不适用：纯 2D Web/桌面应用需求（非 XR 项目可跳过第 1 节，直接参考第 2–3 节的通用验收口径）。

---

## 1. XR 专属需求盲区自检

面向 XR 头显产品编写或评审需求时，必须在进入视觉设计与研发前逐项排查以下高频盲区：

| 盲区维度 | 需求阶段必须明确的问题 | 缺失后果 |
|---|---|---|
| **目标硬件与显示模式** | 支持哪几款具体一体机 / PCVR？纯 VR 还是彩色透视 MR？ | 后续美术面数、UI 对比度与帧率预算全部失焦 |
| **输入方式与兜底** | 主输入是手柄射线、手势裸手还是双模切换？手柄断连或手出视野怎么兜底？ | 真机演示或实际使用时操作卡死 |
| **用户姿态与空间边界** | 坐姿、站姿还是自由行走？最小物理活动面积要求是多少？桌面狭小空间如何降级？ | 用户被迫转身撞墙或够不到交互物体 |
| **空间 UI 摆放与多窗拓扑** | 哪些信息放主窗、侧翼、附属悬浮条或附着在 3D 物体旁？同时允许几个窗口？遇墙/模型穿模如何避让？ | 面板遮挡 3D 主体、多窗重叠或超宽导致频繁大幅转头 |
| **首次上手（FTUE）** | 戴上头显前 30 秒如何引导基础操作与视角重置？是否有免晕静态安全出生点？ | 新用户进场景即迷失方向或产生眩晕 |
| **防眩晕与移动舒适度** | 是否存在移动/转向/电梯/载具场景？默认是否开启瞬移、分段转向与舒适度选项？ | 体验 3 分钟即出现晕动症被迫摘头显 |
| **中断与现实恢复** | 摘戴头显、系统休眠、追踪丢失、弱网/断网时当前进度如何暂存与恢复？ | 培训/作业中途被打断导致进度全丢 |
| **多人 / 协作降级** | 若含多人或云端同步，网络抖动、成员掉线、语音权限被拒时的界面与业务表现是什么？ | 房间状态死锁或单点故障拖垮全员 |

- 🔴 涉及 XR 交互流程的 PRD，严禁只画 2D 线框而不说明用户所处空间位置、视距层级、独立窗口 vs 3D 附属 UI 归属、多窗流转策略及目标设备（Vision Pro / Meta Quest / PICO 等）输入触发方式；若项目已安装 `ui-design` 规则包，空间摆放口径须与 `.agent-rules/ui-design/其他规则/08-XR空间布局与摆放架构规范.md` 保持一致。
- 🔴 凡存在高眩晕风险的创意设想（如高速运动、强迫转视角、密集贴脸特效），必须在 PRD 中同步注明舒适度替代方案，并与 `xr-common` 基准保持一致。

## 2. 跨岗位评审与协同口径

- 🔴 需求评审前明确需要参与把关的岗位：涉及空间界面必邀 **UI 设计师**，涉及模型资产或图生 3D 流程必邀 **三维设计师**，涉及特效/渲染/性能敏感场景必邀 **技术美术（TA）** 与 **Unity / 全栈研发**。
- 🔴 评审结论必须形成书面变更记录，按 [02-PRD 编写与状态流程规则 §5.1](./02-PRD编写与状态流程规则.md#51-会议纪要转待办标准结构) 严格区分“已拍板决策”“明确行动项”与“仍待讨论议题”，并同步更新主 PRD 与协作任务表（如飞书多维表格/文档，若团队已配置）。

## 3. 版本验收准出清单（Release Gate）

版本提测与上线前，逐条对照 [02 §5.2 版本验收用例表](./02-PRD编写与状态流程规则.md#52-版本验收用例表标准结构) 执行并汇总至以下准出清单；未通过项必须明确归类为“阻断发布”或“经负责人批准带风险发布并登记跟进”：

- [ ] **核心功能闭环**：本期 P0 主流程与所有已定义异常拦截路径全部通过实测。
- [ ] **数据与状态一致**：关键统计口径、配置持久化、重启恢复与跨工具同步无漂移。
- [ ] **安全与隐私底线**：未知文件防覆盖、敏感凭证脱敏、系统权限申请与拒绝回退验证通过。
- [ ] **XR 真机准出（XR 项目必查）**：目标最低档位真机完成热稳态帧率、可读性、命中精度、摘戴休眠与追踪丢失回归，非仅桌面预览通过。
- [ ] **文档与交付同步**：版本变更说明、已知限制与受影响的跨岗位文档已同步更新。
