# 03 - UI 视觉设计规则

> - 🟢 本文件适用于参考研究、视觉方向、布局、文字、色彩、图像、动效与平台适配。
> - 🔴 不适用：无依据套用固定风格、尺寸或品牌，或以效果图替代交互和设备验证。

---

## 1. 方向与参考

- 🔴 先理解用户任务、平台输入、内容与品牌约束，复用已有有效方向；新方向用少量可比样例说明取舍和实现成本。
- 🔴 参考区分官方规范、已发布产品实录、工具示例和概念稿。记录具体链接或文件、访问日期、画面与条件、借鉴点和不可迁移部分。
- 🔴 搜索摘要、概念图或宣传片不能证明可用性、运行性能或目标设备支持；无法读取原文时说明证据范围。
- 🔴 探索稿可使用注明性质的临时内容；未经采用的方向不覆盖正式变量、组件或资源。
- 🟡 新项目先形成必要颜色、文字、尺度与控件基础，再用真实代表页修订；已有项目的局部微调不重新发起整套风格探索。

## 2. 信息层级与布局

- 🔴 层级对应用户任务和信息重要性，当前状态与主要操作易于识别。
- 🔴 用对齐、接近、留白和对比组织信息，不依赖装饰框线解释所有关系。
- 🔴 说明固定、拉伸、重排、换行、截断、滚动与溢出行为，核对长文本、空值、加载和异常内容。
- 🔴 弹层、提示及高优先级信息与任务的遮挡、并存和阻断关系明确。
- 🟡 间距、网格、形状和材质使用可复用尺度，具体数值来自项目，不把某个参考页面的像素值提升为通用规则。

## 3. 文字与界面文案（反冗余文案硬门禁）

### 3.1 反冗余文案硬门禁

- 🔴 字体家族、字重、行高、回退、文字覆盖与取得方式明确；按 [资源规则](./06-设计工具与切图导出规则.md) 选择系统字体、已有依赖或需交付文件，不统一要求复制字体二进制。
- 🔴 普通文字优先保留文本语义与运行时可控性，检查缩放、本地化、选择/辅助读取等项目需要；固定艺术字或插画标签的例外需有理由。
- 🔴 **禁止 4 类典型 AI 冗余文案**：
  1. 页面、模块或卡片顶部强加的欢迎语、价值宣传语或功能介绍段落；
  2. 常驻在主工作区的段落式“使用说明 / 操作指南 / 温馨提示横幅”（供阅读的教程留在帮助文档或按需折叠）；
  3. 同一区域内标题、副标题、表单占位符与按钮文案换词同义反复；
  4. 把底层技术实现原理或研发备注（如哈希校验、原子写入、内部协议名）直接印在普通用户界面上。
- 🔴 **字段化/标签化优先于段落化**：业务工作台与工具类常态页面优先使用 **标题 + 关键字段 + 状态徽章 + 动词按钮** 组织信息，不出现超过 1 行的连续解释段落；仅在真实需要说明**错误根因、不可逆危险后果或陌生业务概念**时允许简短说明，长解释收敛至 `?` Tooltip、折叠详情或帮助链接。
- 🔴 简洁不能删除必要的错误原因、恢复方法、陌生概念解释和操作后果；不能以“越少越好”机械删字。
- 🔴 **交付前强制执行「删字逆向自检」**：检查实际画面，对每段非字段文字反问“删掉这句话，用户还能否识别对象、判断状态、完成操作并理解后果？”——能则删除，并同步收紧卡片高度、换行与间距，不留空洞死白。

### 3.2 组件文案防反复返工与抗改字约束

设计稿与研发落地之间最常见的二改、三改集中在按钮、徽章、Tab 与弹窗组件文案，设计阶段必须提前封堵 3 个返工根因：

- 🔴 **高频术语与组件文案单一表**：展开第 2 个业务页面前，先锁死全产品通用的主动作词（如确认 / 取消 / 保存 / 移除）、状态徽章词与通用空态词；PRD、设计稿与代码只能从同一术语表取词，严禁不同页面出现“提交 / 确认保存 / 立即应用”等同义词打架。
- 🔴 **显式区分「已定稿文案」与「待确认占位文案」**：业务方尚未最终拍板的文案必须集中标注待定状态，不在设计稿里把 AI 临场拟定的试探文案伪装成已定稿交给研发硬编码。
- 🔴 **组件容器必须抗改字（1.5× 膨胀测试）**：所有按钮、状态徽章、Tab、侧栏菜单项必须采用自适应内边距（Auto-Layout / Padding）并声明最小/最大宽度及溢出策略（单行截断 `…` 或受控限行折行）；交付前用 **1.5 倍字长或极端长词** 验算，确保文案二次修改不会折行、挤飞图标或撑爆卡片。

❌ 反例：工作台页头写两行欢迎介绍，下方加黄色提示框写三行操作步骤；按钮按 2 个字画死固定宽度且 A/B 两页分别写「确认」「立即提交」，业务方把文案改成 5 个字后按钮文字直接换行溢出。

✅ 正例：先在术语表锁死标准动词与状态词，页头删去冗余说明框；按钮与徽章使用自适应内边距与单行溢出规则，经 1.5 倍长词核对无错位，异常态仅保留状态徽章 + 原因/恢复建议 +「重试」按钮。

## 4. 色彩、图标与图片

- 🔴 色彩按语义使用，品牌、选择、成功、警告和危险分别判断；关键状态不能只依赖颜色差异。
- 🔴 核对真实背景、透明叠加、文字与关键边界的辨识度；适用的对比度要求按目标平台与项目标准核实。
- 🔴 图标有明确语义，风格、视重和对齐一致；可见图形与实际命中区分别定义。
- 🔴 图片说明比例、裁切焦点、加载失败和替代内容；叠字需要检查不同图片下的阅读条件。
- 🔴 字体、图标、照片和生成素材记录来源及使用条件；业务、科学或文字内容须核对，不能把参考素材自动作为可分发资源。
- 🟡 模糊、发光、透明和渐变依据任务需要与性能选择，并准备可行的降级表现。

## 5. 状态、动效与适配

- 🔴 按已采用交互模型表达焦点、选择、按压、禁用和业务状态，不为视觉完整感添加新业务。
- 🔴 动效说明触发、起止、时长依据、缓动、打断、循环及必要降级；不通过装饰动效拖慢高频任务。
- 🔴 响应式或跨尺寸设计说明内容如何变化，不只提供不同尺寸截图；按项目检查安全区、方向、缩放和输入。
- 🔴 系统键盘、权限、账号和导航等平台行为先核对实际集成，不用自制页面冒充系统流程。
- 🟡 可访问性要求贯穿内容、颜色、焦点、输入与运动，不只在完稿后检查色值。

## 6. XR 与空间界面

仅当任务涉及 VR / MR / AR 空间界面时执行；完整空间尺度换算、锚定模式、透视对比度、近/远距输入与性能协同细则见 [07 - XR 空间界面专项规范](./07-XR空间界面规范.md)。

- 🔴 不以平面预览或桌面截图代替空间尺度与目标设备验证；设计像素、物理尺寸、观看距离与角尺寸须按 [07](./07-XR空间界面规范.md) 分别记录与核验。

## 7. 完成检查

- [ ] 方向、基础与正式页面之间有来源和采用依据。
- [ ] 内容层级、文案、极限长度、空值与异常经过实际画面检查。
- [ ] 状态与动效服务于已定义行为，适配与输入有明确条件。
- [ ] 素材与字体取得方式明确，运行时内容未被误烘焙。
- [ ] 平面、空间、实现与设备证据没有混写。
